# 見本: PR に何を残すか

**3つに分ける。**

| どこに | 何を | 読み手 |
|---|---|---|
| **① PR 本文** | **概要／確認したこと／判断を仰ぎたいこと／AIの利用** | **レビュアー** |
| **② PR のコメント** | AIレビューの指摘と仕分け | **レビュアー**（実務ではボットが自動で残す） |
| **③ `振り返り.md`** | 学び・気づき・アプローチの記録 | **自分と講師**（実務では書かない） |

**PR に書く作業は3つだけ。**

| | 何をするか |
|---|---|
| **数える** | テスト件数・ケース件数・欠番の有無 |
| **印を付ける** | 観点に `[x]` か `[ ]` |
| **転記する** | AIの指摘で「判断できない」に分けたもの ＋ 回答待ちのもの |

**発明が要る箇所は無い。**

---

## ① PR 本文

```markdown
## 概要

Todo と Tag の CRUD を実装しました（9エンドポイント、コミット9本）。
着手前に仕様の未決・矛盾を12件確認し、設計書へ反映しています。

## 確認したこと

- テストケース一覧 69件は全件テストがあります。欠番なし
- Controller層の統合テスト 89件。`mvn test` / `mvn checkstyle:check` ともに緑

      Tests run: 89, Failures: 0, Errors: 0, Skipped: 0
      BUILD SUCCESS

- 主要なエンドポイントは Postman でも叩いて確認しました
- [x] 設計に無い判断が入っていないか — **1件**（部分一致検索の `%` `_` の扱い。
      設計書に記載が無く、エスケープする方針で確認・反映済み）
- [x] 編集したファイルは妥当だったか — 実装に必要な範囲のみ。既存クラスの変更なし
- [x] DoD 9項目
- [ ] **ケース一覧そのものの網羅性** — 確認できていません
- [ ] 性能・セキュリティ — 本課題の範囲外のため見ていません（`CLAUDE.md` の前提）

## 判断を仰ぎたいこと

- **TOCTOU で本来404が409になる余地がある**（AIの指摘）。
  競合が起きる頻度は低いと考えており、**このままマージしてよいと思っています。**
  仕様上の想定だけ確認させてください
- **DELETE に `@RequestBody`**（AIの指摘）。設計書どおりに実装していますが、
  プロキシ構成によっては動かない可能性があるとのことです。**設計の判断をお願いします**
- **画面遷移図との不整合**（着手前に確認済み、回答待ち）。**実装には影響しません**

## AIの利用

実装は Claude Code。各コミットにトレーラーを付けています。
テストは実装前に書かせ、失敗を確認してから実装しました。
レビューは別セッションの Claude Code に PR の差分を読ませ、結果をコメントに貼っています。
```

### ★ ここで評価が分かれる

| | |
|---|---|
| **`[ ]` が付いているか** | **「ケース一覧そのものの網羅性は確認できていません」と書けるかどうか。** ここが線引きそのもの。**全部 `[x]` のPRは、むしろ疑わしい** |
| **マージ可否を言っているか** | **「これが直ってからマージ」か「このままマージ」か。**書いていないとレビュアーが動けない |
| **自分の見解があるか** | **「AIの指摘。確認したいです」だけだと丸投げに見える。** **決めるのは相手、意見を言うのは自分。**「独断しない」と「意見を持たない」は別物 |
| **手で動かしたか** | **統合テストだけでは足りない。**受入では「実際に動かしたか」をまず聞かれる |

## ② PR のコメント — AIレビューの指摘と仕分け

**本文ではなくコメントとして自分で貼る。**実務ではボットの指摘がスレッドに残るので、形を合わせる。

```markdown
別セッションの Claude Code にレビューさせました。4件、すべて妥当な指摘と判断しました。

| 指摘 | 判定 | 処置 |
|---|---|---|
| TOCTOU で本来404が409になる余地 | **判断できない** | **本文に上げた** |
| DELETE に `@RequestBody` | **判断できない** | **本文に上げた** |
| Tag存在チェック(404)が楽観ロック(409)より先。優先順位が未検証 | 正しい | **順序を固定するテストを追加** |
| `limit=abc` のような型不正が未検証 | 正しい | **ケースを追加** |
```

**「直さない」にも処置が書いてある状態で終わり。**「正しい」を全部直した、ではない。

## ③ `振り返り.md` に回るもの

**実務では書かないが、学びとして残すもの。**

```markdown
### 4. 「テストが緑」以外に、テストが効いていると言える根拠は何か

`TodoService.delete` から紐づき解除の1行を消して `mvn test` を打ったところ、
89件が緑のまま通った。正常系が紐づきなしの Todo しか消しておらず、FK に当たらなかったため。
紐づきありの削除テストを足して、落ちるようにした。

### 5. AIのレビューに出てこなかったもののうち、自分が見つけたものは何か

`%` `_` のエスケープ漏れ。差分に4箇所あるのに、AIは最後まで読んで一言も触れなかった。
設計書を渡していないので、仕様として決めたことには届かないのだと思う。
```

**★「壊して確かめた」はPRに書かない。**1件では網羅性が無く、**部分的なチェックを保証のように見せてしまう**。
**やる価値はあるが、それは「書くに値する状態を作るための作業」**であって、レビュアーに見せる根拠ではない。
