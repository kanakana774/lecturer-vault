AIエージェントでの開発で品質が劣化する原因を可視化するためにシンプルなモデルを作ってみた

```
  L1  入力 ── 仕様書 / 既存コード / DDL / 実行基盤の既定
   │  ▲  ╎
   │  │  ╎    ↓ 読む    ↑ 返す    ╎ 出したものが次の入力になる
   ▼  │  ╎
  L2  変換 ── 3つの経路で 実装（出力）に入る

       ① ジュニアが読んで渡す      誤読 / 読み漏らし / 独断
       ② AIが自分で読む            同じ3つ。①を通らない
       ③ 誰も読まない              既定が決める

       ①②③は一度きりではない。往復するたびに積む
```

### L1（仕様管理者/上位者）

- 仕様決めに責任
- **入力は仕様書だけではない。** 既存コード・DDL・実行基盤の既定も入力
- **ただし「入力である」と「持ち主がいる」は別。** 仕様管理者は Jackson や MyBatis の既定を持っていないし、変えられない（→ ③）

### L2（ジュニア実装者）

仕事：実装、品質担保、仕様の考慮漏れ指摘

| | 誰が入力を読んだか | 何が起きるか | ジュニアから見えるか |
|---|---|---|---|
| **①** | ジュニア | 誤読 / 読み漏らし / 独断 | **見える**（自分がやった） |
| **②** | AI（①を通らない） | 同じ3つ | **見えない**（渡していないものが実装を決める） |
| **③** | 誰も読まない | **既定が決める** | **見えない**（誰も決めていない） |
| **④** | ①〜③の往復 | **前のターンの出力が壊れる** | **見えない**（差分しか見ない） |

- **④で壊れるのは入力ではなく、自分の前回の出力。** だから①②③のどれにも当たらない
- **読み漏らし → 空白 → 独断 は連鎖する。** 同じ事象が両方に見えるときは、**原因側（読み漏らし）で数える**
- **構造は人に任せても同じ。** 違うのは、**AIは問い返さずに埋めて整合させる**ことと、**往復の回数**
