## 旧版の記述の検証結果

新版を書くにあたり、旧版（`01_講義資料/12_PLpgSQL/PLpgSQL簡略版/` と `PLpgSQL詳細版/`）の記述を実測で検証しました。**旧版はそのまま残してあります**が、使うときは以下に注意してください。

| # | 旧版の記述 | 検証結果 | 根拠 |
|:---|:---|:---|:---|
| 1 | `ERRCODE = 'P0001'` は「独自の SQLSTATE」の例 | **誤り。** `P0001`（`raise_exception`）は `RAISE EXCEPTION` の既定値。独自コードは実装定義クラス（先頭が 5〜9 または I〜Z） | [[12詳解-3_例外とサブトランザクション\|12詳解-3]] §4-2 |
| 2 | `%ROWTYPE` はコンパイル時に列名の存在チェックが走るので安全 | **誤り。** `CREATE` 時は PL/pgSQL の構文しか見ない。SQL の妥当性はその行を実行したときに確認される | [[12詳解-1_実行モデルとプランキャッシュ\|12詳解-1]] §1-1 |
| 3 | 代入の `=` は「PostgreSQL 9.4 以降で許容」 | **バージョン条件に裏付けなし。** `:=` と `=` はどちらも動く（実測）。9.4 は機能追加ではなく文書化のタイミング | [[12詳解-2_変数解決とデータ型の深掘り\|12詳解-2]] §4-3 |
| 4 | `RETURNING` で「UPDATE 前後の値を同時に取得」 | **誤り。** `RETURNING` が返すのは更新後の値のみ。前の値が要るなら更新前に退避する | [[12-2_変数とSQLの実行\|12-2]] §9 |
| 5 | `serial` 列に明示 ID を入れる UPSERT 例 | **危険。** シーケンスが進まず後続の `INSERT` が PK 重複で落ちる。新版は EC スキーマ（手動採番 INT）なのでこの問題自体が起きない | — |
| 6 | 「エラーをログテーブルに `INSERT`」と「最後に `RAISE;` で再スロー」を並列に推奨 | **両立しない。** 再スローするとログの `INSERT` も巻き戻る（実測でログ 0 件） | [[12-4_関数とプロシージャと例外処理\|12-4]] §9、[[12詳解-3_例外とサブトランザクション\|12詳解-3]] §7 |
| 7 | 存在チェックは `PERFORM` + `FOUND`（「変数への代入コストすら惜しむのが良い書き方」） | **価値づけが不適切。** 動作は正しいが、`IF EXISTS (SELECT 1 …)` の方が意図が読める。新版は `EXISTS` を第一候補として整理 | [[12-2_変数とSQLの実行\|12-2]] §4-1 |
| 8 | プロシージャはトランザクション制御が「可能」（無条件） | **不正確。** 条件が 2 つある（外側でトランザクション未開始／`EXCEPTION` 句を持つブロックの本体でない） | [[15-3_補足_PLpgSQLの中のトランザクション制御\|15-3]] §2 |
| 9 | 「PostgreSQL は `ELSIF` です」（`ELSEIF` は他言語の綴り） | **不正確。** `ELSEIF` も構文・意味とも通る（実測）。新版は「両方通るが `ELSIF` に統一する」と記述 | [[12-3_制御構造\|12-3]] §1-2 |

※ #9 は新版の執筆中に実測で判明したものです。

## 検証環境の作り方

この資料群の実測を再現する手順です。

```bash
export PGCLIENTENCODING=UTF8
export PGPASSWORD=aevic
export PGOPTIONS="-c lc_messages=C"   # エラーメッセージを英語に固定
export LC_ALL=C; export LANG=C        # psql 自身のメッセージも英語に

PSQL="/c/Program Files/PostgreSQL/17/bin/psql.exe"

# 検証用DBを作り、08章のDDLとデータを投入する
"$PSQL" -w -U postgres -h localhost -c "CREATE DATABASE sql_plpgsql_check ENCODING 'UTF8'"
"$PSQL" -w -U postgres -h localhost -d sql_plpgsql_check -f <08章のDDLとデータ>
```

`lc_messages` と `LC_ALL` を `C` にしているのは、**エラーメッセージを英語に固定して、資料と実行結果を突き合わせやすくする**ためです。研修生の環境（日本語）では同じメッセージが日本語で出ます。
