# ウィンドウ関数

## 1. 導入：ウィンドウ関数とは？

**ウィンドウ関数**（Window Function）は、一言で言うと「**行をまとめずに、各行に集計結果を付加する機能**」です。

### `GROUP BY` との決定的な違い

| 特徴       | GROUP BY                    | ウィンドウ関数                      |
| :------- | :-------------------------- | :--------------------------- |
| **行数**   | グループ数まで減少する（データを「折りたたむ」）    | **元の行数を維持する**（「折りたたまない」）     |
| **用途**   | 全体の要約統計                     | ランキング、移動平均、累計、前後比較           |
| **記述場所** | `GROUP BY`句に列を指定            | `SELECT`句の中で `OVER()` を使用    |

## 2. 基本構文と構成要素

```sql
関数名() OVER (
    [PARTITION BY 列名, ...]  -- 1. データの分割
    [ORDER BY 列名, ...]      -- 2. 並び替え
    [ウィンドウフレーム句]      -- 3. 計算範囲の絞り込み
)
```

### 2.1. 各要素の役割
1.  **PARTITION BY**: データを「部門別」「年度別」などのグループに分けます。このグループ（パーティション）をまたいで計算が行われることはありません。
2.  **ORDER BY**: パーティション内での並び順を決めます。ランキングや、時系列の累計計算において必須となります。
    *   **計算用と表示用は別物です。** `OVER`句の中の `ORDER BY` は**その関数の計算順序を決めるためだけ**のもので、**クエリの最終的な表示順序を保証しません**。結果を特定の順序で表示したい場合は、必ずSQLの末尾（`SELECT`文の最後）に `ORDER BY` 句を記述してください。
3.  **ウィンドウフレーム**: 「現在の行から見て、どの範囲までを計算対象にするか」を定義します。

### 2.2. 各句を省略した場合の挙動（デフォルト値）

| 省略される句           | 挙動（デフォルトの扱い）                                                                                                                                                                             |
| :--------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **PARTITION BY** | **結果セット全体**が1つの大きなグループとして扱われます。                                                                                                                                                          |
| **ORDER BY**     | パーティション内の行に順序がないとみなされます。<br>集計関数の場合、デフォルトのフレームは「パーティション全体」になります。                                                                                                                         |
| **フレーム句**        | **`ORDER BY` がある場合**: `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`（先頭から現在の行まで＝累計）<br>**`ORDER BY` がない場合**: `RANGE BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`（パーティション全体） |

![[00_SQL研修/01_講義資料/_attachments/window関数1.png]]

### 2.3. 同じウィンドウを使い回す：`WINDOW` 句

同じ `OVER (...)` を何度も書くときは、`WINDOW` 句で名前を付けて使い回せます。定義が1箇所になるので、直すときに直し漏れません。

```sql
WITH monthly_data AS (
    SELECT 'A' AS shop, '2023-01-01'::date AS d, 100 AS sales UNION ALL
    SELECT 'A', '2023-02-01'::date, 150 UNION ALL
    SELECT 'A', '2023-03-01'::date, 120 UNION ALL
    SELECT 'B', '2023-01-01'::date, 200 UNION ALL
    SELECT 'B', '2023-02-01'::date, 250
)
SELECT
    shop, d, sales,
    SUM(sales) OVER w AS cumulative,
    ROUND(AVG(sales) OVER w, 1) AS avg_so_far
FROM monthly_data
WINDOW w AS (PARTITION BY shop ORDER BY d)
ORDER BY shop, d;
```

```
 shop |     d      | sales | cumulative | avg_so_far
------+------------+-------+------------+------------
 A    | 2023-01-01 |   100 |        100 |      100.0
 A    | 2023-02-01 |   150 |        250 |      125.0
 A    | 2023-03-01 |   120 |        370 |      123.3
 B    | 2023-01-01 |   200 |        200 |      200.0
 B    | 2023-02-01 |   250 |        450 |      225.0
(5 rows)
```

`WINDOW` 句は `FROM`（`WHERE` / `GROUP BY` / `HAVING` があればその後）と `ORDER BY` の間に書きます。

## 3. ウィンドウフレームの詳細：`ROWS` vs `RANGE`

ウィンドウ関数の挙動を理解する上で、最も重要なのがこの「フレーム」の概念です。特に、`ROWS`（物理的な行）と `RANGE`（論理的な値）の違いを理解することが不可欠です。

### 3.1. フレームの指定方法
`{ ROWS | RANGE } BETWEEN <開始点> AND <終了点>` という形式で記述します。

*   `UNBOUNDED PRECEDING`: パーティションの最初から
*   `<N> PRECEDING`: N行前、あるいは値がN小さい行から
*   `CURRENT ROW`: 現在の行まで
*   `<N> FOLLOWING`: N行後、あるいは値がN大きい行から
*   `UNBOUNDED FOLLOWING`: パーティションの最後まで

### 3.2. `ROWS` (物理的な行数ベース)
「現在の行から前後何行」という**物理的な位置**で範囲を決めます。
*   **特徴**: データの内容に関わらず、常に一定の行数を対象にします。
*   **用途**: 「直近3日間の移動平均（＝3行の平均）」など。

![[00_SQL研修/01_講義資料/_attachments/window関数2.png]]

### 3.3. `RANGE` (論理的な値ベース)
`ORDER BY` で指定した列の**値の範囲**で計算対象を決めます。
*   **特徴**: `ORDER BY` の値が**同じ（同順位）行がある場合、それらをまとめて一つの範囲**として扱います。
*   **値の間隔を直接指定できる**: PostgreSQLでは `RANGE '1 day' PRECEDING` のように、日付の間隔を指定することも可能です。

> 🐘 **どこまで通じる話か**
> `RANGE` に間隔（`'1 day' PRECEDING` など）を指定する書き方自体は標準SQLの仕様です。

![[00_SQL研修/01_講義資料/_attachments/window関数3.png]]

### 3.4. `ROWS` と `RANGE` の具体的な違い（比較例）

同じデータに対して、`ROWS` と `RANGE` で累計（SUM）を計算した場合の挙動の違いを見てみましょう。

#### サンプルデータとSQL
```sql
WITH sales AS (
    SELECT '2024-01-01'::date AS d, 100 AS amt UNION ALL
    SELECT '2024-01-02'::date, 200 UNION ALL
    SELECT '2024-01-02'::date, 200 UNION ALL -- 2日が重複
    SELECT '2024-01-03'::date, 300
)
SELECT
    d, amt,
    SUM(amt) OVER (ORDER BY d ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS rows_sum,
    SUM(amt) OVER (ORDER BY d RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS range_sum
FROM sales;
```

#### 実行結果と解説

| 日付 (d) | 金額 (amt) | **rows_sum** | **range_sum** | 解説 |
| :--- | :--- | :--- | :--- | :--- |
| 01-01 | 100 | 100 | 100 | 両者同じ |
| 01-02 | 200 | 300 | **500** | RANGEは「同じ値(01-02)」をまとめて計算 |
| 01-02 | 200 | 500 | **500** | 同上 |
| 01-03 | 300 | 800 | 800 | 最終的には同じになる |

*   **`rows_sum`**: 物理的な1行ずつ加算されます。
*   **`range_sum`**: `ORDER BY d` の値が同じ行は「現在行」として同等に扱われるため、1月2日の行には、両方の200円が含まれた状態で集計されます。

> ⚠️ **1行ずつ正確に計算したいなら `ROWS` を明示する。** フレームを省略したときのデフォルトは `RANGE`（→ §2.2）なので、同じ値の行があると意図せず「まとめて集計」されます。

## 4. ウィンドウ関数の種類別解説

関数によって、指定しても効かない句があります。まず全体像を押さえてください。

| 分類 | 関数 | `PARTITION BY` | `ORDER BY` | フレーム |
| :--- | :--- | :--- | :--- | :--- |
| **ランキング関数** | `ROW_NUMBER()` `RANK()`<br>`DENSE_RANK()` `NTILE()` | 任意 | **必須**<br>順位付けの基準 | **影響しない** |
| **値取得関数（前後）** | `LAG()` `LEAD()` | 任意 | **必須**<br>「前後」の定義 | **影響しない** |
| **値取得関数（位置）** | `FIRST_VALUE()` `LAST_VALUE()`<br>`NTH_VALUE()` | 任意 | **必須**<br>「最初/最後/N番目」の定義 | **強く影響する** |
| **集計関数** | `SUM()` `AVG()` `COUNT()`<br>`MAX()` `MIN()` | 任意 | 任意<br>指定すると累計になる | **強く影響する** |

### 4.1. ランキング関数
データに順位を付けます。

| 関数 | 内容 | 重複時の挙動 |
| :--- | :--- | :--- |
| `ROW_NUMBER()` | 重複なしの連番 | 1, 2, 3, 4 |
| `RANK()` | ランク（後続を飛ばす） | 1, 1, 3, 4 |
| `DENSE_RANK()` | ランク（後続を詰める） | 1, 1, 2, 3 |
| `NTILE(n)` | n等分してグループ番号を振る | 四分位数などの算出に |

```sql
WITH scores AS (
    SELECT 1 AS student_id, 90 AS score UNION ALL
    SELECT 2 AS student_id, 85 AS score UNION ALL
    SELECT 3 AS student_id, 90 AS score UNION ALL
    SELECT 4 AS student_id, 70 AS score UNION ALL
    SELECT 5 AS student_id, 85 AS score
)
SELECT
  student_id, score,
  ROW_NUMBER() OVER (ORDER BY score DESC) AS row_num, -- 1,2,3,4,5
  RANK()       OVER (ORDER BY score DESC) AS rank_score, -- 1,1,3,3,5
  DENSE_RANK() OVER (ORDER BY score DESC) AS dense_rank, -- 1,1,2,2,3
  NTILE(3)     OVER (ORDER BY score DESC) AS score_tier  -- 3グループに分割
FROM scores
ORDER BY score DESC, student_id;
```

### 4.2. 値取得関数
「1行前の値」や「最初の値」などを取得します。

*   **`LAG(列, N, デフォルト)`**: N行前の値を取得。
*   **`LEAD(列, N, デフォルト)`**: N行後の値を取得。
*   **`FIRST_VALUE(列)`**: フレーム内の最初の値を取得。
*   **`LAST_VALUE(列)`**: フレーム内の最後の値を取得。
*   **`NTH_VALUE(列, N)`**: フレーム内のN番目の値を取得。

> ⚠️ **`LAST_VALUE` はフレームを明示しないと「現在の行」を返す。** デフォルトのフレーム（`RANGE ... CURRENT ROW`）では、現在の行がその時点での最後だからです。パーティション全体の最後の値を取りたい場合は、必ず `ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING` を指定してください（`NTH_VALUE` も同様）。

```sql
WITH daily_sales AS (
    SELECT '2023-01-01'::date AS sale_date, 100 AS amount UNION ALL
    SELECT '2023-01-02'::date AS sale_date, 120 AS amount UNION ALL
    SELECT '2023-01-03'::date AS sale_date, 110 AS amount UNION ALL
    SELECT '2023-01-04'::date AS sale_date, 150 AS amount UNION ALL
    SELECT '2023-01-05'::date AS sale_date, 130 AS amount
)
SELECT
  sale_date, amount,
  LAG(amount, 1, 0) OVER (ORDER BY sale_date) AS prev_amt, -- 1行前
  LEAD(amount, 1, 0) OVER (ORDER BY sale_date) AS next_amt, -- 1行後
  FIRST_VALUE(amount) OVER (ORDER BY sale_date) AS first_amt,
  LAST_VALUE(amount) OVER (
    ORDER BY sale_date
    ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING -- パーティション全体を指定
  ) AS last_amt
FROM daily_sales
ORDER BY sale_date;
```

### 4.3. 集計ウィンドウ関数
`SUM`, `AVG`, `MIN`, `MAX`, `COUNT` を使用します。フレームの指定によって「全体の集計」にも「移動集計」にもなります。

```sql
WITH monthly_data AS (
    SELECT 'A' AS shop, '2023-01-01'::date AS d, 100 AS sales UNION ALL
    SELECT 'A' AS shop, '2023-02-01'::date AS d, 150 AS sales UNION ALL
    SELECT 'A' AS shop, '2023-03-01'::date AS d, 120 AS sales UNION ALL
    SELECT 'B' AS shop, '2023-01-01'::date AS d, 200 AS sales UNION ALL
    SELECT 'B' AS shop, '2023-02-01'::date AS d, 250 AS sales
)
SELECT
    shop, d, sales,
    -- 1. パーティション内（店舗別）の合計
    SUM(sales) OVER (PARTITION BY shop) AS shop_total,
    -- 2. 店舗別の累計売上 (ORDER BYを指定するとデフォルトで累計になる)
    SUM(sales) OVER (PARTITION BY shop ORDER BY d) AS shop_cumulative,
    -- 3. 店舗別の3ヶ月移動平均 (RANGEで「2ヶ月前から現在まで」を指定)
    AVG(sales) OVER (PARTITION BY shop ORDER BY d RANGE BETWEEN '2 month' PRECEDING AND CURRENT ROW) AS shop_moving_avg,
    -- 4. 全店舗の中での最大売上 (PARTITION BYを省略)
    MAX(sales) OVER () AS global_max_sales
FROM monthly_data
ORDER BY shop, d;
```

## 5. ウィンドウ関数が評価される順番

ウィンドウ関数は、`SELECT` の列を組み立てる段階で評価されます。

```
FROM → WHERE → GROUP BY → HAVING → ウィンドウ関数 → ORDER BY
```

「絞り込みが終わった後」「集約が終わった後」に走る、という位置づけです。ここから次の3つが決まります。

### 5.1. `WHERE` にウィンドウ関数は書けない

`WHERE` はウィンドウ関数より先に評価されます。順位がまだ決まっていない段階なので、そもそも書けません。

```sql
-- エラーになる例：上位1件を WHERE で絞ろうとした
SELECT product_name, price
FROM products
WHERE RANK() OVER (PARTITION BY category_id ORDER BY price DESC) = 1;
```

```
ERROR:  window functions are not allowed in WHERE
```

`GROUP BY` と `HAVING` も同じ理由で書けません。

### 5.2. 上位N件を取る：サブクエリで包んで、外側で絞る

では順位で絞り込みたいときはどうするか。**ウィンドウ関数で順位を付けた結果を1つの表として扱い、その外側で `WHERE` を掛けます。**

```sql
SELECT product_name, price, category_id
FROM (
    SELECT
        product_name, price, category_id,
        RANK() OVER (PARTITION BY category_id ORDER BY price DESC) AS rnk
    FROM products
) sub
WHERE rnk = 1
ORDER BY category_id;
```

```
  product_name  |  price  | category_id
----------------+---------+-------------
 Laptop         | 1200.00 |           1
 Technical Book |   50.00 |           2
 Jacket         |   60.00 |           3
 Luxury Sofa    |  800.00 |           5
(4 rows)
```

内側で順位が確定してから外側の `WHERE` が走るので、これで絞り込めます。上位3件が欲しければ `rnk <= 3` にするだけです。

**これは [[10_サブクエリ]] §2-2 で相関サブクエリを使って解いたお題と同じもので、結果も一致します。** 「2番目に高い商品」を出したいとき、相関サブクエリでは書き換えが難しいのに対し、こちらは `rnk = 2` に変えるだけで済みます。

> ⚠️ **同率1位が複数あれば、その数だけ行が出ます。** `RANK()` は同じ値を同じ順位にするためです。必ず1件にしたいなら `ROW_NUMBER()` を使うか、同率をどう崩すか（登録が古いほう、など）を `ORDER BY` に足して決めます。

### 5.3. `GROUP BY` との併用：集約した「後」に効く

`GROUP BY` はウィンドウ関数より先に評価されるので、**両方を1つのクエリに書けます。** §1 で対比した2つは、排他ではありません。

```sql
SELECT
    category_id,
    SUM(price) AS category_total,
    RANK() OVER (ORDER BY SUM(price) DESC) AS rnk
FROM products
GROUP BY category_id
ORDER BY rnk;
```

```
 category_id | category_total | rnk
-------------+----------------+-----
           1 |        2450.00 |   1
           5 |        1100.00 |   2
           3 |          95.00 |   3
           2 |          70.00 |   4
(4 rows)
```

「カテゴリごとに合計を出し、その合計が大きい順に順位を付ける」形です。`GROUP BY` で1カテゴリ1行に折りたたまれた**後**にウィンドウ関数が走るため、`OVER` の中に `SUM(price)` と書けます。

## 6. 実務での活用シーン

業務でよく出てくる要求は、ほとんどが次の4つの型に収まります。

| 用途 | 書き方 |
| :--- | :--- |
| **累計**（Running Total） | `SUM(列) OVER (ORDER BY 並び順)` |
| **移動平均**（Moving Average） | `AVG(列) OVER (ORDER BY 並び順 ROWS BETWEEN N PRECEDING AND CURRENT ROW)` |
| **前日差**（Day-over-Day） | `列 - LAG(列) OVER (ORDER BY 日付)` |
| **構成比**（Percentage of Total） | `列 / SUM(列) OVER (PARTITION BY グループ)` |

構成比だけは「**同じ行の値を、その行が属するグループの合計で割る**」という形になります。`GROUP BY` では行が折りたたまれて分子が消えるため、ウィンドウ関数でしか素直に書けません。

```sql
WITH product_sales AS (
    SELECT '家電' AS category, '冷蔵庫' AS product, 50000 AS amount UNION ALL
    SELECT '家電' AS category, '洗濯機' AS product, 30000 AS amount UNION ALL
    SELECT '家電' AS category, '電子レンジ' AS product, 20000 AS amount UNION ALL
    SELECT '家具' AS category, 'ソファ' AS product, 60000 AS amount UNION ALL
    SELECT '家具' AS category, 'テーブル' AS product, 40000 AS amount
)
SELECT
    category,
    product,
    amount,
    -- カテゴリー内での合計金額
    SUM(amount) OVER (PARTITION BY category) AS category_total,
    -- カテゴリー内での構成比 (%)
    ROUND(100.0 * amount / SUM(amount) OVER (PARTITION BY category), 2) AS category_ratio
FROM product_sales
ORDER BY category, amount DESC;
```

## 7. 補足：従来手法（自己結合・サブクエリ）との比較

ウィンドウ関数を使わずに「前日差」（**＝行間比較**）を求める場合、以下のような複雑なSQLが必要になります。

### 自己結合（JOIN）の場合
結合条件に計算が必要になり、パフォーマンスが低下しやすいです。
```sql
WITH daily_sales AS (
    SELECT '2023-01-01'::date AS sale_date, 100 AS amount UNION ALL
    SELECT '2023-01-02'::date AS sale_date, 120 AS amount UNION ALL
    SELECT '2023-01-03'::date AS sale_date, 110 AS amount UNION ALL
    SELECT '2023-01-04'::date AS sale_date, 150 AS amount UNION ALL
    SELECT '2023-01-05'::date AS sale_date, 130 AS amount
)
SELECT
    s1.sale_date,
    s1.amount - s2.amount AS diff
FROM daily_sales s1
LEFT JOIN daily_sales s2 ON s1.sale_date = s2.sale_date + INTERVAL '1 day';
```

### 相関サブクエリの場合
1行ごとにサブクエリが実行されるため、データ量が多いと極めて低速になります。
```sql
WITH daily_sales AS (
    SELECT '2023-01-01'::date AS sale_date, 100 AS amount UNION ALL
    SELECT '2023-01-02'::date AS sale_date, 120 AS amount UNION ALL
    SELECT '2023-01-03'::date AS sale_date, 110 AS amount UNION ALL
    SELECT '2023-01-04'::date AS sale_date, 150 AS amount UNION ALL
    SELECT '2023-01-05'::date AS sale_date, 130 AS amount
)
SELECT
    sale_date,
    amount - (SELECT amount FROM daily_sales s2 WHERE s2.sale_date < s1.sale_date ORDER BY sale_date DESC LIMIT 1)
FROM daily_sales s1;
```

**結論**: 「前日差」のような**同一データセット内での行間比較**では、ウィンドウ関数のほうが自己結合・相関サブクエリより可読性が高く、PostgreSQL内部でも最適化されやすいです。ただし、これは万能ではありません。**存在チェック（`EXISTS`）のような用途にはウィンドウ関数は不向き**で、使い分けが要ります。詳しくは [[18-2_相関サブクエリをwindow関数で書き換えてみる]] を参照してください。
