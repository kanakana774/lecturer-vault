
# サブクエリ (Subqueries)

サブクエリとは、**SQLクエリの中に記述される別のSQLクエリ**のことです。入れ子（ネスト）になったクエリと考えると分かりやすいでしょう。
サブクエリは、外側のクエリ（主クエリ）に値を渡すために使われ、`SELECT`, `FROM`, `WHERE`句など、様々な場所で活躍します。
サブクエリを理解する上で最も重要なのは、「**非相関サブクエリ**」と「**相関サブクエリ**」の違いを明確に掴むことです。

| 種類 | 実行タイミング | 特徴 |
| :--- | :--- | :--- |
| **非相関サブクエリ** | **一度だけ**実行される | 内側のクエリが外側から独立しており、先に単独で実行可能。 |
| **相関サブクエリ** | 外側の行ごとに**毎回**実行される | 内側のクエリが外側のクエリの「現在の行」の値を参照する。 |

## 1. 非相関サブクエリ (Non-correlated Subquery)

内側のサブクエリが外側のクエリとは独立して**一度だけ**実行されます。その実行結果（単一値、値のリスト、またはテーブル）が、外側のクエリ全体で利用されます。

**サブクエリを書ける場所は3つあります。** `WHERE`句・`FROM`句・`SELECT`句を順に見ていきます。

### 1-1. `WHERE`句：単一の値と比較する

> **【お題】** 平均価格より高い商品を出す

**非相関サブクエリは、先に単独で実行できます。** まず平均価格を出します。

```sql
SELECT ROUND(AVG(price), 2) AS 平均価格
FROM products;
```

```
 平均価格
----------
   285.77
(1 row)
```

この値を、そのまま条件に埋め込みます。

```sql
SELECT product_name, price
FROM products
WHERE price > (SELECT AVG(price) FROM products)
ORDER BY price DESC;
```

```
 product_name |  price
--------------+---------
 Laptop       | 1200.00
 Smartphone   |  800.00
 Luxury Sofa  |  800.00
 Monitor      |  300.00
(4 rows)
```

**`285.77` を自分で書き写す形にはしません。** データが増えれば平均も変わるので、
サブクエリのままにしておけば、いつ実行しても「そのときの平均」で絞られます。

### 1-2. `WHERE`句：値のリストと比較する（`IN`）

> **【お題】** `Electronics` と `Books` の商品を出す

`products` が持っているのは `category_id` だけで、`Electronics` という名前は `categories` にあります。
**先にカテゴリIDのリストを作り、そのリストで絞ります。**

```sql
SELECT category_id
FROM categories
WHERE category_name IN ('Electronics', 'Books');
```

```
 category_id
-------------
           1
           2
(2 rows)
```

```sql
SELECT product_name, price
FROM products
WHERE category_id IN (
  SELECT category_id
  FROM categories
  WHERE category_name IN ('Electronics', 'Books')
)
ORDER BY price DESC;
```

```
  product_name  |  price
----------------+---------
 Laptop         | 1200.00
 Smartphone     |  800.00
 Monitor        |  300.00
 Headphones     |  150.00
 Technical Book |   50.00
 Novel          |   20.00
(6 rows)
```

`IN` の右側は、**1列であれば何行でも**受け取れます（→ §1-5）。
否定形の `NOT IN` には落とし穴があります（→ §3-3）。
同じお題は `JOIN` でも書けます。どちらを選ぶかは §3 で扱います。

### 1-3. `FROM`句：派生表として使う

サブクエリの結果を1つのテーブル（**派生表**）と見なし、そのテーブルに対して外側のクエリを実行します。
**集計した結果をさらに集計したいとき**に必要になります。

> **【お題】** 注文1件あたりの平均金額を出す

「注文ごとの合計金額」は、明細と商品をつないで集計すれば出ます。

```sql
SELECT
  oi.order_id,
  SUM(p.price * oi.quantity) AS order_total
FROM orderitems AS oi
JOIN products AS p ON p.product_id = oi.product_id
GROUP BY oi.order_id
ORDER BY oi.order_id;
```

```
 order_id | order_total
----------+-------------
        1 |     1240.00
        2 |      800.00
        3 |       60.00
        4 |       45.00
        5 |     1200.00
        6 |     1400.00
        7 |       50.00
        8 |      300.00
        9 |       55.00
       10 |      150.00
       11 |       30.00
       12 |     2400.00
       13 |        5.00
       14 |     1240.00
       15 |      940.00
(15 rows)
```

**欲しいのはこの15行の平均ですが、`AVG(SUM(...))` とは書けません。**

```
ERROR:  aggregate function calls cannot be nested
```

集計関数は入れ子にできないので、**いま出した結果を「表」として置き直してから**平均をかけます。

```sql
SELECT ROUND(AVG(order_total), 2) AS 注文1件あたりの平均金額
FROM (
  SELECT
    oi.order_id,
    SUM(p.price * oi.quantity) AS order_total
  FROM orderitems AS oi
  JOIN products AS p ON p.product_id = oi.product_id
  GROUP BY oi.order_id
) AS order_totals;
```

```
 注文1件あたりの平均金額
-------------------------
                  661.00
(1 row)
```

**派生表には別名（`AS order_totals`）を付けます。** 外側から列を指すときに名前が要ります。
また、派生表の中で付けた別名（`order_total`）は、**外側では列名として使えます。**

### 1-4. `SELECT`句：1つの値を列として足す

**サブクエリが値を1つだけ返すなら、列と同じように `SELECT`句に書けます。**
この形を**スカラーサブクエリ**（スカラ値＝単一の値を返すサブクエリ）と呼びます。

> **【お題】** `Electronics` の商品に、全商品の平均価格との差を付ける

```sql
SELECT
  product_name,
  price,
  ROUND(price - (SELECT AVG(price) FROM products), 2) AS 平均との差
FROM products
WHERE category_id = 1
ORDER BY price DESC;
```

```
 product_name |  price  | 平均との差
--------------+---------+------------
 Laptop       | 1200.00 |     914.23
 Smartphone   |  800.00 |     514.23
 Monitor      |  300.00 |      14.23
 Headphones   |  150.00 |    -135.77
(4 rows)
```

`(SELECT AVG(price) FROM products)` は全体で1つの値なので、**どの行にも同じ値**が入ります。
行ごとに違う値を出したいなら、外側の行を参照する形＝相関サブクエリになります（→ §2-3）。

### 1-5. どの句が、どの形のサブクエリを受け取れるか

サブクエリは**返ってくる形**で3つに分かれます。**書く場所によって、受け取れる形が決まっています。**

**データの次元**

| 形         | 何が返るか          | 例                                                                   |
| :-------- | :------------- | :------------------------------------------------------------------ |
| **スカラ**   | 1行1列＝**値が1つ**  | `SELECT AVG(price) FROM products`                                   |
| **1列の集合** | n行1列＝**値のリスト** | `SELECT category_id FROM categories WHERE …`                        |
| **表**     | n行m列           | `SELECT category_id, MAX(price) FROM products GROUP BY category_id` |

**各句が受け取れるデータの次元**

| 書く場所                   | スカラ | 1列の集合 |  表  | 形が合わないと出るエラー                                                                                              |
| :--------------------- | :-: | :---: | :-: | :-------------------------------------------------------------------------------------------------------- |
| `SELECT`句（列として）        |  〇  |   ×   |  ×  | `more than one row returned by a subquery used as an expression` / `subquery must return only one column` |
| `FROM`句（派生表として）        |  〇  |   〇   |  〇  | （何でも置ける）                                                                                                  |
| 比較演算子の右（`=` `>` `<` …） |  〇  |   ×   |  ×  | `more than one row returned by a subquery used as an expression`                                          |
| `IN` の右                |  〇  |   〇   |  ×  | `subquery has too many columns`                                                                           |
| `EXISTS` の中            |  〇  |   〇   |  〇  | （何でも置ける）                                                                                                  |

**表の読み方は3つです。**

- **`FROM`句と `EXISTS` は何でも受け取ります。** `FROM`句はもともと表を置く場所で、
  `EXISTS` は**中身を見ずに「行が1つでもあるか」だけ**を見るからです（→ §2-1）
- **`SELECT`句と比較演算子は、値1つしか受け取りません。** 1行に1つの値を置く場所なので、
  複数行が返ってきた時点で決められなくなります
- **`IN` は1列であれば何行でもよい。** 「このリストに含まれるか」を見るので行数は問いませんが、
  列が2つになると比べる相手が決まりません

> [!note]- 形が合わないと、実際にはこう出ます
> **比較演算子に複数行を渡した場合**（`price` は13行返る）
>
> ```sql
> SELECT product_name
> FROM products
> WHERE price = (SELECT price FROM products);
> ```
>
> ```
> ERROR:  more than one row returned by a subquery used as an expression
> ```
>
> **`SELECT`句に2列を渡した場合**
>
> ```sql
> SELECT
>   product_name,
>   (SELECT category_id, category_name FROM categories WHERE category_id = 1)
> FROM products;
> ```
>
> ```
> ERROR:  subquery must return only one column
> ```
>
> **`IN` に2列を渡した場合**
>
> ```sql
> SELECT product_name
> FROM products
> WHERE category_id IN (SELECT category_id, category_name FROM categories);
> ```
>
> ```
> ERROR:  subquery has too many columns
> ```

**「行が1件も無い」ときはエラーになりません。** スカラーサブクエリが0行を返すと `NULL` になり、
`IN` の右が0行なら「どれにも含まれない」＝条件を満たす行が無くなります。
**エラーで気づけないので、結果が0件のときはサブクエリを単独で実行して確かめます。**

## 2. 相関サブクエリ (Correlated Subquery)

内側のサブクエリが、外側のクエリが処理している**現在の行の値**に依存して実行されるサブクエリです。
**外側の行を1つ決めないと内側が実行できない**ので、単独では実行できません。ここが非相関との分かれ目です。

### 2-1. 存在チェックを絞り込み条件に使う（`WHERE` + `EXISTS`）

> **【お題】** 注文が1件でもある顧客を出す

```sql
SELECT c.customer_id, c.name
FROM customers AS c
WHERE EXISTS (
  SELECT 1
  FROM orders AS o
  WHERE o.customer_id = c.customer_id
)
ORDER BY c.customer_id;
```

```
 customer_id | name
-------------+-------
           1 | Alice
           2 | Bob
           4 | Diana
           5 | Ellen
           7 | Hank
           8 | Ivy
           9 | Jack
          10 | Kevin
          11 | Leo
(9 rows)
```

**思考プロセス:**

1. `customers` の `Alice`（`customer_id = 1`）の行を見る
2. 内側が `WHERE o.customer_id = 1` として実行される。注文があるので行が返り、`EXISTS` は `TRUE`。`Alice` は結果に入る
3. 次に `Charlie`（`customer_id = 3`）の行を見る
4. 内側が `WHERE o.customer_id = 3` として実行される。注文が無いので0行、`EXISTS` は `FALSE`。`Charlie` は結果に入らない
5. 以下、11人ぶん繰り返す

`Charlie` と `Grace` が消えて9人になっています。

**`SELECT 1` と書いているのは、`EXISTS` が中身を見ないからです。**
見ているのは「行が返ってきたかどうか」だけなので、`SELECT *` でも `SELECT 1` でも結果は同じです。
**「1件でもあるか」しか聞いていない**ことが読み手に伝わるので、`SELECT 1` と書く流儀が広く使われています。

### 2-2. 取得した値との比較を絞り込み条件に使う（`WHERE` + 比較演算子）

> **【お題】** 各カテゴリで最も価格が高い商品を出す

「そのカテゴリの最高価格」は**行ごとに変わる**ので、非相関では書けません。
**外側の行のカテゴリを内側に渡して、そのカテゴリの最高価格を計算させます。**

```sql
SELECT p1.category_id, p1.product_name, p1.price
FROM products AS p1
WHERE p1.price = (
  SELECT MAX(p2.price)
  FROM products AS p2
  WHERE p2.category_id = p1.category_id
)
ORDER BY p1.category_id, p1.product_name;
```

```
 category_id |  product_name  |  price
-------------+----------------+---------
           1 | Laptop         | 1200.00
           2 | Technical Book |   50.00
           3 | Jacket         |   60.00
           5 | Luxury Sofa    |  800.00
(4 rows)
```

**同じテーブルを2回書いて、別名（`p1` / `p2`）で呼び分けています。**
`p1` が外側の「いま見ている行」、`p2` が内側で集計する対象です。
`WHERE p2.category_id = p1.category_id` の1行が、内側と外側をつないでいます。

`Office Supplies`（`category_id = 4`）は商品が0件なので、結果に現れません。

> ⚠️ **最高価格の商品が2つあれば、2行とも出ます。**
> `= (SELECT MAX(...))` は「最高価格と同額のものすべて」を拾う形です。
> 1件に絞りたいなら、何で1件を選ぶのか（登録が古いほう、など）を決める必要があります。

### 2-3. 取得した値を新しい列として使う（`SELECT` + スカラーサブクエリ）

> **【お題】** 各商品に、その商品が属するカテゴリの平均価格を併記する

§1-4 は「全商品の平均」だったので、どの行も同じ値でした。
**カテゴリごとの平均にすると、行によって値が変わります。**

```sql
SELECT
  p.product_name,
  p.price,
  (
    SELECT ROUND(AVG(price), 2)
    FROM products
    WHERE category_id = p.category_id
  ) AS カテゴリ平均
FROM products AS p
WHERE p.category_id IN (1, 5)
ORDER BY p.category_id, p.price DESC;
```

```
 product_name |  price  | カテゴリ平均
--------------+---------+--------------
 Laptop       | 1200.00 |       612.50
 Smartphone   |  800.00 |       612.50
 Monitor      |  300.00 |       612.50
 Headphones   |  150.00 |       612.50
 Luxury Sofa  |  800.00 |       366.67
 Dining Chair |  150.00 |       366.67
 Office Chair |  150.00 |       366.67
(7 rows)
```

`Electronics` の4行には `612.50`、`Furniture` の3行には `366.67` が入りました。
**内側が外側の `p.category_id` を見ているので、行ごとに別の平均が計算されています。**

> [!note]- 同じことは `GROUP BY` では出せません
> 「商品1行ごとの明細」と「カテゴリ単位の集計値」を同時に並べているので、`GROUP BY` では
> 行がグループにまとめられてしまいます（→ [[00_SQL研修/01_講義資料/07_集約関数|07_集約関数]] §2-2）。
> **明細に集計値を添える形は、相関サブクエリか `JOIN` + 派生表（→ §3-4）で書きます。**
> 18章のウィンドウ関数は、これをもっと短く書くための道具です。

## 3. 同じお題を3通りで書く（`EXISTS` / `IN` / `JOIN`）

**「注文履歴のある顧客を出す」は、3通りで書けます。** どれも同じ9人が返ります。

### 3-1. 3つの書き方

```sql
-- ① 相関サブクエリ + EXISTS
SELECT c.customer_id, c.name
FROM customers AS c
WHERE EXISTS (
  SELECT 1
  FROM orders AS o
  WHERE o.customer_id = c.customer_id
)
ORDER BY c.customer_id;

-- ② 非相関サブクエリ + IN
SELECT c.customer_id, c.name
FROM customers AS c
WHERE c.customer_id IN (
  SELECT o.customer_id
  FROM orders AS o
)
ORDER BY c.customer_id;

-- ③ JOIN + DISTINCT
SELECT DISTINCT c.customer_id, c.name
FROM customers AS c
JOIN orders AS o ON o.customer_id = c.customer_id
ORDER BY c.customer_id;
```

```
 customer_id | name
-------------+-------
           1 | Alice
           2 | Bob
           4 | Diana
           5 | Ellen
           7 | Hank
           8 | Ivy
           9 | Jack
          10 | Kevin
          11 | Leo
(9 rows)
```

**③に `DISTINCT` が要るのは、`JOIN` が行を増やすからです。**
`Alice` は注文が4件あるので、結合しただけだと `Alice` が4行に膨れます
（→ [[00_SQL研修/01_講義資料/07_集約関数|07_集約関数]] §4）。
①②は `customers` の行数を変えないので、重複が出ません。

**「顧客の一覧が欲しい」だけなら①②のほうが素直です。**
`JOIN` が要るのは、注文側の列（注文日や金額）も一緒に出したいときです。

### 3-2. `IN` と `EXISTS` の使い分け

どちらも行を絞り込めますが、**動作原理が違います。**

`IN` は**先にリストを作ってから**照合します。②のサブクエリを単独で実行すると15行返り
（`orders` が15件あるため）、`customer_id` は `1, 1, 1, 1, 2, 2, 2, 4, 4, 5, 7, 8, 9, 10, 11` です。
このリストに含まれるかを、`customers` の11行それぞれについて確かめます。

`EXISTS` は**外側の行ごとに**内側を実行し、行が返った時点で打ち切ります（→ §2-1）。

|              | **IN**                                             | **EXISTS**                                 |
| :----------- | :------------------------------------------------- | :----------------------------------------- |
| **サブクエリの役割** | **値のリスト**を返す                                       | **存在有無**をチェックする                            |
| **実行方式**     | 非相関（先に一度だけ実行）                                      | 相関（外側の行ごとに実行）                              |
| **受け取れる形**   | 1列であれば何行でも（→ §1-5）                                  | 何でもよい（中身を見ない）                              |
| **得意なケース**   | `WHERE status IN ('Shipped', 'Pending')` のような**短いリスト**を渡す場合 | 関連テーブルに**マッチする行があるか**を確認する場合（このお題はこちら） |
| **パフォーマンス**  | サブクエリの結果が大きいとリストを持つコストがかかる                  | マッチする行を1つ見つけ次第、内部の検索を打ち切れる      |

**実行計画まで見ると、この違いは今のPostgreSQLではほとんど消えます。**
上の①と②を `EXPLAIN` にかけると、**同じ計画**（`Hash Semi Join`）が返ります。
オプティマイザが `IN` を「マッチする相手が1つあればよい結合」に書き換えるためです
（→ [[17-2_実践_EXPLAINの読み方]]）。**「`EXISTS` のほうが速い」と暗記せず、
まず読みやすいほうを書いてください。**

### 3-3. `NOT IN` にサブクエリを渡すと、`NULL` が見えなくなる

> **【お題】** まだ誰も持っていない会員ランクを出す

`memberships` は4件（`Bronze` / `Silver` / `Gold` / `Platinum`）で、**答えは `Platinum` の1件**です。
`customers` が持っているランクを `NOT IN` に渡します。

```sql
SELECT membership_id, rank_name
FROM memberships
WHERE membership_id NOT IN (
  SELECT membership_id
  FROM customers
);
```

```
 membership_id | rank_name
---------------+-----------
(0 rows)
```

**エラーも出ず、静かに0件になります。** サブクエリを単独で実行すると理由が見えます。

```sql
SELECT DISTINCT membership_id
FROM customers
ORDER BY membership_id;
```

```
 membership_id
---------------
             1
             2
             3
          NULL
(4 rows)
```

ランク未設定の `Charlie` がいるので `NULL` が混ざり、`NOT IN` の判定が `UNKNOWN` になります
（原理は [[00_SQL研修/01_講義資料/09_集合演算子|09_集合演算子]] §3-2）。
**リテラルを並べて書けば `NULL` は目に見えますが、サブクエリでは渡している値が見えません。**
これが 10章 固有の危なさです。肯定形の `IN` では起きません。

書き方は2つあります。

```sql
-- ① サブクエリ側で NULL を落とす
SELECT membership_id, rank_name
FROM memberships
WHERE membership_id NOT IN (
  SELECT membership_id
  FROM customers
  WHERE membership_id IS NOT NULL
)
ORDER BY membership_id;

-- ② NOT EXISTS で書く
SELECT m.membership_id, m.rank_name
FROM memberships AS m
WHERE NOT EXISTS (
  SELECT 1
  FROM customers AS c
  WHERE c.membership_id = m.membership_id
)
ORDER BY m.membership_id;
```

```
 membership_id | rank_name
---------------+-----------
             4 | Platinum
(1 row)
```

**②を既定にしてください。** `NOT EXISTS` が見ているのは「行が返ったかどうか」だけなので、
`NULL` が混ざっても結果は変わりません（→ §2-1）。
①は書く人が毎回 `NULL` を思い出す必要があり、**列が `NOT NULL` でなくなった時点で壊れます。**

### 3-4. 相関サブクエリを `JOIN` に書き換える

§2-2 の「各カテゴリで最も価格が高い商品」は、`JOIN` + 派生表でも書けます。

**思考プロセス:**

1. **先に**、カテゴリごとの最高価格をまとめた派生表を作る
2. `products` とその派生表を `JOIN` する
3. 結合条件を「カテゴリIDが一致」かつ「価格が最高価格と一致」にする

```sql
SELECT p.category_id, p.product_name, p.price
FROM products AS p
JOIN (
  SELECT category_id, MAX(price) AS max_price
  FROM products
  GROUP BY category_id
) AS m
  ON m.category_id = p.category_id
 AND m.max_price   = p.price
ORDER BY p.category_id, p.product_name;
```

```
 category_id |  product_name  |  price
-------------+----------------+---------
           1 | Laptop         | 1200.00
           2 | Technical Book |   50.00
           3 | Jacket         |   60.00
           5 | Luxury Sofa    |  800.00
(4 rows)
```

**§2-2 と同じ4行です。** 違うのは計算の順番で、`JOIN` 版は**カテゴリごとの最高価格を先に1回だけ**
求めます。相関サブクエリ版は、外側の13行それぞれについて内側を実行します。

**行数が増えたときに差が出るのは `JOIN` 版のほうが有利な形です。**
相関サブクエリでパフォーマンスに困ったら、まずこの書き換えを検討してください。
ただし**読みやすさは逆になることも多い**ので、迷ったら §2-2 の形で書いて、
遅くなってから書き換えれば十分です。

## 4. まとめ

- **サブクエリは `WHERE`句・`FROM`句・`SELECT`句に書ける**（→ §1）
- **非相関は単独で実行できる。相関はできない**（外側の行が決まらないと内側が動かない）
- **書く場所ごとに、受け取れる形（スカラ／1列の集合／表）が決まっている**（→ §1-5）
- **集計結果をさらに集計するには `FROM`句の派生表が要る。** `AVG(SUM(...))` は書けない（→ §1-3）
- **明細に集計値を添えるなら、相関スカラーサブクエリか `JOIN` + 派生表**（→ §2-3、§3-4）
- **`EXISTS` は中身を見ず、行があるかだけを見る。** `SELECT 1` で書く（→ §2-1）
- **`IN` / `EXISTS` / `JOIN` は同じお題を書ける。** `JOIN` は行が増えるので `DISTINCT` が要る（→ §3-1）
- **`NOT IN` にサブクエリを渡すと `NULL` で静かに0件になる。** 否定は `NOT EXISTS` で書く（→ §3-3）
- **速さで選ぶ前に、読みやすいほうを選ぶ。** 今のPostgreSQLは `IN` と `EXISTS` を同じ計画にすることが多い（→ §3-2）

相関サブクエリを1行ずつ追って読む手順と、外側から組み立てる手順は補足にあります。
