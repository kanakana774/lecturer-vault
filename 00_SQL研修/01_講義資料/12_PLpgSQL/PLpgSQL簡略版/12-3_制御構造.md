# 制御構造
## 〜条件で分け、繰り返す〜

ここまでは「値を取ってきて表示する」だけでした。この章で **条件分岐（`IF`）** と **繰り返し（ループ）** を扱うと、PL/pgSQL でやりたいことのほとんどが書けるようになります。

同時に、**この章がいちばん危ない章**でもあります。ループは書けてしまうので、SQL 1 文で済む処理までループで書きたくなります。最後の §7 で、それが実際にどれだけ遅いかを測ります。

> **この資料の前提**
> - PostgreSQL 17 で動作確認しています。掲載しているエラーメッセージ・出力・実行時間は**すべて実測**です。
> - 使用するテーブルは [[00_SQL研修/02_問題/08_結合から使用するテーブル|08_結合から使用するテーブル]] で作成したもの（8章以降と同じ）です。§7 の性能比較だけ、比較用のテーブルを作って最後に削除します。
> - [[12-2_変数とSQLの実行|12-2]] の `SELECT ... INTO`・`FOUND`・`RECORD`・`%ROWTYPE` を前提にします。

## 1. 条件分岐：`IF`

### 1-1. 基本の形

```sql
IF 条件 THEN
    処理
ELSIF 別の条件 THEN
    処理
ELSIF 別の条件 THEN
    処理
ELSE
    処理
END IF;
```

3 つ押さえてください。

1. **`THEN` が必要**です。
2. **終わりは `END IF;`**（`END;` ではない）。
3. 2 つめ以降の条件は **`ELSIF`**。

会員ランクで分岐する例です。`customer_id = 3`（Charlie）は会員ランクが未設定（NULL）なので、`ELSE` に落ちます。

```sql
DO $$
DECLARE
    v_target_id integer := 3;
    v_name text;
    v_rank text;
BEGIN
    SELECT c.name, m.rank_name INTO v_name, v_rank
      FROM customers c
      LEFT JOIN memberships m ON c.membership_id = m.membership_id
     WHERE c.customer_id = v_target_id;

    IF v_rank = 'Gold' THEN
        RAISE NOTICE '% さんはゴールド会員です', v_name;
    ELSIF v_rank = 'Silver' THEN
        RAISE NOTICE '% さんはシルバー会員です', v_name;
    ELSIF v_rank = 'Bronze' THEN
        RAISE NOTICE '% さんはブロンズ会員です', v_name;
    ELSE
        RAISE NOTICE '% さんは会員ランクが未設定です', v_name;
    END IF;
END;
$$;
```

```
NOTICE:  Charlie さんは会員ランクが未設定です
```

> ⚠️ **NULL は「どの条件にも当てはまらない」ので `ELSE` に落ちます。**
> `v_rank` が NULL のとき、`v_rank = 'Gold'` の結果は「偽」ではなく **NULL（不明）** です。`IF` は「真のときだけ実行する」ので、NULL なら実行されません。結果として `ELSE` に来ます。
> **`ELSE` を書き忘れると、NULL のケースが黙って無視されます。** ここは実務でよく踏みます。

### 1-2. `ELSIF` の綴り

プログラミング言語によって `ELSEIF` / `elsif` / `elif` とばらつく箇所です。**PostgreSQL は `ELSIF` と `ELSEIF` の両方を受け付けます**（実測で確認済み）。

```sql
DO $$
BEGIN
    IF 1 = 2 THEN
        RAISE NOTICE '1つめ';
    ELSEIF 2 = 2 THEN
        RAISE NOTICE 'ELSEIF の枝が実行された';
    END IF;
END;
$$;
```

```
NOTICE:  ELSEIF の枝が実行された
```

エラーにはなりませんが、**この資料では `ELSIF` に統一します**。混在させると読みにくいので、どちらか一方に決めて書いてください。

### 1-3. CASE 式との使い分け

値を作って変数に入れるだけなら、既習の **CASE 式**（[[00_SQL研修/01_講義資料/06_CASE式|06_CASE式]]）がそのまま使えます。書き方は SQL のときと同じなので、ここでは説明しません。

| やりたいこと | 使うもの |
|:---|:---|
| 条件によって**違う処理**をする（`RAISE`、`UPDATE`、複数行の処理） | `IF` |
| 条件によって**違う値**を 1 つ選ぶ | CASE 式 |

「値を選ぶだけなのに `IF` で 4 行書く」より、CASE 式 1 つの方が読みやすいことがよくあります。

## 2. 決まった回数の繰り返し：`FOR i IN`

`FOR 変数 IN 開始..終了 LOOP` で、整数を 1 つずつ増やしながら繰り返します。

**ループ変数は `DECLARE` に書きません。** `FOR` が自動で用意し、ループの中だけで有効です。

```sql
DO $$
DECLARE
    v_count integer;
BEGIN
    FOR i IN 1..5 LOOP
        SELECT count(*) INTO v_count FROM reviews WHERE rating = i;
        RAISE NOTICE '評価%: %件', i, v_count;
    END LOOP;
END;
$$;
```

```
NOTICE:  評価1: 0件
NOTICE:  評価2: 0件
NOTICE:  評価3: 1件
NOTICE:  評価4: 1件
NOTICE:  評価5: 4件
```

`1..5` は **5 も含みます**（1, 2, 3, 4, 5 の 5 回）。

逆順にする `REVERSE` と、増分を変える `BY` もあります。

```sql
DO $$
BEGIN
    FOR i IN REVERSE 5..1 LOOP
        RAISE NOTICE 'カウントダウン: %', i;
    END LOOP;

    FOR i IN 1..10 BY 3 LOOP
        RAISE NOTICE '3きざみ: %', i;
    END LOOP;
END;
$$;
```

```
NOTICE:  カウントダウン: 5
NOTICE:  カウントダウン: 4
NOTICE:  カウントダウン: 3
NOTICE:  カウントダウン: 2
NOTICE:  カウントダウン: 1
NOTICE:  3きざみ: 1
NOTICE:  3きざみ: 4
NOTICE:  3きざみ: 7
NOTICE:  3きざみ: 10
```

**`REVERSE` のときは「大きい方..小さい方」と書きます**（`REVERSE 5..1`）。`REVERSE 1..5` と書くと 1 回も回りません。

## 3. クエリの結果を 1 行ずつ処理する：`FOR ... IN SELECT`

**この章の主役です。** 実務で PL/pgSQL を書くとき、いちばん多く使う形です。

```sql
FOR レコード変数 IN SELECT ... LOOP
    処理
END LOOP;
```

`SELECT` が返す行が、1 行ずつレコード変数に入ってきます。`SELECT INTO` と違って、**取れた行を全部処理できます**。

```sql
DO $$
DECLARE
    r_product RECORD;
BEGIN
    FOR r_product IN
        SELECT p.product_name, c.category_name, p.price
          FROM products p
          JOIN categories c ON p.category_id = c.category_id
         WHERE c.category_name = 'Furniture'
         ORDER BY p.product_id
    LOOP
        RAISE NOTICE '商品: %, カテゴリ: %, 価格: %',
            r_product.product_name, r_product.category_name, r_product.price;
    END LOOP;
END;
$$;
```

```
NOTICE:  商品: Dining Chair, カテゴリ: Furniture, 価格: 150.00
NOTICE:  商品: Office Chair, カテゴリ: Furniture, 価格: 150.00
NOTICE:  商品: Luxury Sofa, カテゴリ: Furniture, 価格: 800.00
```

- レコード変数は `RECORD` 型か `%ROWTYPE` を使います。JOIN しているので、ここは `RECORD` です（[[12-2_変数とSQLの実行|12-2]] §7）。
- **`ORDER BY` を書いてください。** 書かなければ処理の順番は保証されません。ログを読む人にとっても、順番が決まっている方が追いやすくなります。
- **0 行だった場合、ループの中は 1 回も実行されません。** エラーにはならないので、「1 件も処理されなかった」を検知したいなら、自分でカウンタを持つか `FOUND` を見ます。

### 3-1. 【手を動かす】`IN` の中に `INTO` は書けない

**よく間違えるところです。** `SELECT ... INTO` の書き方に慣れると、つい `FOR` の中にも `INTO` を書いてしまいます。

```sql
DO $$
DECLARE
    r_product RECORD;
    v_name    text;
BEGIN
    FOR r_product IN
        SELECT product_name INTO v_name FROM products ORDER BY product_id
    LOOP
        RAISE NOTICE '%', r_product.product_name;
    END LOOP;
END;
$$;
```

```
ERROR:  cannot open SELECT INTO query as cursor
CONTEXT:  PL/pgSQL function inline_code_block line 6 at FOR over SELECT rows
```

**`FOR ... IN` に書く `SELECT` に `INTO` は書けません。** 行を受け取る先は `FOR` の直後に書いたレコード変数（ここでは `r_product`）であり、`INTO` は不要です。

## 4. ループを抜ける・飛ばす：`EXIT` と `CONTINUE`

| 書き方 | 意味 |
|:---|:---|
| `EXIT;` | ループを抜ける |
| `EXIT WHEN 条件;` | 条件が真ならループを抜ける |
| `CONTINUE;` | 残りを飛ばして次の回へ |
| `CONTINUE WHEN 条件;` | 条件が真なら次の回へ |

`WHEN` を付けた形は、`IF 条件 THEN EXIT; END IF;` と同じ意味です。1 行で書けるので読みやすくなります。

複数の倉庫から在庫を引き当てる例です。**必要数に達したら残りの倉庫は見ません。**

```sql
DO $$
DECLARE
    r_inv       RECORD;
    v_remaining integer := 55;   -- 55個ほしい
    v_taken     integer;
BEGIN
    FOR r_inv IN
        SELECT warehouse_id, stock_quantity
          FROM inventory
         WHERE product_id = 1
         ORDER BY warehouse_id
    LOOP
        -- 在庫0の倉庫は飛ばす
        CONTINUE WHEN r_inv.stock_quantity = 0;

        v_taken     := least(r_inv.stock_quantity, v_remaining);
        v_remaining := v_remaining - v_taken;

        RAISE NOTICE '倉庫% から % 個引き当て（残り必要数 %）',
            r_inv.warehouse_id, v_taken, v_remaining;

        -- ほしい数に達したら終わり
        EXIT WHEN v_remaining = 0;
    END LOOP;

    IF v_remaining > 0 THEN
        RAISE NOTICE '% 個足りませんでした', v_remaining;
    END IF;
END;
$$;
```

```
NOTICE:  倉庫1 から 50 個引き当て（残り必要数 5）
NOTICE:  倉庫2 から 5 個引き当て（残り必要数 0）
```

商品 1（Laptop）は倉庫1に50個・倉庫2に10個あるので、倉庫1から50個・倉庫2から5個を取って終了しています。`least()` は「小さい方を返す」関数です。

## 5. 条件が続く間の繰り返し：`WHILE`

回数が決まっておらず、**条件が成り立つ間だけ**繰り返したいときに使います。

```sql
DO $$
DECLARE
    v_stock integer;
    v_days  integer := 0;
BEGIN
    SELECT stock_quantity INTO v_stock
      FROM inventory WHERE product_id = 3 AND warehouse_id = 1;

    RAISE NOTICE '初期在庫: %', v_stock;

    WHILE v_stock >= 20 LOOP
        v_stock := v_stock - 20;
        v_days  := v_days + 1;
    END LOOP;

    RAISE NOTICE '1日20個ずつ出荷すると % 日で残 % 個', v_days, v_stock;
END;
$$;
```

```
NOTICE:  初期在庫: 100
NOTICE:  1日20個ずつ出荷すると 5 日で残 0 個
```

> ⚠️ **`WHILE` は無限ループを作れます。**
> ループの中で条件に関わる変数（この例では `v_stock`）を**必ず変化させてください**。上の例で `v_stock := v_stock - 20;` を書き忘れると、永久に終わりません。DB を止めることになるので、書いた直後に「この条件はいつ偽になるか」を必ず確認してください。

## 6. ここまでのまとめ（構文一覧）

| やりたいこと | 書き方 |
|:---|:---|
| 条件分岐 | `IF … THEN … ELSIF … THEN … ELSE … END IF;` |
| 決まった回数 | `FOR i IN 1..5 LOOP … END LOOP;` |
| 逆順・きざみ | `FOR i IN REVERSE 5..1 LOOP` / `FOR i IN 1..10 BY 3 LOOP` |
| クエリの結果を 1 行ずつ | `FOR r_x IN SELECT … LOOP … END LOOP;` |
| 抜ける・飛ばす | `EXIT WHEN 条件;` / `CONTINUE WHEN 条件;` |
| 条件が続く間 | `WHILE 条件 LOOP … END LOOP;` |

## 7. 【手を動かす】ループで書くと、どれだけ遅いか

ここが**この章でいちばん大事な節**です。

[[12-1_PLpgSQLの基礎とDOブロック|12-1]] §1-2 で「1 文の SQL で書ける処理をループにするな」と書きました。ここで実際に測ります。

題材は「**顧客ごとの合計金額を出す**」です。研修生が書きがちなのは次の形です。

1. 顧客の一覧をループで回す
2. **ループの中で、その顧客の合計を毎回集計する**

これに対して、SQL なら `GROUP BY` 1 文で終わります。

### 7-1. 比較用のデータを作る

**この節の比較のためだけに使うテーブルです。最後に削除します。**

```sql
DROP TABLE IF EXISTS demo_orders;

CREATE TABLE demo_orders (
    order_id    integer PRIMARY KEY,
    customer_id integer,
    amount      numeric(10, 2)
);

-- 500人の顧客に、10万件の注文を割り振る
INSERT INTO demo_orders (order_id, customer_id, amount)
SELECT i, (i % 500) + 1, (i % 97) + 1
  FROM generate_series(1, 100000) AS i;

ANALYZE demo_orders;
```

### 7-2. 測る

psql なら `\timing on` で各文の実行時間が出ます。

```sql
\timing on

-- ① 1件ずつループして、毎回集計する
DO $$
DECLARE
    r_cust  RECORD;
    v_total numeric;
BEGIN
    FOR r_cust IN SELECT DISTINCT customer_id FROM demo_orders LOOP
        SELECT COALESCE(sum(amount), 0) INTO v_total
          FROM demo_orders
         WHERE customer_id = r_cust.customer_id;
    END LOOP;
END;
$$;

-- ② 1文で集計する
SELECT customer_id, sum(amount) FROM demo_orders GROUP BY customer_id;
```

実測（2 回実行した結果）：

```
-- ① ループ版
DO
Time: 3475.203 ms (00:03.475)

-- ② 1文版
Time: 37.821 ms
```

```
-- 2回目
-- ① ループ版
DO
Time: 3941.810 ms (00:03.942)

-- ② 1文版
Time: 43.985 ms
```

**約 90 倍の差です。** 結果はまったく同じです。

後片付け：

```sql
\timing off
DROP TABLE demo_orders;
```

### 7-3. なぜこんなに違うのか

ループ版は、顧客 500 人ぶん、**同じテーブルを 500 回スキャンしています**。1 回あたり 7 ミリ秒でも、500 回で 3.5 秒です。

一方 `GROUP BY` は、**テーブルを 1 回読みながら顧客ごとに足し込みます**。1 回で済みます。

この「ループの中で毎回クエリを投げる」形は **N+1 問題** と呼ばれ、アプリケーション側でも DB 側でも同じように起きる、代表的な性能の落とし穴です。

> 💡 **単純な処理なら差は小さくなります。**
> 「10万行を 1 行ずつ主キーで `UPDATE` する」対「1 文の `UPDATE`」も測りましたが、こちらは 1.2〜1.9 倍程度でした（実測）。差が爆発するのは、**ループの中でクエリを投げるとき**です。
> とはいえ、遅い方に書く理由はありません。**1 文で書けるなら 1 文で書いてください。**

### 7-4. では、いつループを使うのか

ループが必要なのは、**1 行ごとに違う判断をしないと処理できない**場合です。

- 1 行ごとに、結果によって処理を変える必要がある（§4 の在庫引き当てのように、前の行の結果が次の行の処理に影響する）
- 1 行ごとに、エラーを個別に処理したい（[[12-4_関数とプロシージャと例外処理|12-4]]）
- 1 行ごとに、外部の関数やプロシージャを呼ぶ必要がある

**「SQL でどう書けばいいか分からないから」はループを使う理由になりません。** まず 1 文で書けないかを考えてください。

## この章のまとめ

- **`IF … THEN … ELSIF … ELSE … END IF;`。** 終わりは `END IF;`
- **NULL はどの条件にも当てはまらず `ELSE` に落ちる。** `ELSE` を書き忘れると NULL のケースが消える
- **`ELSIF` と `ELSEIF` はどちらも通る**が、混在させない
- **値を 1 つ選ぶだけなら CASE 式**（06章既習）
- **`FOR i IN 1..5`** は 5 も含む。`REVERSE` のときは「大きい方..小さい方」
- **`FOR r_x IN SELECT … LOOP` が実務の主役。** `ORDER BY` を書く／`IN` の中に `INTO` は書けない
- **`EXIT WHEN` / `CONTINUE WHEN`** で 1 行に書ける
- **`WHILE` は無限ループを作れる。** 条件に関わる変数を必ず変化させる
- **ループの中でクエリを投げると、実測で約 90 倍遅くなった。** 1 文で書けるなら 1 文で書く
