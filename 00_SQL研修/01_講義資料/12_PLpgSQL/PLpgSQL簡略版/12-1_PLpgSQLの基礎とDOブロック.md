# PL/pgSQL の基礎と DO ブロック
## 〜SQL に「手順」を持ち込む〜

ここまで書いてきた SQL は、すべて **「1 つの問いに 1 つの答え」** でした。「条件に合う行を取ってくる」「条件に合う行を更新する」——どれも 1 文で完結しています。

ですが実務では、**「取ってきた値を見てから、次に何をするか決める」**という処理が必要になります。「この顧客の会員ランクを調べて、Gold なら A の処理、それ以外なら B の処理」「対象の行を 1 件ずつ見て、条件に合うものだけ更新する」——こうした**手順（手続き）**は、SQL 1 文では書けません。

そこで使うのが **PL/pgSQL** です。SQL に**変数**・**条件分岐**・**繰り返し**・**エラー処理**を足した言語で、PostgreSQL に最初から組み込まれています。

> **この資料の前提**
> - PostgreSQL 17 で動作確認しています。掲載しているエラーメッセージ・出力は**すべて実測**です。
> - 使用するテーブルは [[00_SQL研修/02_問題/08_結合から使用するテーブル|08_結合から使用するテーブル]] で作成したもの（8章以降と同じ）です。新しく作るものはありません。
> - [[15-1_導入_トランザクションとACID|15-1]] の自動コミット（§2）を読んでいることを前提にします。

## 1. PL/pgSQL とは何か

### 1-1. どこで動くのか

PL/pgSQL のコードは、**PostgreSQL サーバの中で動きます**。

同じ処理をアプリケーション（Java や Python）側で書くと、こうなります。

```
アプリ  ──「顧客1のランクは?」──▶  DB
アプリ  ◀──「Silver です」────────  DB
（アプリ側で分岐を判断）
アプリ  ──「ではこう更新して」───▶  DB
アプリ  ◀──「更新しました」───────  DB
```

往復が 2 回発生しています。PL/pgSQL で書けば、**判断ごと DB の中で完結する**ので往復は 1 回です。

```
アプリ  ──「顧客1を処理して」────▶  DB （中で取得・判断・更新）
アプリ  ◀──「処理しました」───────  DB
```

DB とアプリが別サーバにある実務のシステムでは、この往復（ネットワークの遅延）が積み上がると無視できない差になります。**まとまった手順を一塊で DB に投げられる**のが PL/pgSQL の主な利点です。

### 1-2. 【重要】使わない方がいい場合

先に釘を刺しておきます。**1 文の SQL で書ける処理を PL/pgSQL のループで書き直すと、たいてい遅くなります。**

```sql
-- ○ これで済むなら、これが一番速い
UPDATE products SET price = price * 1.1 WHERE category_id = 1;
```

これを「1 行ずつ取ってきて、1 行ずつ UPDATE する」ループに書き換えると、同じ結果でも実行時間は何倍にもなります（[[12-3_制御構造|12-3]] §7 で実測します）。

PL/pgSQL を使うのは、**「SQL 1 文では表現できない手順があるとき」だけ**です。「PL/pgSQL で書いた方が速い」ではありません。ここを取り違えると、遅いシステムを量産することになります。

## 2. 最小の PL/pgSQL：DO ブロック

### 2-1. まず動かす

PL/pgSQL のコードを**名前を付けずにその場で 1 回だけ実行する**のが `DO` 文です。**匿名ブロック**と呼びます。

```sql
DO $$
BEGIN
    RAISE NOTICE 'PL/pgSQL が動きました';
END;
$$;
```

実行結果：

```
NOTICE:  PL/pgSQL が動きました
DO
```

これが最小の PL/pgSQL です。構造は 3 つしかありません。

| 部分 | 役割 |
|:---|:---|
| `DO $$` … `$$;` | 「この中身は PL/pgSQL のコードです」とサーバに渡す枠 |
| `BEGIN` … `END;` | 処理の本体。**ブロック**と呼ぶ |
| `RAISE NOTICE '…'` | メッセージを表示する |

> ⚠️ **ここでの `BEGIN` は、トランザクションの `BEGIN` とは別物です。**
> [[15-1_導入_トランザクションとACID|15-1]] で使った `BEGIN;`（トランザクション開始）と綴りは同じですが、PL/pgSQL の `BEGIN` は**「ブロックの始まり」**という意味しかありません。混同しやすいので、最初に区別しておいてください。

### 2-2. 結果は表で返ってこない

`DO` ブロックは **値を返せません**。実行結果は `DO` という 1 行だけです。

つまり `SELECT` の代わりにはなりません。**中で何が起きたかを確認する手段は `RAISE NOTICE` です。** ここが最初につまずくところなので、先に押さえてください。

### 2-3. NOTICE はどこに表示されるか

| ツール | 表示場所 |
|:---|:---|
| `psql` | そのまま画面に出る |
| pgAdmin のクエリツール | **「Messages」タブ**（結果グリッドではない） |

pgAdmin で `RAISE NOTICE` を書いたのに「何も出ない」という場合、**Data Output タブを見ています**。Messages タブに切り替えてください。

## 3. 書き方のきまり

### 3-1. `%` で値を埋め込む

`RAISE NOTICE` の文字列に `%` を書くと、後ろに並べた値がその位置に順番に入ります。

```sql
DO $$
BEGIN
    RAISE NOTICE '顧客ID % の割引率は % %% です', 1, 10;
END;
$$;
```

```
NOTICE:  顧客ID 1 の割引率は 10 % です
```

- `%` の数と、後ろに並べる値の数は**一致させる**必要があります。
- **`%` そのものを表示したいときは `%%`** と 2 つ書きます（上の例の「10 % です」の部分）。

### 3-2. `$$` は何をしているのか

`DO` に渡すコード本体は、PostgreSQL からは**ただの文字列**として扱われます。本来は文字列なのでシングルクォートで囲む必要があります。

```sql
-- 原理的にはこう書ける（が、実務では書かない）
DO 'BEGIN RAISE NOTICE ''こんにちは''; END;';
```

コードの中にシングルクォートが出てくるたびに `''` と 2 つ重ねなければならず、すぐに読めなくなります。

これを避けるのが **`$$`（ドル引用符、dollar quoting）** です。`$$` から `$$` までを丸ごと文字列として扱うので、**中のシングルクォートをそのまま書けます**。

```sql
DO $$
BEGIN
    RAISE NOTICE 'こんにちは';   -- そのまま書ける
END;
$$;
```

コード本体の中にさらに `$$` を書きたい場合は、`$body$ … $body$` のように**タグ付き**にもできます。実務では `$$` で足りることがほとんどです。

### 3-3. セミコロンの位置

セミコロンの打ち忘れが、最初のうち一番多いエラーです。

```sql
DO $$
BEGIN
    RAISE NOTICE 'ひとつめ';   -- ← 文の末尾に必要
    RAISE NOTICE 'ふたつめ';   -- ← 文の末尾に必要
END;                          -- ← END の後にも必要
$$;                           -- ← DO 文全体の終わりにも必要
```

**「各文の末尾」「`END` の後」「`$$` の後」の 3 か所すべてに必要**と覚えてください。

### 3-4. `LANGUAGE plpgsql` は省略できる

`DO` 文の正式な書き方は `$$ LANGUAGE plpgsql;` ですが、**言語を省略すると `plpgsql` が使われます**。この資料では省略した形（`$$;`）で統一します。

## 4. 変数を使う

### 4-1. `DECLARE` で宣言し、`:=` で代入する

変数は `BEGIN` の**前**に `DECLARE` セクションを置いて宣言します。使えるデータ型は SQL と同じです（[[01_データ型|01_データ型]]）。

```sql
DO $$
DECLARE
    v_customer_name text;
    v_target_id     integer := 1;   -- 宣言と同時に初期値を入れられる
BEGIN
    SELECT name INTO v_customer_name
      FROM customers
     WHERE customer_id = v_target_id;

    RAISE NOTICE 'ID % の顧客は % さんです', v_target_id, v_customer_name;
END;
$$;
```

```
NOTICE:  ID 1 の顧客は Alice さんです
```

- **代入は `:=`** です。SQL の比較演算子 `=` と見分けるためにこの記号を使います。
- `SELECT … INTO 変数` で、クエリの結果を変数に受け取れます。この構文は次章で詳しく扱います（[[12-2_変数とSQLの実行|12-2]] §1）。
- 宣言していない変数を使うとエラーになります。**使う変数はすべて `DECLARE` に書く**必要があります。

## 5. 変数名のつけ方

### 5-1. 【手を動かす】変数名と列名がぶつかると壊れる

ここは**必ず一度踏むエラー**なので、先に自分で起こしておきます。

変数名を、テーブルの列名と同じ `customer_id` にしてみます。

```sql
DO $$
DECLARE
    customer_id integer := 1;
    v_name      text;
BEGIN
    SELECT name INTO v_name
      FROM customers
     WHERE customer_id = customer_id;

    RAISE NOTICE '%', v_name;
END;
$$;
```

実行すると、こうなります（実測）。

```
ERROR:  column reference "customer_id" is ambiguous
DETAIL:  It could refer to either a PL/pgSQL variable or a table column.
CONTEXT:  PL/pgSQL function inline_code_block line 6 at SQL statement
```

**`column reference "customer_id" is ambiguous`（列の参照 `customer_id` が曖昧です）。** `DETAIL` が理由をそのまま書いています——**「PL/pgSQL の変数」と「テーブルの列」のどちらを指しているか決められない**。

### 5-2. だから接頭辞を付ける

この衝突は、**変数名が列名と決して一致しないようにする**だけで完全に防げます。この研修では次の規約で統一します。

| 対象 | 接頭辞 | 例 |
|:---|:---|:---|
| 変数 | `v_` (variable) | `v_customer_name` |
| 引数 | `p_` (parameter) | `p_customer_id` |
| 行データを入れる変数 | `r_` (record) | `r_product` |

`v_` を付けた §4-1 の例が動いていたのは、この規約のおかげです。

> 💡 **なぜ規約で解くのか。**
> PostgreSQL には「衝突したらどちらを優先するか」を指定する設定もありますが、**設定でごまかすと、そのコードを読む人が設定を知らないと意味を取り違えます**。名前を衝突させない方が、読む人にとって安全です。

## 6. ブロックは入れ子にできる

`BEGIN … END;` の中に、さらに `BEGIN … END;` を書けます。内側のブロックは自分専用の `DECLARE` を持てます。

```sql
DO $$
DECLARE
    v_message text := '外側の値';
BEGIN
    RAISE NOTICE '外側: %', v_message;

    DECLARE
        v_message text := '内側の値';   -- 外側と同じ名前で宣言
    BEGIN
        RAISE NOTICE '内側: %', v_message;
    END;

    RAISE NOTICE '外側に戻ると: %', v_message;
END;
$$;
```

```
NOTICE:  外側: 外側の値
NOTICE:  内側: 内側の値
NOTICE:  外側に戻ると: 外側の値
```

**内側で宣言した変数は内側だけで有効**で、外側の同名変数には影響しません（**スコープ**）。内側を抜けると外側の値がそのまま見えています。

入れ子が本当に効いてくるのは**エラー処理**（[[12-4_関数とプロシージャと例外処理|12-4]]）です。「この一部分だけ、失敗しても全体を止めない」という区切りをブロックで作れます。今は「入れ子にできる」「変数の有効範囲はブロック単位」まで押さえてください。

## この章のまとめ

- **PL/pgSQL は SQL に「手順」を足す言語。** 変数・分岐・繰り返し・エラー処理が書ける
- **1 文の SQL で書ける処理をループにするな。** PL/pgSQL は速くするための道具ではない
- **`DO $$ … $$;` がその場で 1 回実行する匿名ブロック。** 値は返せないので、確認は `RAISE NOTICE`
- **pgAdmin では NOTICE は「Messages」タブに出る**
- **セミコロンは「各文の末尾」「`END` の後」「`$$` の後」の 3 か所**
- **代入は `:=`。変数は `DECLARE` で宣言する**
- **変数名は `v_` / 引数は `p_`。** 列名と衝突すると `column reference … is ambiguous` で止まる
- **ブロックは入れ子にでき、変数の有効範囲はブロック単位**
