 ## PostgreSQL集計関数とグループ化
### 1. 集計とグループ化の目的

PostgreSQLに格納された大量のデータからビジネスの意思決定に役立つ洞察を得るためには、データを要約し、傾向を把握することが不可欠です。そのために「集計」と「グループ化」という強力な機能が用意されています。

*   **集計**: 複数のデータ行から合計値や平均値といった単一の要約値を計算します。
*   **グループ化**: データを特定の基準（例：カテゴリ別、部署別）でグループに分割し、そのグループごとに集計を行います。

### 2. 基本的な集計関数

集計関数は、複数の行の値をまとめて計算し、1つの結果を返します。`SELECT`句や`HAVING`句で使用されます。

#### COUNT()：行数を数える

指定した条件に合致する行の数を数えます。

*   `COUNT(*)`: **テーブルの全行数**を返します。NULL値も含まれます。
*   `COUNT(column_name)`: 指定した列で **NULLではない値**の数を返します。
*   `COUNT(DISTINCT column_name)`: 指定した列で **重複を除いたNULLではない値**の数を返します。

**使用例 (`products` テーブル)**
```sql
-- テーブルの総商品数を取得
SELECT COUNT(*) AS total_products FROM products;

-- 価格が設定されている（NULLではない）商品数を取得
SELECT COUNT(price) AS products_with_price FROM products;

-- 商品カテゴリの種類の数を取得
SELECT COUNT(DISTINCT category) AS unique_categories FROM products;
```

> **コラム: `COUNT(1)` と `COUNT(*)` の違いは？**
> 結論から言うと、現代のPostgreSQLにおいて、**機能的・パフォーマンス的な違いはほとんどありません**。どちらもテーブルの全行数をカウントします。`COUNT(*)` の方がSQL標準で意図が分かりやすいため、一般的に使用が推奨されます。


#### SUM()：合計値を計算する

数値列の合計値を算出します。計算の過程でNULL値は無視されます。

**使用例**
```sql
-- 全商品の在庫数の合計を算出
SELECT SUM(stock_quantity) AS total_stock FROM products;
```


#### AVG()：平均値を計算する

数値列の平均値を算出します。分母・分子の計算においてNULL値は除外されます。

**使用例**
```sql
-- 全商品の平均価格を算出
SELECT AVG(price) AS average_price FROM products;
```


#### MIN() / MAX()：最小値・最大値を求める

指定した列の最小値または最大値を求めます。数値だけでなく、文字列や日付型にも使用できます。

**使用例**
```sql
-- 最も高価な商品の価格を取得
SELECT MAX(price) AS max_price FROM products;

-- アルファベット順で最も先頭に来る商品名を取得
SELECT MIN(product_name) AS first_product_name FROM products;
```

#### 集計関数におけるNULLの扱い

`COUNT(*)`を除くほとんどの集計関数 (`SUM`, `AVG`, `MIN`, `MAX`, `COUNT(列名)`) は、**計算の対象からNULL値を自動的に除外します**。

特に`AVG`関数では注意が必要です。例えば `(100 + 200 + NULL) / 3` ではなく `(100 + 200) / 2` のように計算されます。もしNULLを0として扱いたい場合は、`AVG(COALESCE(列名, 0))` のように関数を組み合わせる必要があります。

### 3. 補足: PostgreSQLで便利な応用集計関数 ※ここは飛ばして大丈夫です

基本的なものに加え、PostgreSQLにはより高度な集計を可能にする便利な関数があります。

#### STRING_AGG()：文字列を連結する

グループ化された複数の行の文字列を、指定した区切り文字で連結して一つの文字列にします。

**使用例 (カテゴリごとに商品名をカンマ区切りでリスト化)**
```sql
SELECT
  category,
  STRING_AGG(product_name, ', ') AS product_list
FROM products
GROUP BY category;
```



#### ARRAY_AGG()：値を配列にする

グループ化された複数の行の値を、一つの配列（Array型）にまとめて返します。

**使用例 (カテゴリごとに商品IDを配列で取得)**
```sql
SELECT
  category,
  ARRAY_AGG(product_id ORDER BY product_name) AS product_ids
FROM products
GROUP BY category;
```
*`ORDER BY`を内部で指定することで、配列内の順序を制御できます。*


#### BOOL_AND() / BOOL_OR()：真偽値（Boolean）を集計する

Boolean型の列を集計するための関数です。

*   `BOOL_AND(expression)`: グループ内の全ての値が`true`であれば`true`を返します（論理積）。
*   `BOOL_OR(expression)`: グループ内に一つでも`true`があれば`true`を返します（論理和）。

**使用例 (カテゴリ内の全ての商品が公開中（is_public=true）か判定)**
```sql
SELECT
  category,
  BOOL_AND(is_public) AS all_products_public
FROM products
GROUP BY category;
```

### 4. データのグループ化と絞り込み

#### GROUP BY句：データをグループに分割

指定した列の値が同じ行を一つのグループにまとめ、そのグループごとに集計関数を適用します。

**重要なルール**: `SELECT`句に集計関数を使わない列を記述する場合、その列は**必ず`GROUP BY`句にも含める必要があります**。

**使用例 (カテゴリごとの商品数と平均価格を算出)**
```sql
SELECT
  category,
  COUNT(*) AS product_count,
  AVG(price) AS average_price
FROM products
GROUP BY category;
```

> **コラム: PostgreSQLにおける厳格なGROUP BYルール**
> PostgreSQLはSQL標準に準拠しており、`SELECT`句に指定された非集計列は必ず`GROUP BY`句に含める必要があります。これは、グループごとにどの行の値を返すべきか一意に定まらないためです。この厳格なルールにより、意図しない値が返されることを防ぎ、クエリの信頼性を高めています。


#### HAVING句：グループ化後の結果を絞り込む

`GROUP BY`句で集計された**結果に対して**条件を指定し、さらに絞り込みを行う場合に使用します。`HAVING`句では集計関数を条件として利用できます。

**使用例 (商品数が10個以上あるカテゴリのみを抽出)**
```sql
SELECT
  category,
  COUNT(*) AS product_count
FROM products
GROUP BY category
HAVING COUNT(*) >= 10;
```


### 5. SQLの評価順序とWHERE句・HAVING句の違い

SQLクエリは記述する順番と、内部で評価される順番が異なります。この違いを理解することが`WHERE`と`HAVING`を正しく使い分ける鍵となります。

#### SQLの評価順序（概念）

1.  **`FROM` / `JOIN`**: 対象テーブルを決定
2.  **`WHERE`**: **行の絞り込み (グループ化の前)**
3.  **`GROUP BY`**: グループ化
4.  **`HAVING`**: **グループの絞り込み (グループ化の後)**
5.  **`SELECT`**: 列の選択、式の評価
6.  **`ORDER BY`**: 結果の並び替え
7.  **`LIMIT` / `OFFSET`**: 表示行の制限

| 特徴 | WHERE句 | HAVING句 |
| :--- | :--- | :--- |
| **評価タイミング** | `GROUP BY`の前（個々の行が対象） | `GROUP BY`の後（グループが対象） |
| **使用できる要素** | 元テーブルの列 | `GROUP BY`で指定した列、**集計関数** |
| **目的** | 集計対象となる行を事前にフィルタリング | 集計結果を元にグループをフィルタリング |

**実践例**
在庫が10より多い商品を対象に、カテゴリごとの平均価格を算出し、その平均価格が500を超えるカテゴリのみを抽出する場合。

```sql
SELECT
  category,
  AVG(price) AS average_price
FROM products
WHERE stock_quantity > 10 -- (1) まず個々の行を絞り込む
GROUP BY category
HAVING AVG(price) > 500;  -- (2) 次に集計結果でグループを絞り込む
```


### 6. HAVING句の応用：高度な条件フィルタリング

`HAVING`句は、単に「合計が100以上」といった単純な条件だけでなく、集計関数の中で`CASE`式を組み合わせることで、「グループ内のデータの構成比」や「集合としての性質」を判定する強力な武器になります。

#### 6.1 条件付き集計（CASE式との組み合わせ）

標準SQLでは、集計関数の中に`CASE`式を入れることで、特定の条件に合致する行だけをカウントしたり合計したりできます。

```SQL
-- 使用する一時テーブル
WITH
	testresults (student_id, class, sex, score) AS (
		VALUES
			('001', 'A', '男', 100),
			('002', 'A', '女', 100),
			('003', 'A', '女', 49),
			('004', 'A', '男', 30),
			('005', 'B', '女', 100),
			('006', 'B', '男', 92),
			('007', 'B', '男', 80),
			('008', 'B', '男', 80),
			('009', 'B', '女', 10),
			('010', 'C', '男', 92),
			('011', 'C', '男', 80),
			('012', 'C', '女', 21),
			('013', 'D', '女', 100),
			('014', 'D', '女', 0),
			('015', 'D', '女', 0)
	)
```

**使用例1：クラスの75%以上が80点以上のクラスを抽出**
```sql
SELECT
    class,
    COUNT(*) AS total_students,
    COUNT(CASE WHEN score >= 80 THEN 1 END) AS high_scorers
FROM testresults
GROUP BY class
HAVING 
    -- 80点以上の人数 ≧ 全体人数の75%
    COUNT(CASE WHEN score >= 80 THEN 1 END) >= COUNT(*) * 0.75;
```

**使用例2：50点以上の生徒のうち、男子より女子が多いクラス**
```sql
SELECT
    class,
    COUNT(CASE WHEN score >= 50 AND sex = '男' THEN 1 END) AS male_passers,
    COUNT(CASE WHEN score >= 50 AND sex = '女' THEN 1 END) AS female_passers
FROM testresults
GROUP BY class
HAVING
    COUNT(CASE WHEN score >= 50 AND sex = '男' THEN 1 END) < 
    COUNT(CASE WHEN score >= 50 AND sex = '女' THEN 1 END);
```

> **解説：なぜこれで動くのか？**
> 集計関数（`COUNT`, `AVG`, `SUM`等）は、**NULLを無視する**という性質があります。
> `CASE WHEN 条件 THEN 1 END` と書くと、条件を満たさない場合は（ELSEがないため）`NULL`になります。結果として、条件に合う行だけが計算対象となります。

#### 6.2 平均計算における注意点（NULLと0の扱い）

「特定の属性の平均」を算出する場合、条件に合致しない行を「0」にするか「NULL（指定なし）」にするかで結果が大きく変わります。

**正しい例：女子の平均が男子の平均より高いクラスを探す**
```sql
SELECT
    class,
    AVG(CASE WHEN sex = '女' THEN score END) AS female_avg,
    AVG(CASE WHEN sex = '男' THEN score END) AS male_avg
FROM testresults
GROUP BY class
HAVING
    AVG(CASE WHEN sex = '女' THEN score END) > 
    AVG(CASE WHEN sex = '男' THEN score END);
```

⚠️ **注意：間違った集計（不正確な平均）**
```sql
-- 良くない例
AVG(CASE WHEN sex = '女' THEN score ELSE 0 END)
```
*   **理由**: `ELSE 0` と書くと、「男子」のスコアが「0点」として女子の計算に含まれてしまいます。
*   **結果**: 「女子の合計点 ÷ **クラス全員の人数**」という計算になり、正しい女子の平均点が出ません。
*   **原則**: 条件外の行は `ELSE` を書かずに `NULL` にし、計算の母集団（分母）から除外するのが正解です。

#### 6.3 集合の特性判定（全称命題と存在命題）

「全員が〇〇である（全称）」や「少なくとも一人が〇〇である（存在）」といった、グループ全体の構成状態を判定するテクニックです。

```SQL
-- 使用する一時テーブル
WITH
	teams (member, team_id, status) AS (
		VALUES
			('ジョー', 1, '待機'),
			('ケン', 1, '出動中'),
			('ミック', 1, '待機'),
			('カレン', 2, '出動中'),
			('キース', 2, '休暇'),
			('ジャン', 3, '待機'),
			('ハート', 3, '待機'),
			('ディック', 3, '待機'),
			('ベス', 4, '待機'),
			('アレン', 5, '出動中'),
			('ロバート', 5, '休暇'),
			('ケーガン', 5, '待機')
	)
```

**① 全称命題：メンバー全員が「待機」状態のチームを抽出**
```sql
SELECT team_id
FROM teams
GROUP BY team_id
HAVING 
    -- チームの総人数 = 「待機」状態の人数
    COUNT(*) = COUNT(CASE WHEN status = '待機' THEN 1 END);
```

**② 存在命題：少なくとも一人は「休暇中」がいるチームを抽出**
```sql
SELECT team_id, COUNT(*) AS team_members
FROM teams
GROUP BY team_id
HAVING 
    -- 「休暇」状態の人数が1人以上
    COUNT(CASE WHEN status = '休暇' THEN 1 END) >= 1;
```

> **設計のポイント：論理の使い分け**
> *   **全員が条件を満たす（全称）**: `全体数 = 条件一致数`
> *   **一通りの条件が揃っている**: `COUNT(DISTINCT 列) = (期待する種類数)`
> *   **一部でも条件を満たす（存在）**: `条件一致数 > 0`


### 7. クロス集計：行を列に変える

「カテゴリごとの商品数」は1つの列で足りますが、「カテゴリごとに、在庫切れが何件・残りわずかが何件」を
**横に並べて比べたい**ことがあります。集計関数の中に条件を入れると、これができます。

以降の例は [[02_DDL（前半用）]] の `products_mst` を使います。

#### 7.1 集計関数の中に CASE を入れる

```sql
SELECT category,
  COUNT(*)                                                    AS 商品数,
  COUNT(CASE WHEN stock_quantity = 0 THEN 1 END)              AS 在庫切れ,
  COUNT(CASE WHEN stock_quantity BETWEEN 1 AND 99 THEN 1 END) AS 残りわずか,
  COUNT(CASE WHEN stock_quantity >= 100 THEN 1 END)           AS 在庫あり
FROM products_mst
GROUP BY category
ORDER BY category;
```

```
    category    | 商品数 | 在庫切れ | 残りわずか | 在庫あり
----------------+--------+----------+------------+----------
 Books          |      5 |        0 |          2 |        3
 Electronics    |      5 |        0 |          1 |        4
 Food           |      4 |        0 |          1 |        3
 Home & Kitchen |      3 |        1 |          1 |        1
 Stationery     |      3 |        0 |          0 |        3
 Toys           |      3 |        3 |          0 |        0
(6 rows)
```

**`GROUP BY` は1回だけ、`WHERE` も使っていません。** 1回のテーブル走査で3種類の内訳が同時に出ます。
`WHERE` で絞ると3回クエリを投げることになり、しかも横に並べられません。

動いている仕組みは §6.1 と同じです。`ELSE` を書かないので条件外の行は `NULL` になり、
`COUNT` が `NULL` を無視します。

#### 7.2 `FILTER` 句：同じことを短く書く

集計関数には `FILTER (WHERE 条件)` を付けられます。**「この集計だけに効く `WHERE`」**です。

```sql
SELECT category,
  COUNT(*)                                                AS 商品数,
  COUNT(*) FILTER (WHERE stock_quantity = 0)              AS 在庫切れ,
  COUNT(*) FILTER (WHERE stock_quantity BETWEEN 1 AND 99) AS 残りわずか,
  COUNT(*) FILTER (WHERE stock_quantity >= 100)           AS 在庫あり
FROM products_mst
GROUP BY category
ORDER BY category;
```

§7.1 と**まったく同じ6行**が返ります。`CASE` 版と違って「条件を満たさない行は `NULL` になり、
集計関数がそれを無視する」という一段の推論が要らないので、意図がそのまま読めます。

`SUM` でも同じです。

```sql
SELECT category,
  SUM(stock_quantity)                              AS 在庫合計,
  SUM(stock_quantity) FILTER (WHERE price >= 3000) AS うち3000円以上
FROM products_mst
GROUP BY category
ORDER BY category;
```

```
    category    | 在庫合計 | うち3000円以上
----------------+----------+----------------
 Books          |      720 |            210
 Electronics    |     1040 |            540
 Food           |      910 |           NULL
 Home & Kitchen |      190 |            190
 Stationery     |     1220 |           NULL
 Toys           |        0 |              0
(6 rows)
```

> [!warning] ⚠️ 該当行が1件も無いと `SUM` は 0 ではなく `NULL` を返します
> `Food` と `Stationery` は3000円以上の商品が無いので `NULL` です。`Toys` は該当商品があって
> 在庫が全部0なので `0` です。**`NULL` と `0` は別の意味**なので、0として扱いたいなら
> `COALESCE(SUM(...) FILTER (...), 0)` と書きます。

#### 7.3 `GROUP BY` のキーを `CASE` で作る

`GROUP BY` はグループ分けのキーを書く場所なので、`CASE`式が書けます。
**元のテーブルに無い区分でまとめ直せます。**

```sql
SELECT
  CASE
    WHEN category IN ('Electronics', 'Home & Kitchen') THEN '家電・生活'
    WHEN category IN ('Books', 'Stationery')           THEN '書籍・文具'
    ELSE 'その他'
  END AS 大分類,
  COUNT(*)            AS 商品数,
  SUM(stock_quantity) AS 在庫合計
FROM products_mst
GROUP BY 大分類
ORDER BY 大分類;
```

```
   大分類   | 商品数 | 在庫合計
------------+--------+----------
 その他     |      7 |      910
 家電・生活 |      8 |     1230
 書籍・文具 |      8 |     1940
(3 rows)
```

> 🐘 **どこまで通じる話か**
> `GROUP BY 大分類` のように**出力列の別名でグループ化できるのは PostgreSQL の拡張**です。
> 標準SQL では `GROUP BY` に書けるのは元テーブルの列だけなので、標準に寄せるなら
> `SELECT` に書いた `CASE`式を `GROUP BY` にもう一度書きます（同じ結果になります）。
> 別名が使えるのは `GROUP BY` と `ORDER BY` で、`WHERE` では使えません（→ [[02_CRUDについて]] §エイリアス）。

> [!warning] ⚠️ `ELSE` を省くと `NULL` という名前のグループができます
> ```sql
> SELECT
>   CASE WHEN category IN ('Electronics', 'Home & Kitchen') THEN '家電・生活' END AS 大分類,
>   COUNT(*) AS 商品数
> FROM products_mst
> GROUP BY 大分類
> ORDER BY 大分類;
> ```
>
> ```
>    大分類   | 商品数
> ------------+--------
>  家電・生活 |      8
>  NULL       |     15
> (2 rows)
> ```
>
> 残り15件が `NULL` グループに全部落ちました。**新しいカテゴリが追加されたときも黙ってここに入る**ので、
> `ELSE 'その他'` を書いて受け止めます。
