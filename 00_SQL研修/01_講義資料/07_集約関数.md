## 集計関数とグループ化

### 集計とは

ここまでの `SELECT` は、**1行が1行として返ってきました。**
集計関数を使うと、**複数の行が1行にまとまります。**

```
product_id | price          
-----------+---------          SUM(price)
         1 | 12800.00    →    ----------
         2 |  2500.00           15300.00
```

「何行あるか」「合計はいくらか」「いちばん高いのはいくらか」といった、
**個々の行を見ているだけでは分からないこと**を出すための道具です。

さらに `GROUP BY` を使うと、**グループごとに1行**という形にできます。
「カテゴリごとの商品数」「月ごとの注文件数」はこれで出します。

---

### 0. この章で使うテーブル

**[[02_DDL（前半用）]] の4テーブルをそのまま使います。** 新しく作るものはありません。
この章は `SELECT` だけなのでデータは変わりません。

| 使うもの | 中身 |
| :--- | :--- |
| `products_mst` | 23件。うち**販売終了が1件**（`deleted_at` が入っている）、`memo` 未入力が7件、`category` は6種 |
| `customers_mst` | 9件。うち**退会済みが1件** |
| `orders_trn` | 18件。うち**キャンセルが2件**。`order_date` は 2023年8月〜2024年9月 |

**この章の例は、断りが無いかぎり `WHERE deleted_at IS NULL` で「生きている行」に絞ります。**
`deleted_at` は論理削除のメタカラムなので、**集計に混ぜると数字が実態とずれます**
（販売終了の商品を在庫合計に足す、退会した顧客を会員数に数える、など）。
実務の集計はまずここを絞るところから始まります。

## 1. 集計関数：複数の行を1つの値にする

集計関数は `SELECT`句と `HAVING`句に書けます。**`WHERE`句には書けません**（理由は §3-2）。

### 1-1. `COUNT`：行数を数える

`COUNT` は書き方が3つあり、**数えるものが違います。**

| 書き方 | 数えるもの |
| :--- | :--- |
| `COUNT(*)` | **行数。** 中身が `NULL` でも数える |
| `COUNT(列名)` | その列が **`NULL` でない行の数** |
| `COUNT(DISTINCT 列名)` | その列の **`NULL` でない値の種類数**（同じ値は1つとして数える） |

`DISTINCT` は「重複を除く」という指定です。`COUNT(DISTINCT category)` は
「カテゴリが何種類あるか」で、商品が何件あるかではありません。
`DISTINCT` を `SELECT` の直後に書いて**行そのものの重複を消す**使い方は §4 で扱います。

```sql
SELECT
  COUNT(*)                 AS 全行数,
  COUNT(memo)              AS memoが入っている行,
  COUNT(DISTINCT category) AS カテゴリの種類
FROM products_mst;
```

```
 全行数 | memoが入っている行 | カテゴリの種類
--------+--------------------+----------------
     23 |                 16 |              6
(1 row)
```

23件のうち `memo` が入っているのは16件、カテゴリは6種類。
**`COUNT(*)` と `COUNT(列名)` の差が、その列の未入力件数です**（→ §1-4）。

> [!note]- `COUNT(1)` と書いてもよいか
> `COUNT(*)` と同じ結果になり、速度も変わりません。ただし `COUNT(*)` のほうが
> 「行を数える」という意図がそのまま読めるので、`COUNT(*)` を使ってください。

### 1-2. `SUM` / `AVG`：合計と平均

```sql
SELECT
  SUM(stock_quantity) AS 在庫合計,
  AVG(price)          AS 平均価格
FROM products_mst
WHERE deleted_at IS NULL;
```

```
 在庫合計 |       平均価格
----------+-----------------------
     4010 | 4868.6363636363636364
(1 row)
```

`AVG` は割り算なので、**桁が延々と出ます。** 表示桁は `ROUND` で決めます
（`ROUND` は [[00_SQL研修/01_講義資料/04_関数|04_関数]] §4.1）。

```sql
SELECT
  SUM(stock_quantity)   AS 在庫合計,
  ROUND(AVG(price), 2)  AS 平均価格
FROM products_mst
WHERE deleted_at IS NULL;
```

```
 在庫合計 | 平均価格
----------+----------
     4010 |  4868.64
(1 row)
```

### 1-3. `MIN` / `MAX`：最小と最大

数値だけでなく、**文字列や日付にも使えます。**

```sql
SELECT MIN(price) AS 最安値, MAX(price) AS 最高値
FROM products_mst
WHERE deleted_at IS NULL;
```

```
 最安値 |  最高値
--------+----------
 750.00 | 29800.00
(1 row)
```

```sql
SELECT MIN(created_date) AS 最初の登録日, MAX(created_date) AS 最新の登録日
FROM customers_mst;
```

```
 最初の登録日 | 最新の登録日
--------------+--------------
 2023-01-15   | 2023-09-18
(1 row)
```

日付の `MIN` / `MAX` は「初回いつ、最後がいつ」を出す形で実務によく出ます。

### 1-4. 集計関数は `NULL` を無視する

**`COUNT(*)` を除くすべての集計関数は、`NULL` の行を計算から外します。**
`SUM` は足さず、`AVG` は分母にも数えず、`MIN` / `MAX` は候補にしません。

```sql
SELECT
  COUNT(*)               AS 全行数,
  COUNT(memo)            AS memoあり,
  COUNT(*) - COUNT(memo) AS memoなし
FROM products_mst
WHERE deleted_at IS NULL;
```

```
 全行数 | memoあり | memoなし
--------+----------+----------
     22 |       16 |        6
(1 row)
```

**`COUNT(*)` は22、`COUNT(memo)` は16。** この差の6件が `memo` 未入力です。
`WHERE memo IS NOT NULL` で絞る必要はありません。**列名を渡すだけで数えないでくれます。**

`AVG` でこの性質が効くと、結果の意味が変わります。
`(100 + 200 + NULL) / 3` ではなく `(100 + 200) / 2` になるので、
**`NULL` を 0 として扱いたい場合だけ `AVG(COALESCE(列名, 0))` と書きます。**

## 2. `GROUP BY`：グループごとに集計する

### 2-1. `GROUP BY` の書き方

`GROUP BY` に書いた列の値が同じ行を1つのグループにまとめ、**グループごとに集計関数を適用**します。
結果は**1グループ1行**になります。

```sql
SELECT
  category,
  COUNT(*)             AS 商品数,
  ROUND(AVG(price), 2) AS 平均価格
FROM products_mst
WHERE deleted_at IS NULL
GROUP BY category
ORDER BY category;
```

```
    category    | 商品数 | 平均価格
----------------+--------+----------
 Books          |      5 |  2760.00
 Electronics    |      4 | 12020.00
 Food           |      4 |  1600.00
 Home & Kitchen |      3 |  6600.00
 Stationery     |      3 |  1510.00
 Toys           |      3 |  4833.33
(6 rows)
```

> [!warning] ⚠️ `GROUP BY` を書いたら `ORDER BY` も書く
> **グループが返ってくる順番は保証されません。** たまたま揃って見えることがあるだけで、
> データが増えると並びが変わります。並べたいなら `ORDER BY` を書いてください。

### 2-2. `SELECT` に書けるのは、`GROUP BY` の列と集計関数だけ

グループは複数行のかたまりなので、**その中の1行しか持っていない値は返せません。**
`category` でまとめたグループに `product_name` が5つあるとき、どれを返すべきか決まらないからです。

```sql
SELECT category, product_name, COUNT(*)
FROM products_mst
GROUP BY category;
```

```
ERROR:  column "products_mst.product_name" must appear in the GROUP BY clause or be used in an aggregate function
LINE 1: SELECT category, product_name, COUNT(*)
                         ^
```

エラーメッセージがそのまま逃げ道を教えてくれています。**`GROUP BY` に足すか、集計関数で包むか**の2つです。

- `GROUP BY category, product_name` … グループを細かくする（＝別の集計になる）
- `MAX(product_name)` … 「そのグループの代表として1つ選ぶ」と決める

### 2-3. 集計の軸を式で作る

`GROUP BY` に書けるのは**列だけではありません。式を書けば、元のテーブルに無い軸でまとめ直せます。**

#### 年月でまとめる

日付をそのまま `GROUP BY` に書くと**1日ずつ**のグループになります。月単位で見たいときは、
**`TO_CHAR(日付, 'YYYY-MM')` で「年月」という文字列のキーを作ります**
（`TO_CHAR` は [[00_SQL研修/01_講義資料/04_関数|04_関数]] §2.4）。

```sql
SELECT
  TO_CHAR(order_date, 'YYYY-MM') AS 年月,
  COUNT(*)                       AS 注文件数
FROM orders_trn
WHERE deleted_at IS NULL
GROUP BY 年月
ORDER BY 年月;
```

```
  年月   | 注文件数
---------+----------
 2023-08 |        8
 2023-09 |        3
 2024-02 |        2
 2024-03 |        1
 2024-08 |        2
(5 rows)
```

**`'YYYY-MM'` は年と月の両方を持つので、年が違えば別のグループになります。**
`YYYY-MM` の文字列は辞書順に並べても時系列順になるので、`ORDER BY` もそのまま使えます。

#### 区分でまとめる

`CASE`式（[[00_SQL研修/01_講義資料/06_CASE式|06_CASE式]]）を `GROUP BY` に書けば、任意の区分でまとめられます。

```sql
SELECT
  CASE
    WHEN category IN ('Electronics', 'Home & Kitchen') THEN '家電・生活'
    WHEN category IN ('Books', 'Stationery')           THEN '書籍・文具'
    ELSE 'その他'
  END AS 大分類,
  COUNT(*)            AS 商品数,
  SUM(stock_quantity) AS 在庫合計
FROM products_mst
WHERE deleted_at IS NULL
GROUP BY 大分類
ORDER BY 大分類;
```

```
   大分類   | 商品数 | 在庫合計
------------+--------+----------
 その他     |      7 |      910
 家電・生活 |      7 |     1160
 書籍・文具 |      8 |     1940
(3 rows)
```

> 🐘 **どこまで通じる話か**
> `GROUP BY 大分類` のように**出力列の別名でグループ化できるのは PostgreSQL の拡張**です。
> 標準SQL では `GROUP BY` に書けるのは元テーブルの列と式だけなので、標準に寄せるなら
> `SELECT` に書いた `TO_CHAR(...)` / `CASE ... END` を `GROUP BY` にもう一度書きます（同じ結果になります）。
> 別名が使えるのは `GROUP BY` と `ORDER BY` で、`WHERE` では使えません（→ [[02_CRUDについて]] §エイリアス）。

> [!warning]- ⚠️ `ELSE` を省くと `NULL` という名前のグループができます
> ```sql
> SELECT
>   CASE WHEN category IN ('Electronics', 'Home & Kitchen') THEN '家電・生活' END AS 大分類,
>   COUNT(*) AS 商品数
> FROM products_mst
> WHERE deleted_at IS NULL
> GROUP BY 大分類
> ORDER BY 大分類;
> ```
>
> ```
>    大分類   | 商品数
> ------------+--------
>  家電・生活 |      7
>  NULL       |     15
> (2 rows)
> ```
>
> 残り15件が `NULL` グループに全部落ちました。**新しいカテゴリが追加されたときも黙ってここに入る**ので、
> `ELSE 'その他'` を書いて受け止めます。

## 3. `HAVING`：グループを絞り込む

### 3-1. `HAVING` の書き方

`HAVING` は**グループを絞り込みます。** 集計した結果を条件に書けるのが `WHERE` との違いです。

```sql
SELECT category, COUNT(*) AS 商品数
FROM products_mst
WHERE deleted_at IS NULL
GROUP BY category
HAVING COUNT(*) >= 4
ORDER BY category;
```

```
  category   | 商品数
-------------+--------
 Books       |      5
 Electronics |      4
 Food        |      4
(3 rows)
```

§2-1 では6カテゴリ全部が出ていましたが、商品数4件以上の3カテゴリに絞られました。
**行が消えたのではなく、グループが消えています。**

### 3-2. `WHERE` と `HAVING` の違い

どちらも絞り込みですが、**効く相手とタイミングが違います。**

| | `WHERE` | `HAVING` |
| :--- | :--- | :--- |
| 何を絞るか | **行** | **グループ** |
| いつ効くか | `GROUP BY` の**前** | `GROUP BY` の**後** |
| 書けるもの | 元テーブルの列 | `GROUP BY` に書いた列、**集計関数** |
| 使いどころ | 集計に入れる行を選ぶ | 集計結果でグループを選ぶ |

**集計関数を `WHERE` に書けないのはこのためです。** `WHERE` が効く時点ではまだグループが無く、
`COUNT(*)` の値が決まっていません。

両方使う例です。「**在庫がある**販売中の商品だけを対象に、カテゴリごとの平均価格を出し、
その**平均が3000円を超える**カテゴリだけを見る」。

```sql
SELECT
  category,
  COUNT(*)             AS 商品数,
  ROUND(AVG(price), 2) AS 平均価格
FROM products_mst
WHERE deleted_at IS NULL
  AND stock_quantity > 0     -- (1) まず行を絞る
GROUP BY category
HAVING AVG(price) > 3000     -- (2) 次にグループを絞る
ORDER BY category;
```

```
    category    | 商品数 | 平均価格
----------------+--------+----------
 Electronics    |      4 | 12020.00
 Home & Kitchen |      2 |  5000.00
(2 rows)
```

`Home & Kitchen` は §2-1 では3件でしたが、在庫0の商品が1件あるので2件になっています。
**`WHERE` で落とした行は、そのあとの集計に一切現れません。**

句がどの順に処理されるかを、表が1段ずつ変わっていく形で追った資料があります。
`WHERE` と `HAVING` の関係がまだ飲み込めないときはこちらを見てください。

→ [[07_補足_groupByの論理実行順]]

## 4. `DISTINCT`：重複した行を除く

`GROUP BY` は**集計するため**にグループを作る道具です。
集計はせず、**重複した行を消して一覧にしたいだけ**のときは `DISTINCT` を使います。

### 4-1. `SELECT DISTINCT`：結果から重複行を消す

`Books` の商品名を出すと、同じ名前が2回出てきます。

```sql
SELECT product_name
FROM products_mst
WHERE deleted_at IS NULL
  AND category = 'Books'
ORDER BY product_name;
```

```
     product_name
-----------------------
 Python プログラミング
 SQL 入門
 SQL 入門
 データ分析の基礎
 自己啓発の法則
(5 rows)
```

`SQL 入門` が2件登録されているためです（`product_id` が 2 と 19）。
**商品の一覧が欲しいだけなら、重複は消したいところです。**

```sql
SELECT DISTINCT product_name
FROM products_mst
WHERE deleted_at IS NULL
  AND category = 'Books'
ORDER BY product_name;
```

```
     product_name
-----------------------
 Python プログラミング
 SQL 入門
 データ分析の基礎
 自己啓発の法則
(4 rows)
```

`DISTINCT` は `SELECT` の**直後に一度だけ**書きます。列ごとに付けるものではありません。
`GROUP BY` と同じく**返る順番は保証されない**ので（→ §2-1）、並べたいなら `ORDER BY` を書いてください。

> [!note]- `DISTINCT` を書くと、`ORDER BY` に使える列が減ります
> `SELECT` に無い列で並べようとするとエラーになります。
>
> ```sql
> SELECT DISTINCT category
> FROM products_mst
> WHERE deleted_at IS NULL
> ORDER BY price;
> ```
>
> ```
> ERROR:  for SELECT DISTINCT, ORDER BY expressions must appear in select list
> LINE 4: ORDER BY price;
>                  ^
> ```
>
> 重複を除いた時点で、結果に残っているのは `category` だけです。`price` は
> 同じカテゴリの中でも行ごとに違うので、「どの `price` で並べるか」が決まりません
> （`DISTINCT` は `ORDER BY` より前に効きます。→ [[07_補足_groupByの論理実行順]]）。

### 4-2. `DISTINCT` は列ではなく行に効く

**重複かどうかは、`SELECT` に並べた列の組み合わせで判定されます。**
先頭の列だけに効くのではありません。

```sql
SELECT DISTINCT category, product_name
FROM products_mst
WHERE deleted_at IS NULL
  AND category IN ('Books', 'Toys')
ORDER BY category, product_name;
```

```
 category |     product_name
----------+-----------------------
 Books    | Python プログラミング
 Books    | SQL 入門
 Books    | データ分析の基礎
 Books    | 自己啓発の法則
 Toys     | ぬいぐるみ（うさぎ）
 Toys     | ラジコンカー
 Toys     | 木製パズル
(7 rows)
```

`category` が何度も出てきます。**`(category, product_name)` の組み合わせで見れば
どの行も違うので、消える行が無い**からです（`SQL 入門` の2件だけが1行にまとまっています）。

**「カテゴリの一覧が欲しい」なら、列は `category` だけにします。**
列を足すほど組み合わせは細かくなり、重複は消えなくなります。

### 4-3. 表記のゆれは `DISTINCT` では消えない

**`DISTINCT` が1つにまとめるのは、完全に同じ値だけです。**
`Food` の商品名を出すと、`国産はちみつ` が2行残ります。

```sql
SELECT DISTINCT product_name
FROM products_mst
WHERE deleted_at IS NULL
  AND category = 'Food'
ORDER BY product_name;
```

```
       product_name
--------------------------
  国産はちみつ
 オーガニックコーヒー豆
 国産はちみつ
 高級チョコレートアソート
(4 rows)
```

1行目は `product_id = 20` の `' 国産はちみつ '` で、**前後に半角スペースが入っています。**
`'国産はちみつ'` とは別の値なので、`DISTINCT` はこれを重複とは見ません。

**揃えたい形を自分で作ってから、重複を除きます。**
前後の空白を落とすなら `TRIM`（[[00_SQL研修/01_講義資料/04_関数|04_関数]] §1.6）です。

```sql
SELECT DISTINCT TRIM(product_name) AS product_name
FROM products_mst
WHERE deleted_at IS NULL
  AND category = 'Food'
ORDER BY product_name;
```

```
       product_name
--------------------------
 オーガニックコーヒー豆
 国産はちみつ
 高級チョコレートアソート
(3 rows)
```

> ⚠️ **重複が消えないときは、まず値そのものを疑ってください。**
> 大文字小文字（`UPPER` / `LOWER`）、全角と半角、末尾の空白は、見た目が近くても別の値です。
> `DISTINCT` を付けたのに件数が減らないのは、たいていこれです。

### 4-4. `GROUP BY` との使い分け

**カテゴリの一覧は、どちらでも同じ6行が返ります。**

```sql
SELECT DISTINCT category
FROM products_mst
WHERE deleted_at IS NULL
ORDER BY category;
```

```
    category
----------------
 Books
 Electronics
 Food
 Home & Kitchen
 Stationery
 Toys
(6 rows)
```

§2-1 の `GROUP BY category` から集計関数を外した形（`SELECT category … GROUP BY category`）でも
結果は同じです。**同じ結果を返せるので、選ぶ基準は「何をしたいか」になります。**

| | `DISTINCT` | `GROUP BY` |
| :--- | :--- | :--- |
| 何のための道具か | **重複した行を消す** | **グループごとに集計する** |
| 集計関数 | 書けない | 書ける |
| `HAVING` でグループを絞る | できない | できる |
| 読み手に伝わること | 「一覧が欲しい」 | 「グループごとの数字が欲しい」 |

**集計しないなら `DISTINCT`。** `GROUP BY` で書くと「このあと何か数えるのだろう」と読まれます。
逆に、件数や合計を1つでも出すなら `GROUP BY` の側です。

### 4-5. `SELECT DISTINCT` と `COUNT(DISTINCT 列名)`

同じ `DISTINCT` ですが、**返るものが違います。**

| 書き方 | 返るもの |
| :--- | :--- |
| `SELECT DISTINCT 列名` | 重複を除いた**行**（種類の数だけ行が返る） |
| `COUNT(DISTINCT 列名)` | 種類の**個数**（1行返る。→ §1-1） |

```sql
SELECT
  COUNT(*)                     AS 全行数,
  COUNT(DISTINCT product_name) AS 商品名の種類
FROM products_mst
WHERE deleted_at IS NULL;
```

```
 全行数 | 商品名の種類
--------+--------------
     22 |           21
(1 row)
```

22行に対して商品名は21種類。**`SQL 入門` の2件が1種類に数えられた分の差**です。
`' 国産はちみつ '` は §4-3 のとおり別の値なので、ここでも別の種類として数えられています。

## 5. 条件付き集計：集計に条件を付ける

`WHERE` で絞ると**クエリ全体**が絞られます。
「合計は全体で、そのうち条件に合うぶんも並べて見たい」ときは、`WHERE` では書けません。
**集計関数の側に条件を持たせます。**

### 5-1. 集計関数の中に `CASE` を入れる

```sql
SELECT
  category,
  COUNT(*)                                  AS 商品数,
  COUNT(CASE WHEN price >= 3000 THEN 1 END) AS 高額商品数
FROM products_mst
WHERE deleted_at IS NULL
GROUP BY category
ORDER BY category;
```

```
    category    | 商品数 | 高額商品数
----------------+--------+------------
 Books          |      5 |          2
 Electronics    |      4 |          3
 Food           |      4 |          0
 Home & Kitchen |      3 |          3
 Stationery     |      3 |          0
 Toys           |      3 |          2
(6 rows)
```

**なぜこれで数えられるのか**は §1-4 と [[00_SQL研修/01_講義資料/06_CASE式|06_CASE式]] §2-2 の組み合わせです。

1. `CASE WHEN price >= 3000 THEN 1 END` は `ELSE` が無いので、条件に合わない行は `NULL` を返す
2. `COUNT` は `NULL` を数えない

つまり**条件に合う行だけが `1` になって数えられます。** `Food` と `Stationery` は
3000円以上の商品が無いので 0 です（`NULL` ではなく 0 なのは、`COUNT` が「数えた結果0件」を返すため）。

**`ELSE` は書きません。** `AVG` で同じことをするとき `ELSE 0` と書くと、条件外の行が
「0点」として分母に入ります（§1-4 のとおり `NULL` なら分母から外れます）。

### 5-2. クロス集計：行を列に変える

§5-1 の列を増やすと、**1つのグループの内訳を横に並べられます。**
「行」だったデータが「列」になるので**クロス集計**と呼びます。

```sql
SELECT
  category,
  COUNT(*)                                                AS 商品数,
  COUNT(CASE WHEN price >= 10000 THEN 1 END)              AS 高額,
  COUNT(CASE WHEN price BETWEEN 3000 AND 9999 THEN 1 END) AS 中価格,
  COUNT(CASE WHEN price < 3000 THEN 1 END)                AS 低価格
FROM products_mst
WHERE deleted_at IS NULL
GROUP BY category
ORDER BY category;
```

```
    category    | 商品数 | 高額 | 中価格 | 低価格
----------------+--------+------+--------+--------
 Books          |      5 |    0 |      2 |      3
 Electronics    |      4 |    2 |      1 |      1
 Food           |      4 |    0 |      0 |      4
 Home & Kitchen |      3 |    0 |      3 |      0
 Stationery     |      3 |    0 |      0 |      3
 Toys           |      3 |    0 |      2 |      1
(6 rows)
```

**`GROUP BY` は1回、テーブルを読むのも1回だけです。**
`WHERE` で価格帯を絞る形にすると、クエリを3回投げることになり、しかも横に並べられません。

### 5-3. `FILTER` 句：同じことを短く書く

集計関数には `FILTER (WHERE 条件)` を付けられます。**「この集計だけに効く `WHERE`」**です。

```sql
SELECT
  category,
  COUNT(*)                                            AS 商品数,
  COUNT(*) FILTER (WHERE price >= 10000)              AS 高額,
  COUNT(*) FILTER (WHERE price BETWEEN 3000 AND 9999) AS 中価格,
  COUNT(*) FILTER (WHERE price < 3000)                AS 低価格
FROM products_mst
WHERE deleted_at IS NULL
GROUP BY category
ORDER BY category;
```

§5-2 と**まったく同じ6行**が返ります。`CASE` 版と違って
「条件に合わない行は `NULL` になり、集計関数がそれを無視する」という一段の推論が要らないので、
**やりたいことがそのまま読めます。**

> [!note]- `SUM` でも同じ ―― ただし該当0件は `NULL` になる
> ```sql
> SELECT
>   category,
>   SUM(stock_quantity)                               AS 在庫合計,
>   SUM(stock_quantity) FILTER (WHERE price >= 10000) AS うち高額商品
> FROM products_mst
> WHERE deleted_at IS NULL
> GROUP BY category
> ORDER BY category;
> ```
>
> ```
>     category    | 在庫合計 | うち高額商品
> ----------------+----------+--------------
>  Books          |      720 |         NULL
>  Electronics    |      970 |          250
>  Food           |      910 |         NULL
>  Home & Kitchen |      190 |         NULL
>  Stationery     |     1220 |         NULL
>  Toys           |        0 |         NULL
> (6 rows)
> ```
>
> `Toys` の在庫合計が `0` なのは「商品はあるが在庫が全部0」だから。
> `Books` の「うち高額商品」が `NULL` なのは「10000円以上の商品が1件も無い」から。
> **`0` と `NULL` は別の意味**です。0にしたいなら `COALESCE(SUM(...) FILTER (...), 0)` と書きます。

## 6. 【理解度チェック】`HAVING` で集合の性質を判定する

§5 の条件付き集計を `HAVING` に置くと、**「グループ全体がどうなっているか」を条件にできます。**

**ここは問題として出します。** 答えを開く前に、自分で書いてみてください。

> [!note]- `WITH ... AS (VALUES ...)` はその場限りの表を作る書き方です
> `WITH 名前 (列名, ...) AS (VALUES (値, ...), (値, ...))` と書くと、
> **そのSQLの中だけで使える表**を作れます。テーブルは作られないので、
> 実行しても手元のDBには何も残りません。
> **下のSQLは `WITH` から `ORDER BY` までを1つのSQLとして実行してください。**
> `WITH` そのものについては [[99_補足_CTE（共通テーブル式）]] にまとめてあります。

### 使うデータ

**チーム編成**（§6-1・§6-2 で使う。待機・出動中・休暇の3状態）

| `team_id` | メンバー | 状態 |
| ---: | :--- | :--- |
| 1 | ジョー / ケン / ミック | 待機・**出動中**・待機 |
| 2 | カレン / キース | **出動中**・**休暇** |
| 3 | ジャン / ハート / ディック | 待機・待機・待機（**全員待機**） |
| 4 | ベス | 待機（**1人だけ**） |
| 5 | アレン / ロバート / ケーガン | **出動中**・**休暇**・待機 |

```sql
WITH teams (member, team_id, status) AS (
  VALUES
    ('ジョー',   1, '待機'),   ('ケン',     1, '出動中'), ('ミック',   1, '待機'),
    ('カレン',   2, '出動中'), ('キース',   2, '休暇'),
    ('ジャン',   3, '待機'),   ('ハート',   3, '待機'),   ('ディック', 3, '待機'),
    ('ベス',     4, '待機'),
    ('アレン',   5, '出動中'), ('ロバート', 5, '休暇'),   ('ケーガン', 5, '待機')
)
```

**テストの点数**（§6-3・§6-4 で使う。クラス・性別・点数）

| `class` | 男子 | 女子 |
| ---: | :--- | :--- |
| A | 100 / 30 | 100 / 49 |
| B | 92 / 80 / 80 | 100 / 10 |
| C | 92 / 80 | 21 |
| D | （**0人**） | 100 / 0 / 0 |

```sql
WITH testresults (student_id, class, sex, score) AS (
  VALUES
    ('001', 'A', '男', 100), ('002', 'A', '女', 100), ('003', 'A', '女',  49), ('004', 'A', '男',  30),
    ('005', 'B', '女', 100), ('006', 'B', '男',  92), ('007', 'B', '男',  80), ('008', 'B', '男',  80),
    ('009', 'B', '女',  10),
    ('010', 'C', '男',  92), ('011', 'C', '男',  80), ('012', 'C', '女',  21),
    ('013', 'D', '女', 100), ('014', 'D', '女',   0), ('015', 'D', '女',   0)
)
```

### 6-1. 全員が条件を満たす（全称）

> **問題**：**全員が待機中**のチームを出してください。

**「全体の人数」と「条件に合う人数」が一致すれば、全員が満たしている**ということです。

> [!example]- 答え
> ```sql
> SELECT team_id, COUNT(*) AS 人数
> FROM teams
> GROUP BY team_id
> HAVING COUNT(*) = COUNT(CASE WHEN status = '待機' THEN 1 END)
> ORDER BY team_id;
> ```
>
> ```
>  team_id | 人数
> ---------+------
>        3 |    3
>        4 |    1
> (2 rows)
> ```
>
> チーム3は3人全員が待機、チーム4は1人だけでその1人が待機。どちらも「全員待機」です。

> ⚠️ **「1人もいない」も全称を満たします。** メンバーが0人のチームがあれば
> `COUNT(*) = 0` と `条件に合う人数 = 0` が一致するので「全員が待機」と判定されます。
> ただし `GROUP BY` はデータがある行しかグループを作らないので、1人もいないチームは
> そもそも結果に現れません。「0人のチームも出したい」ときはチーム側のテーブルと
> 突き合わせる必要があります（→ [[00_SQL研修/01_講義資料/08_結合|08_結合]]）。

### 6-2. 一つでも条件を満たす（存在）

> **問題**：**休暇中のメンバーが一人はいる**チームを、人数と休暇人数つきで出してください。

**条件に合う件数が1件以上あればよい**ので、`> 0` で判定します。

> [!example]- 答え
> ```sql
> SELECT
>   team_id,
>   COUNT(*)                                    AS 人数,
>   COUNT(CASE WHEN status = '休暇' THEN 1 END) AS 休暇
> FROM teams
> GROUP BY team_id
> HAVING COUNT(CASE WHEN status = '休暇' THEN 1 END) > 0
> ORDER BY team_id;
> ```
>
> ```
>  team_id | 人数 | 休暇
> ---------+------+------
>        2 |    2 |    1
>        5 |    3 |    1
> (2 rows)
> ```

「`NULL` かどうか」を条件にするなら `CASE` は要りません。
`COUNT(*)` と `COUNT(列名)` の差がそのまま「その列が未入力の件数」なので（→ §1-4）、
`HAVING COUNT(*) <> COUNT(列名)` で「未入力が1件でもあるグループ」が出せます。

### 6-3. 何割以上が条件を満たす

> **問題**：**80点以上の生徒が全体の75%以上**を占めるクラスを、人数と高得点者数つきで出してください。

構成比も `HAVING` に書けます。**割り算ではなく掛け算で書くのがポイントです。**

> [!note]- 割合を出すときは整数除算に注意
> **整数を整数で割ると、結果も整数になり、小数部は捨てられます。**
>
> ```sql
> SELECT
>   3 / 2          AS 整数で割る,
>   3 / 2.0        AS 小数で割る,
>   3::numeric / 2 AS キャストして割る;
> ```
>
> ```
>  整数で割る |     小数で割る     |  キャストして割る
> ------------+--------------------+--------------------
>           1 | 1.5000000000000000 | 1.5000000000000000
> (1 row)
> ```
>
> `COUNT` が返すのは整数です。**`COUNT` を `COUNT` で割ると整数除算になります。**
> 割合や比率を出すときは、**割る前にどちらかを小数にしておきます。**

> [!example]- 答え
> ```sql
> SELECT
>   class,
>   COUNT(*)                                AS 人数,
>   COUNT(CASE WHEN score >= 80 THEN 1 END) AS 高得点者
> FROM testresults
> GROUP BY class
> HAVING COUNT(CASE WHEN score >= 80 THEN 1 END) >= COUNT(*) * 0.75
> ORDER BY class;
> ```
>
> ```
>  class | 人数 | 高得点者
> -------+------+----------
>  B     |    5 |        4
> (1 row)
> ```
>
> `高得点者 / 人数 >= 0.75` と書くと `COUNT` 同士の整数除算になって答えが崩れます。
> **両辺に人数を掛けた形にすれば割り算が消えます。**

### 6-4. グループの中で2つの集計値を比べる

> **問題**：**女子の平均点が男子の平均点より高い**クラスを、両方の平均つきで出してください。

条件付き集計を2つ並べ、`HAVING` でそれ同士を比べます。

> [!example]- 答え
> ```sql
> SELECT
>   class,
>   ROUND(AVG(CASE WHEN sex = '女' THEN score END), 1) AS 女子平均,
>   ROUND(AVG(CASE WHEN sex = '男' THEN score END), 1) AS 男子平均
> FROM testresults
> GROUP BY class
> HAVING AVG(CASE WHEN sex = '女' THEN score END) > AVG(CASE WHEN sex = '男' THEN score END)
> ORDER BY class;
> ```
>
> ```
>  class | 女子平均 | 男子平均
> -------+----------+----------
>  A     |     74.5 |     65.0
> (1 row)
> ```
>
> **D組は出てきません。** 男子が0人なので `AVG(CASE WHEN sex = '男' ...)` が `NULL` になり、
> `NULL` との比較は真にならないからです。

> ⚠️ **ここで `ELSE 0` を書くと答えが変わります。** 条件外の行が「0点」として分母に入るので、
> A組の女子平均は 74.5 ではなく 37.3（女子の合計点 ÷ クラス全員の人数）になります（→ §5-1、§1-4）。

> [!note] 判定の型
> | 言いたいこと | 書き方 |
> | :--- | :--- |
> | **全員**が条件を満たす | `COUNT(*) = 条件に合う件数` |
> | **一つでも**条件を満たす | `条件に合う件数 > 0` |
> | 一通り**揃っている** | `COUNT(DISTINCT 列) = 期待する種類数` |
> | 何割以上が条件を満たす | `条件に合う件数 >= COUNT(*) * 0.5`（**割り算を使わない形**にする） |
> | 2つの集計値を**比べる** | `AVG(CASE ...) > AVG(CASE ...)`（片方が `NULL` のグループは出ない） |

## 7. 補足：PostgreSQL の応用集計関数

> [!note]- ここは読み飛ばしてよい枝葉です
> 基本の5つ（`COUNT` / `SUM` / `AVG` / `MIN` / `MAX`）が使えれば実務は回ります。
> 以下は「そういうものもある」という紹介です。
>
> #### `STRING_AGG`：グループの値を1つの文字列につなぐ
>
> ```sql
> SELECT category, STRING_AGG(product_name, ', ' ORDER BY product_name) AS 商品一覧
> FROM products_mst
> WHERE deleted_at IS NULL
> GROUP BY category
> ORDER BY category;
> ```
>
> ```
>     category    |                                    商品一覧
> ----------------+--------------------------------------------------------------------------------
>  Books          | Python プログラミング, SQL 入門, SQL 入門, データ分析の基礎, 自己啓発の法則
>  Electronics    | USB 充電器, スマートウォッチ, ポータブルバッテリー, ワイヤレスイヤホン
>  Food           |  国産はちみつ , オーガニックコーヒー豆, 国産はちみつ, 高級チョコレートアソート
>  Home & Kitchen | セラミックフライパン, 電気ケトル, 高性能ブレンダー
>  Stationery     | A4 ノート 5冊セット, 多機能ボールペン, 蛍光マーカー 6色
>  Toys           | ぬいぐるみ（うさぎ）, ラジコンカー, 木製パズル
> (6 rows)
> ```
>
> 関数の**中に** `ORDER BY` を書けるので、つなぐ順番を決められます。
> 帳票の「対象商品」欄を1セルに収めるときなどに使います。
>
> #### `BOOL_AND` / `BOOL_OR`：真偽値を集計する
>
> 真偽値を返す式を渡すと、グループ全体の論理積・論理和を返します。
> §6 の全称・存在をそのまま1つの関数で書ける形です。
>
> ```sql
> SELECT
>   category,
>   BOOL_AND(stock_quantity > 0) AS 全部在庫あり,
>   BOOL_OR(stock_quantity = 0)  AS 欠品が1つでもある
> FROM products_mst
> WHERE deleted_at IS NULL
> GROUP BY category
> ORDER BY category;
> ```
>
> ```
>     category    | 全部在庫あり | 欠品が1つでもある
> ----------------+--------------+-------------------
>  Books          | t            | f
>  Electronics    | t            | f
>  Food           | t            | f
>  Home & Kitchen | f            | t
>  Stationery     | t            | f
>  Toys           | f            | t
> (6 rows)
> ```
>
> `Home & Kitchen` と `Toys` に在庫0の商品があることが一目で分かります。
> ただし**件数が分からない**ので、発注量まで出したいなら §5 の条件付き集計を使います。

## 8. まとめ

- **集計関数は複数の行を1つの値にする。** `GROUP BY` を足すとグループごとに1行になる
- **`COUNT(*)` は行数、`COUNT(列名)` は `NULL` でない件数。** 差がその列の未入力件数（→ §1-1、§1-4）
- **`COUNT(*)` 以外の集計関数は `NULL` を無視する。** `AVG` の分母にも入らない（→ §1-4）
- **`SELECT` に書けるのは `GROUP BY` に書いた列と集計関数だけ**（→ §2-2）
- **`GROUP BY` には式が書ける。** 年月キーは `TO_CHAR(日付, 'YYYY-MM')`、区分は `CASE`（→ §2-3）
- **`WHERE` は行を、`HAVING` はグループを絞る。** 集計関数は `WHERE` に書けない（→ §3-2）
- **重複した行を消したいだけなら `DISTINCT`。** 集計するなら `GROUP BY`（→ §4）
- **集計に条件を付けたいときは `FILTER`、または集計関数の中に `CASE`**（→ §5）
- **条件付き集計の `CASE` に `ELSE` は書かない。** `AVG` で `ELSE 0` を書くと分母が変わる（→ §5-1）
- **`COUNT` を `COUNT` で割ると整数除算になる。** 割合は片方を小数にしてから割る（→ §6-3）
- **全称は `COUNT(*) = 条件に合う件数`、存在は `条件に合う件数 > 0`**（→ §6）

複数のテーブルをまたいだ集計（「顧客ごとの購入金額」など）は、
テーブルのつなぎ方を学んだあとの [[00_SQL研修/01_講義資料/08_結合|08_結合]] 以降で扱います。
