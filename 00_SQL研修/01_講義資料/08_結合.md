# JOINによる複数テーブルの結合

## 0. この章で使うテーブル

**この章から、以降の章まで同じテーブルを使います。** [[00_SQL研修/02_問題/08_結合から使用するテーブル|08_結合から使用するテーブル]] の DDL とテストデータを流してください。

説明では主に次の2つを使います。**この2つには、結合の種類による違いが見えるように仕込みがあります。**

| 使うもの | 中身 | 仕込み |
| :--- | :--- | :--- |
| `customers` | 顧客11人。`membership_id` で会員ランクを持つ | **Charlie だけ`membership_id`が`NULL`**（ランク未設定） |
| `memberships` | Bronze / Silver / Gold / Platinum の4ランク | **Platinum は誰も持っていない**（会員ゼロのランク） |

結合の種類を変えると、この **Charlie（ランクなしの顧客）** と **Platinum（会員ゼロのランク）** が出たり消えたりします。そこを見てください。

---

## 1. なぜテーブルを結合するのか

データベースでは、データの重複をなくし一貫性を保つために、関連するデータを複数のテーブルに分割して管理します（**正規化**）。

もし顧客と会員ランクを1つの表で持つと、「Silver の割引率を10%から12%に変える」ときに、Silver会員**全員の行**を書き換えることになります。1行でも漏れれば、同じ Silver なのに割引率が違う顧客が生まれます。ランクを別の表に分けておけば、書き換えるのは1行だけです。

分割すると管理は楽になりますが、**「顧客名とそのランク名を並べて見たい」**ときには、分かれた表を一時的に1つに戻す必要があります。この操作が **JOIN（結合）** です。

> [!note]- なぜ分けるのかをもっと詳しく
> テーブル分割の考え方そのものは [[00_なぜテーブルを分けるのか]] で扱っています。この章は「分けたものを戻す側」に集中します。

## 2. JOINの種類

| JOINの種類 | 何を返すか | 実務での重要度 | この章での扱い |
| :--- | :--- | :--- | :--- |
| **INNER JOIN** | 両方のテーブルに**一致する行だけ** | **非常に高** | §3 |
| **LEFT OUTER JOIN** | **左のテーブルを全部**＋右は一致すれば付ける | **非常に高** | §4 |
| **自己結合** | 同じテーブルを別名で2回使って結合する | 中 | §6 |
| FULL OUTER JOIN | **両方のテーブルを全部** | 低 | §7 |
| RIGHT OUTER JOIN | 右のテーブルを全部（`LEFT JOIN`の左右逆） | 低 | §8-2 |
| CROSS JOIN | すべての行の組み合わせ（総当たり） | 低 | §8-2 |

**覚えるのは`INNER JOIN`と`LEFT JOIN`、そして§5の「`ON`と`WHERE`の違い」です。** 残りは「そういうものがある」で構いません。

---

## 3. INNER JOIN：両方にある行だけ

`INNER JOIN`は、**両方のテーブルで結合条件に一致する行のみ**を返します。最も基本で、最も頻繁に使います。

#### 基本構文

```sql
SELECT 列リスト
FROM テーブル1 AS t1
INNER JOIN テーブル2 AS t2 ON t1.共通列 = t2.共通列;
```

#### 例：顧客名とその会員ランク名を並べる

```sql
SELECT
	c.name,
	m.rank_name
FROM
	customers AS c
	INNER JOIN memberships AS m ON c.membership_id = m.membership_id
ORDER BY
	c.customer_id;
```

**実行結果:** 11人いる顧客が **10行**になります。

```
 name  | rank_name
-------+-----------
 Alice | Silver
 Bob   | Bronze
 Diana | Gold
 Ellen | Silver
 Grace | Bronze
 Hank  | Bronze
 Ivy   | Bronze
 Jack  | Silver
 Kevin | Gold
 Leo   | Silver
(10 rows)
```

**両側に相手がいない行が消えます。**

- **Charlie が消えた** … `membership_id`が`NULL`なので、`memberships`のどの行とも一致しない
- **Platinum が出てこない** … 誰も持っていないランクなので、`customers`のどの行とも一致しない

「顧客の一覧が欲しかったのに1人足りない」という事故は、たいていこれです。

## 4. LEFT JOIN：左の行をすべて残す

`LEFT JOIN`は、**左側（`FROM`句に書いたテーブル）の行をすべて**返します。右側に一致する行がなければ、右側の列は`NULL`になります。

`LEFT JOIN`と`LEFT OUTER JOIN`は**まったく同じ意味**です（`OUTER`は省略できる）。

#### 例：全顧客を残したまま、ランク名を付ける

```sql
SELECT
	c.name,
	m.rank_name
FROM
	customers AS c
	LEFT JOIN memberships AS m ON c.membership_id = m.membership_id
ORDER BY
	c.customer_id;
```

**実行結果:** **11行**。`INNER JOIN`で消えた Charlie が戻ります。

```
  name   | rank_name
---------+-----------
 Alice   | Silver
 Bob     | Bronze
 Charlie | NULL
 Diana   | Gold
 Ellen   | Silver
 Grace   | Bronze
 Hank    | Bronze
 Ivy     | Bronze
 Jack    | Silver
 Kevin   | Gold
 Leo     | Silver
(11 rows)
```

Charlie の`rank_name`が`NULL`になっているのは、「ランク名が`NULL`という値だった」のではなく、**結合相手が見つからなかったので`NULL`で埋められた**という意味です。

**「親テーブルの行は全部出したい。子の情報は、あれば付ける」** が`LEFT JOIN`の使い所です。顧客一覧・商品一覧のような**一覧画面はほぼ`LEFT JOIN`**になります。

なお Platinum は出てきません。左が`customers`なので、`memberships`側だけにある行は残らないからです。

## 5. ON句とWHERE句の決定的な違い

**この章でいちばん事故が起きるところです。**

`ON`句と`WHERE`句はどちらも条件を書きますが、**評価されるタイミングが違います**。`INNER JOIN`ではどちらに書いても同じ結果になりますが、**`LEFT JOIN`では結果が変わります。**

- **`ON`句** … **結合するときの条件**。「どの行をくっつけてよいか」を判定する
- **`WHERE`句** … **結合し終わった結果**に対する絞り込み

### シナリオ

**「全顧客の一覧を出し、Silver 会員にだけランク名を表示したい」**（Silver でない人も一覧には残したい）

### 5-1. ON句に条件を書く（意図どおり）

```sql
SELECT
	c.name,
	m.rank_name
FROM
	customers AS c
	LEFT JOIN memberships AS m
		ON c.membership_id = m.membership_id
		AND m.rank_name = 'Silver'
ORDER BY
	c.customer_id;
```

**実行結果:** **11行**。全顧客が残り、Silver 以外は`NULL`になります。

```
  name   | rank_name
---------+-----------
 Alice   | Silver
 Bob     | NULL
 Charlie | NULL
 Diana   | NULL
 Ellen   | Silver
 Grace   | NULL
 Hank    | NULL
 Ivy     | NULL
 Jack    | Silver
 Kevin   | NULL
 Leo     | Silver
(11 rows)
```

`ON`句は「くっつけてよいか」の判定なので、**条件を満たさなければ`NULL`で埋めるだけ**で、左側の行は消えません。

### 5-2. WHERE句に条件を書く（LEFT JOIN が死ぬ）

```sql
SELECT
	c.name,
	m.rank_name
FROM
	customers AS c
	LEFT JOIN memberships AS m ON c.membership_id = m.membership_id
WHERE
	m.rank_name = 'Silver'
ORDER BY
	c.customer_id;
```

**実行結果:** **4行**。Silver 会員しか残りません。

```
 name  | rank_name
-------+-----------
 Alice | Silver
 Ellen | Silver
 Jack  | Silver
 Leo   | Silver
(4 rows)
```

`LEFT JOIN`はいったん11行を作りますが、そのあと`WHERE`が`m.rank_name = 'Silver'`でない行を落とします。**`NULL`で埋められた行も`NULL = 'Silver'`が真にならないので消えます。** 結果は`INNER JOIN`と同じになり、`LEFT JOIN`と書いた意味がなくなります。

> ⚠️ **`OUTER JOIN`で「右側のテーブル」を絞り込みたいなら`ON`句に書く。`WHERE`句に書くと`INNER JOIN`に化ける。**
> 逆に、結合し終わった結果から行を減らしたいとき（左側のテーブルの条件など）は`WHERE`句が正しいです。

## 6. 自己結合：同じテーブルを2回使う

同じテーブルに**違う別名を付けて2回書き**、自分自身と結合します。テーブル内の**行同士の関係**を見たいときに使います。

**`SELF JOIN`という構文はありません。** 同じテーブルを`INNER JOIN`や`LEFT JOIN`で結合しているだけです。別名を付けないと、どちらの`price`なのか区別できないので、別名が必須になります。

#### 例：従業員テーブルから、上司と部下の関係を見せる

```sql
WITH employees (employee_id, employee_name, manager_id) AS (
    VALUES
        (1, 'Alice', NULL),
        (2, 'Bob', 1),
        (3, 'Charlie', 1),
        (4, 'David', 2)
)
SELECT
    e.employee_name AS employee, -- 従業員
    m.employee_name AS manager   -- 上司
FROM
    employees AS e
LEFT JOIN -- 上司がいない従業員(Alice)も表示するためLEFT JOINを使用
    employees AS m ON e.manager_id = m.employee_id;
```

## 7. FULL OUTER JOIN：両方の行をすべて残す

**両方のテーブルのすべての行**を返します。一致しない行は、相手側の列が`NULL`になります。

#### 例：ランクなしの顧客も、会員ゼロのランクも、両方出す

```sql
SELECT
	c.name,
	m.rank_name
FROM
	customers AS c
	FULL OUTER JOIN memberships AS m ON c.membership_id = m.membership_id
ORDER BY
	c.customer_id NULLS LAST;
```

**実行結果:** **12行**。Charlie（ランクなし）と Platinum（会員ゼロ）が**両方**出ます。

```
  name   | rank_name
---------+-----------
 Alice   | Silver
 Bob     | Bronze
 Charlie | NULL
 Diana   | Gold
 Ellen   | Silver
 Grace   | Bronze
 Hank    | Bronze
 Ivy     | Bronze
 Jack    | Silver
 Kevin   | Gold
 Leo     | Silver
 NULL    | Platinum
(12 rows)
```

同じ2テーブルで、4種類の結合の件数を並べると違いがはっきりします。

| 結合 | 件数 | Charlie（ランクなし） | Platinum（会員ゼロ） |
| :--- | :--- | :--- | :--- |
| `INNER JOIN` | 10 | 消える | 消える |
| `LEFT JOIN` | 11 | **残る** | 消える |
| `FULL OUTER JOIN` | 12 | **残る** | **残る** |

実務での用途は「**2つの表の突き合わせ**」（どちらにしかない行を洗い出す）に絞られます。日常のクエリではまず使いません。

> [!note]- FULL OUTER JOIN が使えない環境
> `FULL OUTER JOIN`を持たないDBでは、`LEFT JOIN`の結果と`RIGHT JOIN`の結果を`UNION`でつないで同じものを作れます（`UNION`は9章）。
>
> ```sql
> SELECT ... FROM customers c LEFT  JOIN memberships m ON ...
> UNION
> SELECT ... FROM customers c RIGHT JOIN memberships m ON ...;
> ```

## 8. 補足

### 8-1. USING：結合キーの列名が同じとき

結合する2つのテーブルで**結合キーの列名がまったく同じ**なら、`ON`句の代わりに`USING`が書けます。`customers`と`memberships`はどちらも`membership_id`なので使えます。

```sql
SELECT
	name,
	rank_name
FROM
	customers
	INNER JOIN memberships USING (membership_id)
ORDER BY
	customer_id;
```

**実行結果:** §3 の`ON`句版と同じ10行です。

```
 name  | rank_name
-------+-----------
 Alice | Silver
 Bob   | Bronze
 Diana | Gold
 Ellen | Silver
 Grace | Bronze
 Hank  | Bronze
 Ivy   | Bronze
 Jack  | Silver
 Kevin | Gold
 Leo   | Silver
(10 rows)
```

`USING`で指定した列は結果の中で**1つにまとめられる**ため、`c.membership_id`のようにテーブル名で修飾する必要がなくなります。

ただし`USING`では次が書けません。**迷ったら`ON`を使ってください。**

- 列名が違う場合（`employee_id`と`staff_code`など）
- `=`以外での結合（範囲や大小の比較）
- 結合条件を複数書きたい場合

### 8-2. RIGHT JOIN と CROSS JOIN

**`RIGHT JOIN`** は`LEFT JOIN`の左右を逆にしたものです。`FROM A RIGHT JOIN B`は`FROM B LEFT JOIN A`と同じ結果になるので、**テーブルの書き順を入れ替えて`LEFT JOIN`に統一する**のが実務の作法です。「基準になる表を`FROM`に書く」と読み方が一定になり、複数結合したときに追いやすくなります。

**`CROSS JOIN`** は結合条件を書かず、すべての行の組み合わせ（デカルト積）を返します。`customers`（11行）と`memberships`（4行）なら`11 × 4 = 44行`です。「全店舗 × 全月」のような**組み合わせを網羅した枠を作る**とき以外は使いません。

> ⚠️ `ON`句の書き忘れや、結合条件が効いていない結合は、事実上`CROSS JOIN`になります。**結果の行数が元のテーブルより異常に多いときは、まずここを疑ってください。**
