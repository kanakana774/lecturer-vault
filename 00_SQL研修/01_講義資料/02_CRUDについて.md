# SQL 基礎：データ操作（CRUD）

## 導入：CRUD とは

SQL における **CRUD** とは、データベースを操作するための基本的な4つの機能の頭文字をとった言葉です。

|                | 操作          | SQL      |
| :------------- | :---------- | :------- |
| **C**reate（作成） | データの新規追加    | `INSERT` |
| **R**ead（読み取り） | データの検索・取得   | `SELECT` |
| **U**pdate（更新） | 既存データの変更    | `UPDATE` |
| **D**elete（削除） | データの削除      | `DELETE` |

これらの操作は、あらゆるデータベースアプリケーションの根幹をなします。

### この章で使うテーブル

以下の `products` テーブルを例に説明します。テーブルの作り方は [[01_RDBMSとDDL]]、データ型は [[01_データ型]] を参照してください。

```sql
CREATE TABLE products (
    product_id     INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,  -- 商品ID（自動採番）
    product_name   VARCHAR(255) NOT NULL,        -- 商品名
    price          NUMERIC(10, 2) DEFAULT 0.00,  -- 価格
    stock_quantity INTEGER DEFAULT 0             -- 在庫数
);
```

## データの作成 (Create)：`INSERT`

テーブルに新しい行（レコード）を追加します。

### 基本構文

**列名を指定する形**を基本にしてください。

```sql
INSERT INTO テーブル名 (列名1, 列名2, ...) VALUES (値1, 値2, ...);
```

`product_id` は自動採番されるので、指定する必要はありません。

```sql
INSERT INTO products (product_name, price, stock_quantity)
VALUES ('Laptop', 1200.00, 50);
```

列名を省いて `INSERT INTO テーブル名 VALUES (...)` と書くこともできますが、この形は**テーブル定義の列順に、全ての列の値を並べる**必要があります。

⚠️ **列名を省いた形は、自動採番の列も自分で埋めなければならない。** 上の `products` で列名を省くと、1つ目の値が `product_id` として扱われて失敗します（実測）。

```sql
INSERT INTO products VALUES ('Laptop', 1200.00, 50);
```

```
ERROR:  invalid input syntax for type integer: "Laptop"
LINE 1: INSERT INTO products VALUES ('Laptop', 1200.00, 50);
                                     ^
```

列の順序に依存し、テーブルに列が追加されただけで壊れるため、**実務では列名を必ず書きます**。

### 省略した列はどうなるか

列名を指定する形では、**書かなかった列にはデフォルト値が入り、デフォルト値が無ければ `NULL` が入ります**。

```sql
-- stock_quantity を省略 → DEFAULT の 0 が入る
INSERT INTO products (product_name, price)
VALUES ('Mouse', 25.50);
```

### 複数行をまとめて挿入

`VALUES` をカンマで並べれば、1文で何行でも挿入できます。1行ずつ `INSERT` を繰り返すより速く、テストデータの投入でよく使います。

```sql
INSERT INTO products (product_name, price, stock_quantity) VALUES
  ('Keyboard', 45.00, 12),
  ('Webcam',   85.00, 30),
  ('Monitor', 320.00,  8);
```

### 挿入した行を受け取る：`RETURNING` 句

通常、`INSERT` を実行しても「何件挿入した」という結果しか返りません。`RETURNING` を付けると、**挿入された直後の行**をその場で取得できます。**自動採番された ID を知りたいとき**に重宝します（実測）。

```sql
INSERT INTO products (product_name, price, stock_quantity) VALUES
  ('Laptop', 1200.00, 50),
  ('Mouse',    25.50,  0)
RETURNING product_id, product_name;
```

```
 product_id | product_name
------------+--------------
          1 | Laptop
          2 | Mouse
```

アプリケーション開発では「登録した直後の ID を使って別のテーブルに登録する」場面で使います。`RETURNING` は `UPDATE` と `DELETE` でも使えます（後述）。

## データの読み取り (Read)：`SELECT`

データベースからデータを取得する、最もよく使うコマンドです。

### 基本構文

```sql
SELECT 列名1 [AS 列のエイリアス], 列名2, ...
FROM テーブル名 [AS テーブルのエイリアス]
[WHERE 条件式]
[ORDER BY 列名 [ASC|DESC]]
[LIMIT 件数 [OFFSET 開始位置]];
```

### 取得する列の指定

必要な列名をカンマ区切りで並べます。

```sql
SELECT product_name, price FROM products;
```

アスタリスク `*` を使うと全ての列を取得できます。

```sql
SELECT * FROM products;
```

⚠️ **`*` は確認用と考えてください。** 使わない列まで転送されるだけでなく、**後から列が追加・削除されたときに結果の形が勝手に変わります**。アプリケーションから実行する SQL では、必要な列を明示的に並べます。

### エイリアス（別名）：`AS`

`AS` を使うと、列名やテーブル名に別名（エイリアス）を付けられます。`AS` は省略も可能です。

**列のエイリアス** — 取得結果の見出しを変えたり、計算結果に名前を付けたりできます。

```sql
SELECT
  product_name AS 商品名,
  price        AS 価格
FROM products;
```

**テーブルのエイリアス** — テーブル名が長いときや、複数のテーブルを結合する（JOIN）ときに、クエリを簡潔に書けます。

```sql
SELECT p.product_name, p.price
FROM products AS p
WHERE p.price > 1000;
```

⚠️ **列のエイリアスは `WHERE` では使えません。** `SELECT` で列を決めるより先に `WHERE` が評価されるためです。`ORDER BY` では使えます（実測）。

```sql
SELECT product_name, price AS 価格 FROM products WHERE 価格 > 100;    -- 通らない
SELECT product_name, price AS 価格 FROM products ORDER BY 価格 DESC;  -- 通る
```

```
ERROR:  column "価格" does not exist
LINE 1: ...T product_name, price AS 価格 FROM products WHERE 価格 > 100...
```

この「どの句が先に処理されるか」は [[07_補足_groupByの論理実行順]] で扱います。

> [!note]- エイリアスにダブルクォーテーションは必要か
> [[01_RDBMSとDDL]] で「列名をダブルクォーテーションで囲むと以後ずっとクォートし続けることになる」と書きましたが、**エイリアスは結果の表示名として使われるだけ**なので、そこまで気にする必要はありません。日本語のエイリアスもクォート無しで書けます。
> クォートが必要になるのは、**空白や記号を含めたい**とき（`AS "商品 名"`）と、**英字の大文字を残したい**とき（クォートしないと小文字に畳まれます）です。

### 条件による絞り込み：`WHERE` 句

特定の条件に合致する行だけを取得します。

```sql
-- 価格が1000より大きい商品を取得
SELECT product_name, price
FROM products
WHERE price > 1000;
```

比較演算子、`AND` / `OR`、`BETWEEN`、`IN`、`LIKE`、`IS NULL` といった条件の書き方は [[02_演算子]] にまとめてあります。

### 結果の並び替え：`ORDER BY` 句

取得した結果を、指定した列の値で並び替えます。

- **`ASC`**: 昇順（小さい順、既定）
- **`DESC`**: 降順（大きい順）

```sql
-- 価格が高い順に並び替え
SELECT product_name, price
FROM products
ORDER BY price DESC;
```

複数の列をキーとして並び替えることも可能です。

```sql
-- 在庫数が多い順、同じ在庫数なら価格が安い順に並び替え
SELECT product_name, price, stock_quantity
FROM products
ORDER BY stock_quantity DESC, price ASC;
```

### 取得件数の制限：`LIMIT` 句 / `OFFSET` 句

取得する行数を制限したり、開始位置をずらしたりします。Web アプリケーションのページネーション機能などでよく利用されます。

```sql
-- 価格が高い商品トップ3を取得
SELECT product_name, price
FROM products
ORDER BY price DESC
LIMIT 3;

-- 4件目から2件を取得（2ページ目のようなイメージ）
SELECT product_name, price
FROM products
ORDER BY product_name ASC
LIMIT 2 OFFSET 3;
```

⚠️ **`ORDER BY` の無い `LIMIT` は、どの行が返るか保証されません。** 同じデータ・同じ SQL でも、**更新が入ると並びが変わります**（実測）。

```sql
SELECT product_name FROM products LIMIT 2;
```

```
 product_name
--------------
 Laptop
 Mouse
```

ここで、`Mouse` の価格を更新してから同じ SQL を実行します。

```sql
UPDATE products SET price = 22.95 WHERE product_name = 'Mouse';
SELECT product_name FROM products LIMIT 2;
```

```
 product_name
--------------
 Laptop
 Keyboard      ← Mouse が返らなくなった
```

`Mouse` は削除されていません。**更新された行がテーブルの中で移動した**ためです（仕組みは [[17-1_導入_物理構造とスキャン方式]]）。**`LIMIT` を使うときは必ず `ORDER BY` を付けてください。**

> 🐘 **どこまで通じる話か**
> 件数を絞る構文は製品ごとに違います。`LIMIT` / `OFFSET` は PostgreSQL と MySQL の書き方で、SQL Server は `TOP`、Oracle は `ROWNUM` や `FETCH FIRST` を使います。

## データの更新 (Update)：`UPDATE`

既存のテーブルデータを変更します。

### 基本構文

```sql
UPDATE テーブル名
SET 列名1 = 新しい値1, 列名2 = 新しい値2, ...
[WHERE 条件式];
```

### 使用例

特定の行の価格を更新します。

```sql
UPDATE products
SET price = 1100.00
WHERE product_name = 'Laptop';
```

既存の値を元に計算して更新することもできます。

```sql
-- Mouse の価格を10%引き、在庫を1つ減らす
UPDATE products
SET price = price * 0.9, stock_quantity = stock_quantity - 1
WHERE product_name = 'Mouse';
```

### 更新した行を確認する：`RETURNING` 句

`INSERT` と同様に `UPDATE` でも使えます。返るのは**更新後の値**です（実測）。

```sql
UPDATE products
SET price = price * 0.9
WHERE product_name = 'Mouse'
RETURNING product_name, price;
```

```
 product_name | price
--------------+-------
 Mouse        | 22.95
```

## データの削除 (Delete)：`DELETE`

テーブルから行を削除します。

### 基本構文

```sql
DELETE FROM テーブル名
[WHERE 条件式];
```

### 使用例

在庫が0の商品を削除します。`RETURNING` を付けると、実際に消えた行が分かります。

```sql
DELETE FROM products
WHERE stock_quantity = 0
RETURNING product_name, stock_quantity;
```

```
 product_name | stock_quantity
--------------+----------------
 Mouse        |              0
```

なお、**全ての行を消してテーブルだけ残したい**場合は `TRUNCATE` の方が高速です（→ [[01_RDBMSとDDL]]）。

## UPDATE / DELETE の事故を防ぐ

`WHERE` を省略した `UPDATE` / `DELETE` は**エラーになりません。テーブルの全ての行が対象になります。**

```sql
UPDATE products SET price = 0;   -- 全商品の価格が 0 になる
DELETE FROM products;            -- 全ての行が消える
```

実行する前に、次の手順を習慣にしてください。

**手順1：同じ `WHERE` で `SELECT` して、対象を目で見る。**

```sql
-- これから変える／消す行を先に確認する
SELECT * FROM products WHERE price < 100;
```

**手順2：不安なときはトランザクションで囲み、`RETURNING` で確認してから確定する。**

`COMMIT` するまで結果は確定しないので、想定と違えば `ROLLBACK` で元に戻せます（実測）。

```sql
BEGIN;

DELETE FROM products
WHERE price < 100
RETURNING product_name, price;
```

```
 product_name | price
--------------+-------
 Keyboard     | 45.00
 Mouse        | 22.95
DELETE 2
```

```sql
ROLLBACK;                       -- 取り消す（想定どおりなら COMMIT で確定）
SELECT count(*) FROM products;  -- 3 … 元に戻っている
```

トランザクションの仕組みは [[15-1_導入_トランザクションとACID]] で扱います。
