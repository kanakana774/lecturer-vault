### SQLの集合演算子とは

集合演算子は、2つ以上の`SELECT`文の結果を、行を追加する形で**縦方向に結合**するための演算子です。

`JOIN`が「列を横に増やす」のに対し、集合演算子は「行を縦に増やす（あるいは減らす）」演算だと考えてください。つなぐ相手は**テーブルではなく`SELECT`文の結果**なので、片方は`WHERE`で絞っただけ、もう片方は`JOIN`した結果、というように**作り方が違っていても構いません**。

### 0. この章で使うサンプルデータ

以下の2つのテーブルを作ってから読み進めてください。**章の最後に片付けます。**

```sql
CREATE TABLE products_tmp (product_name TEXT);
INSERT INTO products_tmp VALUES ('Laptop'), ('Electronics'), ('Mouse'), ('Smartphone'), (NULL);

CREATE TABLE categories_tmp (category_name TEXT);
INSERT INTO categories_tmp VALUES ('Electronics'), ('Peripherals'), ('Mobile'), ('Smartphone'), (NULL);
```

`'Electronics'`と`'Smartphone'`が両方にあり、`NULL`も両方にあります。**この`NULL`が後半の主役**になります。

## 1. 4つの演算子

### 1-1. UNION：和集合（重複を排除）

複数の`SELECT`文の結果を1つにまとめます。その際、**完全に重複する行は1行にまとめて表示**します。

```sql
SELECT 列リスト FROM テーブル1
UNION
SELECT 列リスト FROM テーブル2;
```

#### 具体例

```sql
SELECT product_name FROM products_tmp
UNION
SELECT category_name FROM categories_tmp
ORDER BY product_name;
```

**実行結果:** 10行が7行になります。

```
 product_name
--------------
 Electronics
 Laptop
 Mobile
 Mouse
 Peripherals
 Smartphone

(7 rows)
```

最終行の空欄は`NULL`です。`'Electronics'`・`'Smartphone'`・`NULL`がそれぞれ1行にまとまりました。

### 1-2. UNION ALL：和集合（重複を保持）

`UNION`とは異なり、**重複する行もそのまま全て表示**します。重複チェックを行わない分、`UNION`より高速です（→ §5）。

```sql
SELECT product_name FROM products_tmp
UNION ALL
SELECT category_name FROM categories_tmp;
```

**実行結果:** 5行 + 5行 = 10行がそのまま出ます。

```
 product_name
--------------
 Laptop
 Electronics
 Mouse
 Smartphone

 Electronics
 Peripherals
 Mobile
 Smartphone

(10 rows)
```

### 1-3. INTERSECT：積集合（共通部分）

**両方に共通して存在する行のみ**を返します。`UNION`と同じく重複は排除されます。

```sql
SELECT product_name FROM products_tmp
INTERSECT
SELECT category_name FROM categories_tmp
ORDER BY product_name;
```

**実行結果:**

```
 product_name
--------------
 Electronics
 Smartphone

(3 rows)
```

**`NULL`も「共通」として取れている**点に注目してください（→ §3）。

### 1-4. EXCEPT / MINUS：差集合

最初の`SELECT`文の結果から、2番目の`SELECT`文の結果に**存在する行を取り除いた結果**を返します。こちらも重複は排除されます。

DBMSによってキーワードが異なります。

- **`EXCEPT`**: PostgreSQL, SQL Server, SQLite, MySQL 8.0.31以降
- **`MINUS`**: Oracle

```sql
SELECT product_name FROM products_tmp
EXCEPT
SELECT category_name FROM categories_tmp
ORDER BY product_name;
```

**実行結果:** `products_tmp`にしかない名前だけが残ります。

```
 product_name
--------------
 Laptop
 Mouse
(2 rows)
```

#### EXCEPT は左右を入れ替えると結果が変わる

`UNION`と`INTERSECT`は左右を入れ替えても同じ結果になりますが、**`EXCEPT`だけは変わります**。「AとBの違い」ではなく「AからBを引く」演算だからです。

```sql
SELECT category_name FROM categories_tmp
EXCEPT
SELECT product_name FROM products_tmp
ORDER BY category_name;
```

```
 category_name
---------------
 Mobile
 Peripherals
(2 rows)
```

「どちらか片方にしかない行」（対称差）が欲しいときは、両方向の`EXCEPT`を`UNION`でつなぎます。

```sql
(SELECT product_name FROM products_tmp EXCEPT SELECT category_name FROM categories_tmp)
UNION
(SELECT category_name FROM categories_tmp EXCEPT SELECT product_name FROM products_tmp)
ORDER BY 1;
```

```
 product_name
--------------
 Laptop
 Mobile
 Mouse
 Peripherals
(4 rows)
```

## 2. 書き方の規則

意味を覚えても、ここを知らないと**エラーで手が止まります**。4つあります。

### 2-1. 列の数は一致、型は「互換」であればよい

**列の数は完全に一致していなければなりません。**

```sql
SELECT 1, 2 UNION ALL SELECT 3;
-- ERROR:  each UNION query must have the same number of columns
```

一方、**データ型は「一致」でなく「互換であればよい」**、つまり片方に寄せられるなら通ります。

```sql
SELECT 1 AS n UNION ALL SELECT 2.5;   -- 通る（両方 numeric に解決される）
```

```
  n
-----
   1
 2.5
```

寄せられない組み合わせはエラーになります。

```sql
SELECT 1 AS n UNION ALL SELECT 'abc';
-- ERROR:  invalid input syntax for type integer: "abc"
```

> ⚠️ `integer` と `numeric` のように**黙って型が変わる**ことがあります。件数や桁数が想定と違うときは、まずここを疑ってください。

### 2-2. 列名は左端の SELECT が決める

結果の列名には、**いちばん左の`SELECT`で付けた名前だけ**が使われます。右側の列名は結果からは見えません。

```sql
SELECT product_name FROM products_tmp
UNION
SELECT category_name FROM categories_tmp
ORDER BY category_name;
-- ERROR:  column "category_name" does not exist
-- DETAIL:  There is a column named "category_name" in table "*SELECT* 2",
--          but it cannot be referenced from this part of the query.
```

意味の通る名前にしたいときは、**左端の`SELECT`で別名を付けます**。

```sql
SELECT product_name AS name FROM products_tmp
UNION
SELECT category_name FROM categories_tmp
ORDER BY name;
```

### 2-3. ORDER BY / LIMIT は全体に1つ、いちばん最後に書く

枝（個々の`SELECT`）に直接書くと**構文エラー**になります。

```sql
SELECT product_name FROM products_tmp ORDER BY product_name
UNION
SELECT category_name FROM categories_tmp;
-- ERROR:  syntax error at or near "UNION"
```

```sql
SELECT product_name FROM products_tmp LIMIT 2
UNION ALL
SELECT category_name FROM categories_tmp;
-- ERROR:  syntax error at or near "UNION"
```

正しくは、**全体の末尾に1つだけ**書きます。

```sql
SELECT product_name FROM products_tmp
UNION
SELECT category_name FROM categories_tmp
ORDER BY product_name;
```

どうしても枝ごとに絞りたいときは、**枝を括弧で囲みます**。

```sql
(SELECT product_name  FROM products_tmp   ORDER BY product_name  LIMIT 2)
UNION ALL
(SELECT category_name FROM categories_tmp ORDER BY category_name LIMIT 2);
```

```
 product_name
--------------
 Electronics
 Laptop
 Electronics
 Mobile
(4 rows)
```

> ⚠️ **`ORDER BY`を書かなければ、結果の並び順は保証されません。** 集合演算子は重複排除に並べ替えやハッシュを使うため、入力順にも辞書順にもなりません。実際、§1-1の例から`ORDER BY`を外すと `NULL, Electronics, Smartphone, Mouse, Peripherals, Laptop, Mobile` の順で返ってきます。**順序が要るなら必ず`ORDER BY`を書く。**

### 2-4. INTERSECT が先に結合する

3つ以上つないだとき、**`INTERSECT`は`UNION`／`EXCEPT`より優先して評価されます**（掛け算が足し算より先に計算されるのと同じ）。左から順に処理されるわけではありません。

```sql
-- 括弧なし → EXCEPT (INTERSECT ...) と解釈される
SELECT product_name FROM products_tmp
EXCEPT
SELECT category_name FROM categories_tmp
INTERSECT
SELECT 'Laptop'
ORDER BY 1;
```

```
 product_name
--------------
 Electronics
 Laptop
 Mouse
 Smartphone

(5 rows)
```

```sql
-- 左から順に、と書いたつもりならこちら
(SELECT product_name FROM products_tmp
 EXCEPT
 SELECT category_name FROM categories_tmp)
INTERSECT
SELECT 'Laptop'
ORDER BY 1;
```

```
 product_name
--------------
 Laptop
(1 row)
```

5行と1行。**同じ順番に並べただけで結果がまるで違います。**

> ⚠️ **3つ以上つなぐときは、必ず括弧で意図を書く。** エラーにならず黙って違う結果を返すため、レビューでも見落とされます。

## 3. NULL の扱い

**集合演算子は`NULL`同士を「同じ値」とみなします。** これが`JOIN`との決定的な違いです。

### 3-1. JOIN との違い

`JOIN`の`ON`句は`=`による比較なので、`NULL = NULL`は`TRUE`にならず**結合されません**。

```sql
SELECT p.product_name, c.category_name
FROM products_tmp p
INNER JOIN categories_tmp c ON p.product_name = c.category_name
ORDER BY p.product_name;
```

```
 product_name | category_name
--------------+---------------
 Electronics  | Electronics
 Smartphone   | Smartphone
(2 rows)
```

一方、`INTERSECT`は`NULL`を共通部分として拾います（§1-3の再掲、**3行**）。

```
 product_name
--------------
 Electronics
 Smartphone

(3 rows)
```

| | `INNER JOIN` | `INTERSECT` |
| :--- | :--- | :--- |
| `NULL`同士 | 結合されない（`UNKNOWN`） | **一致とみなす** |
| 上の例の件数 | 2件 | **3件** |

`UNION`なら重複する`NULL`は1つにまとめられ、`EXCEPT`なら右に`NULL`があれば左の`NULL`は消えます。

### 3-2. NOT IN の罠と、EXCEPT による回避

「AにあってBにない」を`NOT IN`で書くと、**Bに`NULL`が1つでも混ざっていると結果が0件になります。**

```sql
SELECT product_name FROM products_tmp
WHERE product_name NOT IN (SELECT category_name FROM categories_tmp);
```

```
 product_name
--------------
(0 rows)
```

`'Laptop' NOT IN ('Electronics', ..., NULL)` は「`'Laptop'`は`NULL`と違う」を判定できず`UNKNOWN`になり、`WHERE`は`TRUE`でない行を落とすためです。**エラーが出ず、静かに0件になる**のが厄介なところです。

`EXCEPT`は`NULL`を値として扱うので、この罠がありません。

```sql
SELECT product_name FROM products_tmp
EXCEPT
SELECT category_name FROM categories_tmp
ORDER BY product_name;
```

```
 product_name
--------------
 Laptop
 Mouse
(2 rows)
```

`NOT IN`のまま書くなら、右側から`NULL`を除きます。

```sql
SELECT product_name FROM products_tmp
WHERE product_name NOT IN (
	SELECT category_name FROM categories_tmp WHERE category_name IS NOT NULL
)
ORDER BY product_name;   -- 2件。EXCEPT と同じ結果になる
```

#### 3つの書き方は同じ結果にならない

「`products_tmp`にあって`categories_tmp`にない」という**同じ問い**を3通りで書くと、件数が3通りに割れます。原因は、`NULL`が左右のどちらにあるかで扱いが変わることです。

| 書き方 | 件数 | 結果 | なぜ |
| :--- | :--- | :--- | :--- |
| `NOT IN` | **0件** | （なし） | 右に`NULL`があると全ての判定が`UNKNOWN`になり、全滅する |
| `NOT EXISTS` | **3件** | Laptop, Mouse, `NULL` | 全滅はしない。ただし`=`比較なので**左の`NULL`は誰とも一致せず残る** |
| `EXCEPT` | **2件** | Laptop, Mouse | 左右の`NULL`を同じ値として扱い、打ち消し合う |

```sql
-- NOT EXISTS：3件。NULL が残る
SELECT p.product_name
FROM products_tmp p
WHERE NOT EXISTS (SELECT 1 FROM categories_tmp c WHERE c.category_name = p.product_name)
ORDER BY p.product_name;
```

`NOT EXISTS`で`EXCEPT`と揃えたいなら、`=`ではなく**`IS NOT DISTINCT FROM`**（`NULL`同士を等しいとみなす比較）を使います。

```sql
SELECT p.product_name
FROM products_tmp p
WHERE NOT EXISTS (
	SELECT 1 FROM categories_tmp c
	WHERE c.category_name IS NOT DISTINCT FROM p.product_name
)
ORDER BY p.product_name;   -- 2件。EXCEPT と同じ
```

> ⚠️ **`NOT IN`の右側が`NULL`を含みうるなら、`NOT IN`は使わない。** 「0件のはずがないのに0件」はこれを疑ってください。
>
> ⚠️ **`NOT EXISTS`は`NOT IN`の安全な代替だが、`EXCEPT`と同義ではない。** 左側にも`NULL`がありうるなら、上の表のどれが欲しい結果かを決めてから選んでください。

## 4. 実務での使いどころ

### 4-1. UNION ALL：横持ちを縦持ちに変換する

1行に複数の数量が並んだ表を、「種別」列を持つ縦長の形に変えます。集計やグラフ描画の前処理として頻出です。

```sql
CREATE TABLE stats_tmp (product_name TEXT, stock_qty INT, order_qty INT);
INSERT INTO stats_tmp VALUES ('Laptop', 60, 4), ('Mouse', 20, 1);

SELECT product_name, 'Stock' AS source, stock_qty AS quantity FROM stats_tmp
UNION ALL
SELECT product_name, 'Order',           order_qty            FROM stats_tmp
ORDER BY product_name, source;
```

```
 product_name | source | quantity
--------------+--------+----------
 Laptop       | Order  |        4
 Laptop       | Stock  |       60
 Mouse        | Order  |        1
 Mouse        | Stock  |       20
(4 rows)
```

`'Stock'`／`'Order'`のような**固定値の列を足して行の出自を持たせる**のが定石です。ここで`UNION`を使ってはいけません。在庫と注文はたまたま数量が一致しても別の行だからです。

同じ形をした月次テーブル（`sales_202601`, `sales_202602`, …）を1本にまとめるのも`UNION ALL`の仕事です。

### 4-2. EXCEPT：新旧データの突合

**`EXCEPT`の実務での一番の使い道がこれです。** システム移行やバッチ再実行の後、移行元と移行先が一致しているかを確認します。

```sql
CREATE TABLE orders_old (order_id INT, amount NUMERIC);
INSERT INTO orders_old VALUES (1, 1000), (2, 2000), (3, 3000), (4, 4000);

CREATE TABLE orders_new (order_id INT, amount NUMERIC);
INSERT INTO orders_new VALUES (1, 1000), (2, 2500), (3, 3000), (5, 5000);
```

```sql
-- 移行元にあって移行先にない
SELECT * FROM orders_old EXCEPT SELECT * FROM orders_new ORDER BY order_id;

-- 移行先にあって移行元にない
SELECT * FROM orders_new EXCEPT SELECT * FROM orders_old ORDER BY order_id;
```

**両方が0件で、はじめて「一致」と言えます。** 片方向だけでは、移行先に余計な行が増えていても気づけません。

1本のクエリで見たいなら、どちら側かのラベルを付けて縦に積みます。

```sql
(SELECT '移行元のみ' AS side, * FROM orders_old
 EXCEPT ALL
 SELECT '移行元のみ',        * FROM orders_new)
UNION ALL
(SELECT '移行先のみ' AS side, * FROM orders_new
 EXCEPT ALL
 SELECT '移行先のみ',        * FROM orders_old)
ORDER BY order_id, side;
```

```
    side    | order_id | amount
------------+----------+--------
 移行元のみ |        2 |   2000
 移行先のみ |        2 |   2500
 移行元のみ |        4 |   4000
 移行先のみ |        5 |   5000
(4 rows)
```

`order_id = 2` は金額だけが変わった行、`4`は消えた行、`5`は増えた行だと読み取れます。

> [!note]- `EXCEPT ALL` とは
> `EXCEPT`が重複を排除するのに対し、`EXCEPT ALL`は**重複の個数で引き算**します。左に`'A'`が3行、右に1行なら、結果は`'A'`が2行です。突合では「同じ行が何行あるか」まで一致してほしいので、`EXCEPT ALL`のほうが厳密です。`INTERSECT ALL`も同様にあります。

### 4-3. VALUES を片側に置く：マスタに無い値を探す

集合演算子がつなぐのは`SELECT`の結果なので、**`VALUES`で書き下した値の並びも片側に置けます。** 取り込みデータの検証で使います。

```sql
SELECT * FROM (VALUES ('Laptop'), ('Tablet'), ('Mouse'), ('Keyboard')) AS t(name)
EXCEPT
SELECT product_name FROM products_tmp
ORDER BY name;
```

```
   name
----------
 Keyboard
 Tablet
(2 rows)
```

`'Tablet'`と`'Keyboard'`がマスタに未登録だと分かります。

### 4-4. EXCEPT：全称命題（すべて〜である）を解く

集合演算子は「否定」を表現するのが得意です。これを利用して、**「メンバー全員が〇〇であるチーム」**のような、集約関数で書くと複雑になるクエリを簡潔に書けます。

「全員が待機」を直接書くのは難しいので、**「全体」から「待機でない人がいるチーム」を引きます**。

```sql
WITH teams (member, team_id, status) AS (
	VALUES
		('ジョー', 1, '待機'), ('ケン', 1, '出動中'), ('ミック', 1, '待機'),
		('カレン', 2, '出動中'), ('キース', 2, '休暇'),
		('ジャン', 3, '待機'), ('ハート', 3, '待機'), ('ディック', 3, '待機'),
		('ベス', 4, '待機'),
		('アレン', 5, '出動中'), ('ロバート', 5, '休暇'), ('ケーガン', 5, '待機')
)
-- 全チーム
SELECT team_id FROM teams
EXCEPT
-- 待機じゃないメンバーがいるチーム
SELECT team_id FROM teams WHERE status <> '待機'
ORDER BY team_id;
```

```
 team_id
---------
       3
       4
(2 rows)
```

## 5. パフォーマンス：既定は UNION ALL

`UNION` / `INTERSECT` / `EXCEPT` は、**重複を排除するために並べ替え（またはハッシュ）を行います**。行数が多いとここが効いてきます。

**重複が起きないと分かっている、あるいは重複しても構わないなら`UNION ALL`を使ってください。** `UNION ALL`は結果を単に連結するだけなので、この処理が丸ごと不要になります。

逆に言えば、`UNION`を選ぶのは「重複が起きうる**うえに**排除したい」場合だけです。「なんとなく`UNION`」は避けます。

> 🐘 `INTERSECT` / `EXCEPT` に`ALL`を付けても、重複の個数を数える必要があるため`UNION ALL`ほど安くはなりません。

> [!note]- インデックスは効かないのか
> 集合演算子は**それぞれの枝を実行し終えてから**結果同士を突き合わせます（PostgreSQLの実行計画では`HashSetOp`や`SetOp`として現れます）。したがってインデックスが効くのは**枝の内側の`WHERE`や`JOIN`まで**で、突き合わせ自体には効きません。枝を`WHERE`で早めに絞ることが、集合演算の高速化としては一番効きます。実行計画の読み方は17章で扱います。

## 6. まとめ：JOIN と集合演算子の使い分け

| 項目 | JOIN（結合） | 集合演算子（UNION, etc.） |
| :--- | :--- | :--- |
| **結合方向** | **横**（列が増える） | **縦**（行が増える／減る） |
| **つなぐもの** | テーブル同士 | `SELECT`の結果同士 |
| **列の制約** | 自由 | **列数が一致し、型が互換であること** |
| **NULLの比較** | 結合されない（`UNKNOWN`） | **一致とみなす** |
| **主な用途** | 属性の追加（名前と価格を紐付ける等） | データの統合・比較（新旧の突合等） |
| **計算負荷** | 結合キーのインデックスに依存 | 重複排除（並べ替え／ハッシュ）による負荷 |

## 7. 補足：JOIN による集合演算の代用

`EXCEPT`／`INTERSECT`が使えない環境（MySQL 8.0.30以前など）や、**除外したうえで右側の列も見たい**場合は、`JOIN`で似たことができます。

```sql
-- EXCEPT（差集合）を LEFT JOIN で代用する
SELECT p.product_name
FROM products_tmp p
LEFT JOIN categories_tmp c ON p.product_name = c.category_name
WHERE c.category_name IS NULL   -- 結合できなかった行だけを残す
ORDER BY p.product_name;
```

```
 product_name
--------------
 Laptop
 Mouse

(3 rows)
```

> ⚠️ **これは`EXCEPT`と同じ結果ではありません。** `EXCEPT`は2行、この`LEFT JOIN`版は**3行**です。差の1行は`NULL`。`ON`句の`=`が`NULL`同士を結合しないため、`products_tmp`の`NULL`行が「相手が無かった行」として残ってしまいます（→ §3-1）。

#### 代用を EXCEPT に揃えるには2つ直す

`ON`を`IS NOT DISTINCT FROM`に変えるだけでは**直りません**。`NULL`同士は結合されるようになりますが、結合できた相手の`category_name`も`NULL`なので、`WHERE c.category_name IS NULL`が**結合できた行まで拾ってしまう**からです（依然3行）。

「結合できなかったか」を判定する列は、**`NULL`にならない列**でなければなりません。主キーを使うか、無ければ目印の列を足します。

```sql
SELECT p.product_name
FROM products_tmp p
LEFT JOIN (SELECT category_name, 1 AS matched FROM categories_tmp) c
	ON p.product_name IS NOT DISTINCT FROM c.category_name   -- ① NULL 同士を結合する
WHERE c.matched IS NULL                                      -- ② NULL にならない列で判定する
ORDER BY p.product_name;
```

```
 product_name
--------------
 Laptop
 Mouse
(2 rows)
```

> ⚠️ **`LEFT JOIN` + `WHERE 〜 IS NULL` の代用は、判定に使う列が`NULL`許容だと壊れます。** ②は`NULL`を含む列に限らず、この書き方そのものの落とし穴です。判定には必ず`NULL`にならない列を選んでください。

代用が`EXCEPT`より優れる点は、**右側の列を結果に出せる**ことです。「BになかったAの行」だけでなく「Bにあった場合はその値も」を1本で取りたいなら`LEFT JOIN`を選びます。
