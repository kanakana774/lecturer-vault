# SQL研修 トピック網羅チェックリスト（実務基準）

> 更新: 2026-08-21（作成: 2026-08-12） / 目的: **実務で使うかどうか**を判定基準に、現行教材のトピックの漏れを洗い出す
> 判定の物差し: ①[[★常駐先の想定業務★]]（業務システム系＝抽出・加工・集計／View・ストアド／夜間バッチ／帳票／障害調査／データ移行／チューニング） ②[[★SQLの現場で求められる人材想定★]] ③**移植可能か**（配属先DBは不定。製品固有の名前は忘れてよく、原理は残る → [[00_見直しの進め方]] 原則5）
> 使い方: 各項目を実物で点検 → チェックを付け、**幹／ハッチ(a)／ハッチ(b)／入れない**を末尾の記録欄に残す
> **「入れる／入れない」の二値では止めない。** 入れると決めたら、原理を導出させる（幹）のか、暗記対象と明示する（ハッチ(a)）のか、導出についてこれない人向けのパターン（ハッチ(b)）なのかまで決める

## 0. 前提：現状はかなり網羅されている

漏れの指摘に入る前に、**すでに厚い**ところを確認しておく（重複して足さないため）。

DDL・制約・データ型・正規化・マスタ/トラン／CRUD・演算子・NULL・LIKE（ILIKE・エスケープ）・BETWEENの半開区間・LIMIT/OFFSETのタイブレーク／文字列・日付関数・`||`と`CONCAT`のNULL差・不可視空白／CASE式（WHEN順序・シンプルCASEとNULL・SET句のELSE省略）／集約・GROUP BY・HAVING・`COUNT(*)`と`COUNT(列)`・整数除算・論理実行順・年月キーの作り方／JOIN全種・ON句とWHERE句・非等価結合（適用期間）・LEFT JOINを殺すINNER JOIN・行の増殖と集計不整合・ER図からの経路選択／集合演算子／サブクエリ（非相関・相関・EXISTS・スカラ）・IN と EXISTS・書き換え／ウィンドウ関数・CTE・view・sequence／PL/pgSQL 全5章（改訂版。トリガー・動的SQLを含む）／トランザクション・ACID・分離レベル・MVCC・`FOR UPDATE`・デッドロック・ロック調査／index・EXPLAIN・スキャン方式・結合アルゴリズム・効かない落とし穴・統計情報／psqlチートシート／実務想定問題（障害調査・データ移行・夜間バッチ・整合性チェック・帳票）。

**とくに 01〜07章の「追加問題」（罠ベース）は実務価値が高い。** 以下の指摘は、この水準を他の章にも広げるという性格のものが多い。

> **ただし「網羅している」＝「二層になっている」ではない。** 上記のほとんどは幹（原理）としては存在するが、**ハッチ(b)（導出についてこれない人向けのパターン提示）は一つも無い**。→ [[★SQLの現場で求められる人材想定★]] §1「二層で見た状態」

## A. 優先度【高】— 実務で必ず触るのに、講義に無い

### A-1. 更新系SQLの実務パターンが講義に存在しない

現行の CRUD 講義（[[02_CRUDについて]]）は単一テーブルの `INSERT` / `UPDATE` / `DELETE` で終わっている。実務のタスク例「条件に合致する顧客情報の一括更新」「システム間データ変換・登録処理」で使うのは全部この先。

**この項目は幹とハッチ(a)が混ざっているので分けて扱う。** 「なぜ複数テーブルを参照した更新が必要になるか」は移植可能な**幹**。個々の構文は製品差があるので**ハッチ(a)**。

| 構文 | 移植可能性 | 層 |
|---|---|---|
| `INSERT ... SELECT` | **標準SQL。どのDBでも通る** | 幹に近い |
| `CREATE TABLE AS SELECT` | **標準SQL** | 幹に近い |
| `UPDATE ... FROM` | **PostgreSQL方言。** 標準は `MERGE`、Oracleは別構文 | ハッチ(a) |
| `DELETE ... USING` | PostgreSQL方言 | ハッチ(a) |
| `RETURNING` | PostgreSQL方言（Oracleは `RETURNING INTO`） | ハッチ(a) |
| UPSERT `INSERT ... ON CONFLICT` | PostgreSQL方言。標準は `MERGE` | ハッチ(a) |
| `CREATE TEMP TABLE` | 概念は共通、構文に差 | ハッチ(a) |

- [ ] **`INSERT ... SELECT`** — 講義に0件。データ移行・作業退避・サマリテーブル作成の基本形
- [ ] **`UPDATE ... FROM`（結合更新）** — 講義に0件。**なのに [[業務システムを意識した問題_回答付]] の問題3（顧客ランク一括付与）で書かせている**＝教えずに出題している状態（→ [[00_見直しの進め方]] 原則6「先出し禁止」に違反している）
- [ ] **`DELETE ... USING`（結合削除）** — 0件
- [ ] **`CREATE TABLE AS SELECT` / `CREATE TEMP TABLE`** — 講義に0件。「消す前に退避」「バッチの中間結果」の定番。破壊的操作の作法としても効く（A-7 と直結）
- [ ] **`RETURNING`** — 素のSQLとしては無し（[[12-2_変数とSQLの実行]] の PL/pgSQL 文脈のみ）
- [ ] **UPSERT `INSERT ... ON CONFLICT`** — PL/pgSQL章にしかない。素のSQLとして未紹介。マスタ同期・再実行可能バッチの定番

→ 置き場案: `01_講義資料/03_更新系SQLの実務パターン.md` を新設（02章と11章の間）。演習は `02_問題/03_UPDATE文について` の追加問題に寄せる手もある。

### A-2. `SELECT DISTINCT` を正面から扱った節が無い

`COUNT(DISTINCT 列)`（[[07_集約関数]]）と解答例中の使用だけで、**講義本編・用語集ともに `SELECT DISTINCT` の節が無い**。標準SQLで完全に移植可能。

- [ ] 現場で最初に覚え、かつ最初に誤用する構文（「重複が出たからDISTINCTで消す」で原因を隠す）。[[08_補足_結合]] §6（行の増殖）と**対で**教えると、なぜ増えたかを考える癖に繋がる＝**幹**

### A-3. 「無い方を探す」＝アンチジョインの定型化と `NOT IN` の罠

障害調査（孤児レコード検出・件数突合）の中核だが、整理された形で存在しない。**3通り全部標準SQLで、純度の高い幹。**

- [ ] **`NOT EXISTS` / `LEFT JOIN ... WHERE 右.PK IS NULL` / `EXCEPT` の3通り**を並べた節が無い（`LEFT JOIN`＋`IS NULL` は [[08_補足_結合]] に1箇所出てくるだけ、`EXCEPT` は [[09_集合演算子]] にあるが「差分を出す道具」としての実務接続が薄い）
- [ ] **`NOT IN` + サブクエリ + NULL で結果が全件消える罠** — 記述0件。[[02_演算子]] は `NOT IN (...)` を「`<>` の AND と等価」と説明して終わっており、[[10_サブクエリ]] の IN/EXISTS 比較も性能の話に寄っている。**実務で最も痛く、最も気づきにくいバグの一つ**
- [ ] **この罠は三値論理から導出できる**ので、暗記させず導かせる（幹）。**同時にハッチ(b)としてもパターンを置く**（「`NOT IN` ＋ サブクエリ ＋ NULL は全件消える → `NOT EXISTS` に書き換える」）。どちらか一方ではない

### A-4. 数値関数と丸めの節が無い

[[04_関数]] は「文字列関数／日付・時刻関数／汎用関数」の3本立てで、**数値関数の節が存在しない**。

- [ ] `ROUND` / `TRUNC` / `CEIL` / `FLOOR` — **どのDBにもある。移植可能**
- [ ] `ROUND(値, 桁数)` が `numeric` にしか使えないこと、`::numeric` へのキャスト — **PostgreSQL固有。導出できないのでハッチ(a)**
- [ ] 消費税・按分の丸め — 業務ルールなので移植可能
- [ ] [[01_データ型]] は「金額に FLOAT を使うな」と明記できているので、**その受け皿が関数側に無い**状態。帳票・金額計算は「1円の誤差も許されない」領域（[[★SQLの現場で求められる人材想定★]] #2）
- [ ] 整数除算の罠自体は [[07_group byと集計関数]] 問題11でカバー済み＝**演習だけ先にある**

### A-5. 月初・月末の計算（**優先度を下げた**）

**2026-08-21 に評価を見直した。** 当初は「`date_trunc` が0件」を欠落として挙げていたが、**移植可能性の物差しを入れると判定が逆転する。**

| | 移植可能性 | 層 |
|---|---|---|
| **半開区間**（`>= 月初 AND < 翌月初`） | **どのDBでも通る考え方** | **幹。ここが本体** |
| `TO_CHAR(日付,'YYYY-MM')` | **Oracle でもほぼそのまま通る** | 現状の教え方のままでよい（**加点材料**） |
| `date_trunc` | **PostgreSQL固有名**（Oracleは `TRUNC(date,'MM')`） | 🐘 ハッチ(a) |

- [ ] **半開区間を幹として立てる。** [[06_SELECT文（特殊な演算子）]] 問題14で扱っているので**接続するだけ**
- [ ] `date_trunc` は🐘印を付けてハッチ(a)に置く。「文字列キーのままでは期間比較・前月との差・日付型で返す帳票で詰まる」のは事実だが、**それは半開区間で解ける**
- [ ] 月末の作り方（`+ INTERVAL '1 month' - INTERVAL '1 day'`）も方言差があるので、方言対応表（B-3）に寄せる

### A-6. 既存DBの構造をSQLで調べる手段（**優先度を上げた**）

**配属先DBが不定なのが常態**なので、ここは最優先級。保守・改修案件の初日にやるのは「テーブル定義・制約・外部キー・インデックスを調べる」。

| | 移植可能性 | 層 |
|---|---|---|
| `information_schema.columns` / `.table_constraints` | **標準SQL。Oracle / SQL Server / MySQL でも使える** | **幹** |
| `pg_catalog` / `pg_indexes` | PostgreSQL固有 | 🐘 ハッチ(a) |
| psql の `\d` 系 | **psql 専用。現場の道具（A5M2 / DBeaver / SQL Developer / SSMS）では使えない** | 参考程度 |

- [ ] `information_schema` / `pg_catalog` が**0件**。`\d` 系は [[99_補足_psqlコマンドチートシート]] にあるが psql 専用
- [ ] **「メタデータもテーブルである」が幹。** SELECT で調べられると分かれば、製品ごとのカタログ名はハッチ(a)で足りる
- [ ] インデックス一覧だけは製品ごとに違う（`pg_indexes` / Oracle `USER_INDEXES` / SQL Server `sys.indexes`）→ 方言対応表（B-3）に寄せる

### A-7. 書いたSQLを自分で検証する作法が講義に無い（構文ではなく手順の漏れ）

[[★SQLの現場で求められる人材想定★]] §3-1 で追加。**構文の網羅では出てこない種類の漏れ**なので、この章の他項目とは性格が違う。**2026-08-21 に総括の順位内（1位と同着）へ移した。**

- [ ] 「更新前に同じ `WHERE` で `SELECT` して件数を見る → `BEGIN` で囲む → 件数を照合して `COMMIT`」という作法が、**実務想定問題の解説の中だけ**に存在する。[[業務システムを意識した問題_回答付]] 問題3の講師向け解説に「この『事前検証』プロセスを**研修で徹底させます**」と書いてあるが、それを教える教材が無い
- [ ] 実務想定問題は最後にやる発展問題なので、**そこまで到達しない研修生には一度も伝わらない**
- [ ] **完全に製品非依存で、1ページで足りる。** 移植可能性の物差しでは全項目中で最強。合否判定をしない方針とも噛み合う（渡すのは作法であって採点対象ではない）
- [ ] 置き場案は `01_講義資料/00_SQLを検証する.md`（[[00_SQLを書く時の注意]] の隣＝書き方の作法と検証の作法の対）。A-1 の `CREATE TABLE AS SELECT`（退避）と [[15-1_導入_トランザクションとACID]] に接続する

## B. 優先度【中】— あると配属後の立ち上がりが変わる

### B-1. 既存の長いSQLを「読む」演習が無い

- [ ] [[★常駐先の想定業務★]] に「新規開発よりも保守・改修・運用対応が中心」「既存SQLの解析・修正・チューニングの比率が高い」と書いてあるのに、**演習は全部「書く」側**
- [ ] 土台の資料（[[07_補足_groupByの論理実行順]]・[[10_補足_相関サブクエリの読み書き]]）は揃っているので、「100行のSQLを渡して日本語で説明させる／条件を1つ足させる／なぜこの結果になるか説明させる」型の演習を作る余地がある
- [ ] **合否判定をしない方針と相性が良い。** 採点しづらいので、逆に「一度解かせる」形に向く

### B-2. 権限とロール（`GRANT` / `REVOKE`）

- [ ] 教材中の出現は旧「SQL学習トピックの選定」（2026-08-20 に廃止）の「ステージ7＝絶対やらない」の1件のみ
- [ ] ただし現場では「参照権限しかない」「本番はSELECTのみ」「見えないのは権限のせい」に**必ず**当たる。設計として教える必要はなく、**トラブルの語彙として15分**でよい
- [ ] 権限という概念自体は全DB共通なので移植可能。原則4の「気づいて報告する」に該当

### B-3. Oracle / SQL Server の方言差 — **実質【高】。優先度を上げた**

**2026-08-21 に根拠を差し替えた。** 当初は「Oracleが主流だから」「翻訳表なので安い」という理由だったが、**配属先DBが不定なのが常態**だから必須、という設計上の理由に変わった。**ハッチ(a) の典型**（`NVL`↔`COALESCE` は原理から導けない）で、幹とセットで全員に渡すもの。

- [ ] [[01_データ型]] に「他RDBMSでの類似型」列はある＝**型だけは対応済み**。関数・構文の対応表が無い
- [ ] 対象: `NVL`↔`COALESCE`、`DECODE`↔`CASE`、`SYSDATE`↔`NOW()`、`ROWNUM`/`FETCH FIRST`↔`LIMIT`、`(+)`↔`OUTER JOIN`、`TO_DATE` の書式、`DUAL`、文字列連結、`SERIAL`↔`IDENTITY`、月末の作り方（A-5）、インデックス一覧の調べ方（A-6）
- [ ] **1ページの翻訳表。** 新規に教えるのではなく既存知識の対応付けなので工数は小さい

### B-4. マテリアライズドビュー

- [ ] `CREATE MATERIALIZED VIEW` は0件（CTEの内部マテリアライズの言及が [[99_補足_CTE（共通テーブル式）]] に1件だけ）
- [ ] [[99_補足_viewについて]] は更新可能ビューまで扱えているので、**帳票・集計スナップショットとしてのマテビューと `REFRESH`** を足すだけ。夜間バッチで集計テーブルを作る話とも繋がる
- [ ] Oracle にもあるが `REFRESH` の作法が違う＝製品差あり。**優先度は据え置き〜降格**

### B-5. ~~トリガー・カーソル・動的SQL が PL/pgSQL 詳細版にしか無い~~ → **解消済み**

- [x] ~~`12-7_高度なトピック`（詳細版）のみ。**簡略版（12-1〜12-6）で回すと未接触**になる~~
  → **2026-08-21 確認: 解消済み。** 12章は改訂され、現行の完成品に [[12-5_トリガーと動的SQL]] がある（旧簡略版 12-1〜12-6 は温存されているだけで現行ではない）。指摘が参照していた `12-7_高度なトピック` は**存在しない**
- [ ] **残る論点は旧版の並存**。`01_講義資料/12_PLpgSQL/` に `PLpgSQL簡略版/`（旧6本）と `PLpgSQL簡略版_改訂/`（現行5本）が並んでいる。どちらが現行か資料側から読み取れないので、旧版の扱いを決める必要がある（→ D-3）
- [ ] トリガーは「知らないと調査で詰む」種類の知識（更新した覚えのない列が変わる／INSERTしたら別テーブルにも入る）。**トリガー自体は全DBにある**ので移植可能。改訂版で幹として扱えているか点検する

### B-6. 文字列→日付・数値の変換失敗とクレンジング

- [ ] `MyWork/01_業務概要.md` §8 に「CSV取り込みは TEXTステージング → `TO_DATE` 型変換 → `TRIM`/`NULLIF` クレンジングの2段構え（移行実務のミニチュア）」と**方針として書き**、電子カルテDWHのDDLでは実践しているのに、**講義側に受け皿が無い**
- [ ] `TO_DATE` の書式ずれ・全角空白・`NULLIF(列,'')` は、データ移行タスクで最初に踏む
- [ ] **`TO_DATE` は Oracle と共通、`NULLIF`/`TRIM` は標準SQL。移植性が高い**ので、移植可能性の物差しでは加点

### B-7. `NULLS FIRST` / `NULLS LAST`

- [ ] ほぼ0件。`ORDER BY` で NULL がどこに来るか（PostgreSQL・Oracle は ASC で最後、**SQL Server は逆**）は帳票の並び順で当たる。**1〜2行で済む**ので [[02_CRUDについて]] の ORDER BY の節に追記
- [ ] **導出できないのでハッチ(a)。** 製品差の代表例なので、むしろ方言対応表（B-3）の教材として使える

## C. 優先度【低】／要判断

- [ ] **`pg_dump` / リストア** — [[99_補足_psqlコマンドチートシート]] に列挙のみ。「破壊的操作の前に退避」の作法としては A-1 の `CREATE TABLE AS SELECT` でも代替できる。**製品固有度が高いので降格**
- [ ] **VACUUM / テーブル膨れ** — MVCCの代償として [[15-2_実践_ロックとMVCC]] に、運用面は `03_詳細版/17_indexと実行計画/17-4_運用とチューニング.md` にある。**原則4の「気づいて報告する」に該当**するので、語彙として一言入れる方向
- [ ] **パーティショニング・行レベルセキュリティ** — 保守で「既にそうなっている」に出会う可能性はあるが、研修範囲としては過剰。**入れない**
- [x] ~~**再帰CTE（階層展開）** — 「発展問題ではCTE禁止」の方針と衝突するので位置づけの判断が必要~~
  → **2026-08-21 解消。** 禁止の正体は「先出し禁止」（講義していない構文を課題で求めない）だった。**範囲そのものの禁止ではない**ので衝突は消えた（→ [[00_見直しの進め方]] 原則6）。CTEを講義した後なら使ってよい

## D. トピックの漏れではないが、あわせて点検したいこと

### D-1. 「追加課題」が 08・10 に無い（章間の非対称）

追加課題（罠ベースの実務直結演習）があるのは **01・02・03・04・06・07・08 のみ**。

> **2026-08-19 の書式統一で、番号の呼び方が変わりました。** 「追加問題N」は廃止し、ファイル内の通し番号（`## 問題 N:`）に統一。必須と任意の境界は `## 追加課題（ここから先は任意）` の行で示します（→ [[_問題・解答ページのフォーマット]] §4）。
