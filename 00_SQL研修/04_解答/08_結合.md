## 問題 1: 会員ランクの表示（未設定は NoRank）
- **目的**: `LEFT OUTER JOIN` で相手が見つからない行も残し、`COALESCE` で NULL を既定値に置き換える。

### 問題:
各顧客の名前と、所属している会員ランクの名前をCUSTOMER_IDの昇順取得してください。
ただし、会員ランクが未設定のユーザーは「NoRank」と表示するようにしてください。

### 解答:
```sql
-- 案1: COALESCE で NULL を 'NoRank' に置き換える
SELECT
	C.CUSTOMER_ID,
	C.NAME AS CUSTOMER_NAME,
	COALESCE(M.RANK_NAME, 'NoRank') AS RANK_NAME
FROM
	CUSTOMERS C
	LEFT OUTER JOIN MEMBERSHIPS M ON C.MEMBERSHIP_ID = M.MEMBERSHIP_ID
ORDER BY
	C.CUSTOMER_ID;
```
```sql
-- 案2: CASE 式で書く
SELECT
   c.customer_id,
   name 顧客名,
   CASE
      WHEN rank_name IS NULL THEN 'NoRank'
      ELSE rank_name
   END 会員ランク名
FROM
   customers c
   LEFT OUTER JOIN memberships m ON c.membership_id = m.membership_id
ORDER BY
   c.customer_id;
```

### 解説:
`INNER JOIN` にすると会員ランク未設定の Charlie が結果から消えてしまいます。「未設定でも表示する」という指示があるので外部結合が必要です。

> **⚠️ 講師向けの注意**: 全体的に、内部結合ですべきか外部結合ですべきか問題から読み取りづらかったため、その辺の判定を緩くしてる。

## 問題 2: 商品とカテゴリ名の一覧
- **目的**: 商品テーブルとカテゴリテーブルを結合し、外部キーの値ではなく名前で表示する。

### 問題:
全ての商品について、商品名とカテゴリ名を取得してください。

### 解答:
```sql
SELECT
	P.PRODUCT_ID,
	P.PRODUCT_NAME,
	C.CATEGORY_NAME
FROM
	PRODUCTS P
	LEFT OUTER JOIN CATEGORIES C ON P.CATEGORY_ID = C.CATEGORY_ID;
```

### 解説:
「全ての商品について」なので、カテゴリが未設定の商品が将来現れても落ちないように `LEFT OUTER JOIN` にしています。今のデータでは全商品にカテゴリが付いているため `INNER JOIN` でも同じ13行になります。

## 問題 3: 注文と顧客名
- **目的**: `INNER JOIN` で2つのテーブルを結び、`AS` で列に別名を付ける。

### 問題:
すべての注文について、注文ID・注文日・顧客名を取得してください。
ただし、顧客名はcustomer_nameという別名で表示してください。

### 解答:
```sql
SELECT
	O.ORDER_ID,
	O.ORDER_DATE,
	C.NAME AS CUSTOMER_NAME
FROM
	ORDERS O
	INNER JOIN CUSTOMERS C ON O.CUSTOMER_ID = C.CUSTOMER_ID;
```

## 問題 4: 注文明細ごとの合計金額
- **目的**: 結合した相手テーブルの列を使って計算列（数量 × 単価）を作る。

### 問題:
各注文明細ごとに、注文ID・商品名・数量・単価・商品ごとの合計金額を取得してください。

### 解答:
```sql
SELECT
	OI.ORDER_ID,
	P.PRODUCT_NAME,
	OI.QUANTITY,
	P.PRICE,
	(OI.QUANTITY * P.PRICE) AS TOTAL_AMOUNT
FROM
	ORDERITEMS OI
	INNER JOIN PRODUCTS P ON OI.PRODUCT_ID = P.PRODUCT_ID;
```

### 解説:
単価は `orderitems` ではなく `products` 側にあるため、結合しないと金額が計算できません。

## 問題 5: 注文ごとの支払金額と配送状況
- **目的**: 複数テーブルの外部結合と集計を組み合わせ、`COALESCE` と `CASE` で未確定の状態を表示用の値に変換する。

### 問題:
すべての注文について、注文の配送状況毎の、注文ID・顧客名・支払金額・配送状況を取得してください。
支払金額にはpayment_amount、配送状況shipment_statusという別名をつけてください。
ただし、支払いをしていないユーザーの支払金額は0と表示するようにしてください。
また、配送が完了していないユーザーの配送状況はNotDeliveredと表示するようにしてください。具体的にはstatusがnullだったり、In Transit（輸送中）のものをNotDeliveredとしましょう。

### 解答:
```sql
SELECT
	ord.order_id,
	cu.name,
	ord.status,
	COALESCE(SUM(pa.amount), 0) AS payment_amount,
	CASE
		WHEN sh.status = 'Delivered' THEN sh.status
		ELSE 'NotDelivered'
	END AS shipment_status
FROM
	orders ord
	LEFT JOIN customers cu ON cu.customer_id = ord.customer_id
	LEFT JOIN shipments sh ON sh.order_id = ord.order_id
	LEFT JOIN payments pa ON pa.order_id = ord.order_id
GROUP BY
	ord.order_id,
	cu.customer_id,
	cu.name,
	sh.shipment_id,
	sh.status
ORDER BY
	ord.order_id;
```

### 解説:
1つの注文に支払いが複数ある（order_id = 5 は2件）ため `SUM()` でまとめます。支払いが1件も無い注文は `SUM()` が NULL を返すので `COALESCE(..., 0)` で 0 にします。
`GROUP BY` に `sh.shipment_id` を入れているのは「配送状況毎に」という指示のためです。1つの注文に配送が複数ある場合は行が分かれます。

## 問題 6: 顧客ごとの注文件数（0件も表示）
- **目的**: `LEFT JOIN` と `COUNT(相手の列)` を組み合わせて、該当が無い行を0件として数える。

### 問題:
すべての顧客について、顧客名と、その顧客が行った注文の総数を取得してください。注文が一度もない顧客も表示してください。
結果は顧客名で昇順に並べてください。

### 解答:
```sql
SELECT
	c.name AS customer_name,
	COUNT(o.order_id) AS total_orders
FROM
	Customers AS c
	LEFT JOIN Orders AS o ON c.customer_id = o.customer_id
GROUP BY
	c.customer_id, c.name
ORDER BY
	c.name;
```

### 解説:
`COUNT(*)` にすると、注文が無い顧客も外部結合で1行（相手が NULL の行）が残るため **1** と数えてしまいます。`COUNT(o.order_id)` は NULL を数えないので 0 になります。

## 問題 7: カテゴリ・商品・在庫倉庫の一覧
- **目的**: 3つ以上のテーブルを、内部結合と外部結合を混ぜてつなぐ。

### 問題:
すべての商品カテゴリについて、そのカテゴリに属する商品名、価格、および各商品の在庫がある倉庫名と在庫数を取得してください。
在庫がない商品も表示し、その場合は倉庫名と在庫数を NULL としてください。
結果はカテゴリ名、商品名で昇順に並べてください。

### 解答:
```sql
SELECT
	ca.category_name,
	p.product_name,
	p.price,
	w.warehouse_name,
	i.stock_quantity
FROM
	Categories AS ca
	JOIN Products AS p ON ca.category_id = p.category_id
	LEFT JOIN Inventory AS i ON p.product_id = i.product_id
	LEFT JOIN Warehouses AS w ON i.warehouse_id = w.warehouse_id
ORDER BY
	ca.category_name, p.product_name;
```

### 解説:
在庫が無い商品を残すために `Inventory` は `LEFT JOIN` にします。そのうえで `Warehouses` を `INNER JOIN` にしてしまうと、`i.warehouse_id` が NULL の行が消えて `LEFT JOIN Inventory` の意味が無くなるため、こちらも `LEFT JOIN` にします。
なお `Laptop` は東京・大阪の2倉庫に在庫があるため、商品13件に対して結果は14行になります。

## 問題 8: 倉庫ごとのスタッフ数と商品種類数
- **目的**: 1:n の結合が2つ重なると行数が掛け算に膨れることを理解し、`COUNT(DISTINCT)` で正しく数える。

### 問題:
倉庫ごとに、所属するスタッフの人数と、保管されている商品の種類数を集計してください。  
スタッフがいない倉庫や、商品がない倉庫も漏れなく表示してください。  
結果は、倉庫名（どこの倉庫にも所属してないレコードに関しては、所属倉庫なしとしてください）、スタッフ数、商品種類数の順に表示してください。

ヒント：倉庫とstaffは1:nで、倉庫と在庫も1:mで、結果がn×mに膨れてしまうので、集計に注意しましょう。

### 解答:
```sql
SELECT
	COALESCE(w.warehouse_name, '所属倉庫なし') AS warehouse_name,
	COUNT(DISTINCT s.staff_id) AS staff_count,
	COUNT(DISTINCT i.product_id) AS product_type_count
FROM
	warehouses w
	FULL OUTER JOIN staff s ON w.warehouse_id = s.warehouse_id
	FULL OUTER JOIN inventory i ON w.warehouse_id = i.warehouse_id
GROUP BY
	w.warehouse_id,
	w.warehouse_name
ORDER BY
	warehouse_name;
```

### 期待結果:
| warehouse_name | staff_count | product_type_count |
| :--- | ---: | ---: |
| Fukuoka Warehouse | 0 | 0 |
| Osaka Warehouse | 1 | 6 |
| Tokyo Warehouse | 1 | 8 |
| 所属倉庫なし | 1 | 0 |

### 解説:
staff と inventory を両方つなぐと、東京倉庫は「スタッフ1人 × 在庫8種類 = 8行」に膨れます。ここで `COUNT(s.staff_id)` と書くと 8 になってしまうため `COUNT(DISTINCT s.staff_id)` が必要です。
どの倉庫にも所属していないスタッフ（Heidi）を残すために `FULL OUTER JOIN` を使い、`w.warehouse_name` が NULL になるそのグループを `COALESCE` で「所属倉庫なし」と表示しています。

## 問題 9: 注文と配送状況の一覧
- **目的**: 対応するレコードが無い側を NULL のまま残す `LEFT JOIN` の使いどころを確認する。

### 問題:
すべての顧客について、顧客名、注文日、注文ステータス、およびその注文の配送状況（delivery_date, status）を取得してください。
配送がまだ行われていない注文（Shipments テーブルに該当するレコードがない注文）も表示し、その場合は配送に関する情報（shipped_date, delivery_date, status）を NULL としてください。
結果は顧客名、注文日で昇順に並べてください。

### 解答:
```sql
SELECT
	c.name AS customer_name,
	o.order_date,
	o.status AS order_status,
	s.shipped_date,
	s.delivery_date,
	s.status AS shipment_status
FROM
	Customers AS c
	JOIN Orders AS o ON c.customer_id = o.customer_id
	LEFT JOIN Shipments AS s ON o.order_id = s.order_id
ORDER BY
	c.name, o.order_date;
```

### 解説:
`Customers` と `Orders` は内部結合なので、注文が1件も無い顧客（Charlie・Grace）はこの結果には現れません。「すべての注文について配送情報を出す」問題であり、問題 6 とは残すべき側が違う点に注意してください。

## 問題 10: 商品ごとの平均レビュー評価
- **目的**: `LEFT JOIN` した相手を集計し、該当が1件も無い場合に平均が NULL になることを確認する。

### 問題:
すべての商品について、商品名と、その商品に投稿されたレビューの平均評価を取得してください。
レビューが一つも投稿されていない商品も表示し、その場合は平均評価を NULL としてください。
平均評価は小数点以下 2 桁まで表示してください。
結果は商品名で昇順に並べてください。

### 解答:
```sql
SELECT
	p.product_name,
	ROUND(AVG(r.rating), 2) AS average_rating
FROM
	Products AS p
	LEFT JOIN Reviews AS r ON p.product_id = r.product_id
GROUP BY
	p.product_id, p.product_name
ORDER BY
	p.product_name;
```

### 解説:
`AVG()` は NULL を無視するため、レビューが1件も無い商品は結果が NULL になります（`COUNT()` のように 0 にはなりません）。0 と表示したい場合は `COALESCE(ROUND(AVG(r.rating), 2), 0)` とします。
