# 問題ページ・解答ページのフォーマット

**【所有】個人（講師用）｜【種類】運用ルール｜【配布】しない**

---

## 原則：解答ページが正本。問題ページはそこから解答を抜いたもの

**解答ページに問題文も入れます。** 丸付けのときに問題ページと解答ページを行き来しなくて済むようにするためです。

```
解答ページ  =  問題文 ＋ 解答 ＋ 解説
問題ページ  =  解答ページから「### 解答:」以降を抜いたもの
```

**書くときは解答ページを先に完成させ、そこから削って問題ページを作ってください。** 逆順で作ると、問題文が二重管理になってズレます。

参考実装：[[00_SQL研修/04_解答/07_group byと集計関数|04_解答/07_group byと集計関数]]

---

## 1. 解答ページの型

````markdown
# NN章 演習 解答：タイトル

（前置き：実測環境・注意など。1〜3行）

---

## 問題 1: 短いタイトル
- **目的**: この問題で身につけること（1行）

### 問題:
（問題文。手順があれば番号付きで、SQLはコードブロックで）

**【問1】** 問いの本文
**【問2】** 問いの本文

### 解答:

**【問1】** 答え

**【問2】** 答え

### 解説:
（任意。なぜそうなるか。実測出力・落とし穴・関連節へのリンク）

---

## 問題 2: ...
````

### 各パーツの約束

| パーツ | 必須 | 書き方 |
| :--- | :---: | :--- |
| `## 問題 N: タイトル` | ● | **半角スペースは「問題」と数字の間に1つ**。タイトルは短く |
| `- **目的**:` | ● | **1行。**「〜を理解する」「〜を使えるようになる」 |
| `### 問題:` | ● | 問題文・手順・問い。**ここまでが問題ページに載る** |
| `### 解答:` | ● | **ここから下は問題ページに載せない** |
| `### 期待結果:` | | 任意。**実測**の出力。markdown表でよい。`### 解答:` の直後に置く |
| `### 解説:` | | 任意。**「なぜ」を書く場所。**答えそのものは `### 解答:` に書く |
| `---` | ● | 問題と問題の間に必ず入れる |

### 表記の約束

- 問いの番号は **`【問1】`**。`【問い1】` とは書かない
- 手順は `1.` `2.` の番号付きリスト。**SQLは必ずコードブロック**に入れる
- 実測出力は**言語指定なしのコードブロック**（` ``` ` のみ）に入れる
- 解答が複数の問いに分かれる場合、`### 解答:` の中でも **`**【問1】** 〜`** で対応させる
- **講師にだけ伝えたいこと**（引っかけ・時間配分・受講生には見せない補足）は**解答ページに書かない。** 講師カンペに書く

---

## 2. 問題ページの型

**解答ページから機械的に落とすだけです。**

````markdown
# NN章 演習：タイトル

（前置き）

---

## 問題 1: 短いタイトル
- **目的**: （解答ページと同じ1行）

### 問題:
（解答ページと同じ）

### 解答:
```sql
ここに解答を記入
```

---
````

- 見出しは解答ページと**同じ `### 解答:`**。中身を ```` ```sql ここに解答を記入``` ```` に差し替え、受講生がそこに書き込む
- 答えがSQLでない問い（説明・観察結果など）は、言語指定なしの ```` ```ここに解答を記入``` ```` にする
- `### 解説:` は問題ページに載せない

---

## 3. 準備セクション（章の先頭）

ハンズオンがある章は、問題1の前に置きます。

````markdown
## 準備

### 使用するテーブル
（どのテーブルを使うか。作成済みなら「NN章のものをそのまま使う」）

### （必要なら）この章だけの追加設定
（ALTER TABLE など。**撤去SQLも併記する**）

### リセットSQL
（値が分からなくなったときに初期状態へ戻すSQL）
````

**リセットSQLは必ず用意してください。** ハンズオンでデータが変わる章では、これが無いと受講生が詰まります。

---

## 4. 必須課題と追加課題の線引き

**問題番号はファイル内で通し番号にします。** 「本編」「追加課題」でセクションを分けて番号を1から振り直さないでください（`## 問題 3` が1ファイルに2つある状態になり、指し示せなくなります）。

そのうえで**どこまでが必須か**を示すために、境界に次の1ブロックを置きます。

````markdown
---

## 追加課題（ここから先は任意）

**問題 5 まで**が必須です。ここから先は、早く終わった人・もっと解きたい人向けです。

---

## 問題 6: 短いタイトル
````

- 見出しは `## 追加課題（ここから先は任意）` で固定。**問題ページと解答ページの両方に同じものを置く**
- 直後の1行で「問題 N まで」と必須の範囲を明示する。**線を動かすときはこの数字だけ直せばよい**
- 追加課題側の問題も、書式は必須課題と同じ（`## 問題 N:` ＋ `- **目的**:` ＋ `### 問題:` ＋ `### 解答:`）
- 線が要らない章（全部必須）は、このブロックごと置かない

## 5. チェックリスト

新しく問題・解答を作るとき、または既存を直すときに確認します。

- [ ] 解答ページに**問題文が入っている**
- [ ] 問題ページ＝解答ページから `### 解答:` 以降を抜いたものになっている（問題文が一字一句同じ）
- [ ] 問いの番号が `【問N】`（`【問い N】` になっていない）
- [ ] `## 問題 N: タイトル` の形式（`##問題N` や `## 問題N：` になっていない）
- [ ] 各問題に `- **目的**:` が1行ある
- [ ] 問題番号がファイル内で**通し**になっている（セクションごとに1から振り直していない）
- [ ] 追加課題がある章に `## 追加課題（ここから先は任意）` の線がある
- [ ] 講師向けの記述が解答ページに混ざっていない（→ カンペへ）
- [ ] ハンズオン章なら**リセットSQL**がある
- [ ] 掲載している出力が**実測**である（推測で書かない）
- [ ] 章をまたぐ参照は `[[ファイル名\|表示名]] §N-M` の形（§番号が実在するか確認）
