## 問題 1: 顧客名とメールアドレスを結合して表示する
- **目的**: `CONCAT()` 関数または `||` 演算子を使用して、複数の文字列を結合する方法を理解する。

### 問題:
`customers_mst` テーブルから、顧客の名前とメールアドレスを結合し、以下のような形式で表示してください。
カラムのエイリアス（別名）は `customer_contact` としてください。

**表示形式の例**: `佐藤 太郎 (sato.taro@example.com)`

### 解答:
```sql
SELECT
    CONCAT(customer_name, ' (', email, ')') AS customer_contact
FROM
    customers_mst;
```

**別解: `||` 演算子を使う**
```sql
SELECT
    customer_name || ' (' || email || ')' AS customer_contact
FROM
    customers_mst;
```

## 問題 2: 商品名の短縮形と大文字・小文字変換
- **目的**: `SUBSTRING()`, `UPPER()`, `LOWER()` 関数を使用して文字列を加工する方法を理解する。

### 問題:
`products_mst` テーブルから、以下の3つの形式で商品名を表示してください。

1. **short_name**: 商品名の最初の 3 文字
2. **upper_name**: 商品名を全て大文字に変換したもの
3. **lower_name**: 商品名を全て小文字に変換したもの

### 解答:
```sql
SELECT
    product_name,
    SUBSTRING(product_name FROM 1 FOR 3) AS short_name,
    UPPER(product_name) AS upper_name,
    LOWER(product_name) AS lower_name
FROM
    products_mst;
```

### 解説:
`SUBSTRING(列名 FROM 開始位置 FOR 文字数)` は標準SQLの書き方です。PostgreSQLでは `SUBSTR(列名, 開始位置, 文字数)` と書くことも可能です。

## 問題 3: 商品メモの空白を除去する
- **目的**: `TRIM()` 関数を使用して、文字列の両端の空白文字を除去する方法を理解する。

### 問題:
`products_mst` テーブルの `memo` 列について、もし前後に余分な空白が含まれていた場合にそれらを除去した結果を表示したいとします。
以下のカラムを表示するSQLを作成してください（対象は `memo` がNULLではない行のみ）。

1. **original_memo**: 元のメモ
2. **trimmed_memo**: 両端の空白を除去したメモ

※現在のデータには空白が含まれていないかもしれませんが、空白が含まれていると仮定してSQLを作成してください。

> **参考**: 動作を確認したい場合は、一時的に空白を含むデータをINSERTしてみると良いでしょう。**`BEGIN;` … `ROLLBACK;` で囲めば残りません。**
> 例: `INSERT INTO products_mst (..., memo) VALUES (..., '   空白あり   ');`

### 解答:
```sql
SELECT
    product_name,
    memo AS original_memo,
    TRIM(memo) AS trimmed_memo
FROM
    products_mst
WHERE
    memo IS NOT NULL;
```

## 問題 4: 現在の日付と時刻を取得し、特定の形式で表示する
- **目的**: `NOW()` で現在日時を取得し、`TO_CHAR()` で日付を任意の形式（文字列）に整形する方法を理解する。

### 問題:
以下の2つのカラムを表示するSQLを作成してください。

1. **current_datetime**: 現在のシステム日時そのまま
2. **formatted_datetime**: 現在日時を「YYYY 年 MM 月 DD 日 HH 時 MI 分 SS 秒」の形式（例: `2023 年 10 月 25 日 14 時 30 分 00 秒`）に整形したもの

### 解答:
```sql
SELECT
    NOW() AS current_datetime,
    TO_CHAR(NOW(), 'YYYY 年 MM 月 DD 日 HH24 時 MI 分 SS 秒') AS formatted_datetime;
```

### 解説:
`HH` だけだと12時間表記、`HH24` だと24時間表記になります。

## 問題 5: 注文日の翌週の同じ曜日を計算する
- **目的**: `INTERVAL` キーワードを使用して日付に期間を加算する方法を理解する。

### 問題:
`orders_trn` テーブルから、各注文の注文日(`order_date`)と、その **7 日後（翌週の同じ曜日）** の日付を計算して表示してください。
エイリアスは `next_week_date` としてください。

### 解答:
```sql
SELECT
    order_id,
    order_date,
    order_date + INTERVAL '7 days' AS next_week_date
FROM
    orders_trn;
```

### 解説:
PostgreSQLでは `+ 7` と整数を足すだけでも日付の加算ができますが、`INTERVAL '1 month'` や `INTERVAL '1 hour'` など柔軟に対応できる `INTERVAL` 構文を覚えるのが推奨されます。

## 問題 6: 顧客の登録月を抽出する

### 解答:

SELECT
    customer_name,

## 問題 8: 顧客メールアドレスのドメイン名抽出
- **目的**: 文字列関数を組み合わせて、特定のパターン（@より後ろ）を抽出する方法を理解する。

### 問題:
`customers_mst` テーブルから、各顧客のメールアドレスの **ドメイン名のみ** （@マークより後ろの部分）を抽出して表示してください。
（例: `sato.taro@example.com` → `example.com`）

### 解答:
```sql
SELECT
    customer_name,
    email,
    SUBSTRING(email FROM POSITION('@' IN email) + 1) AS email_domain
FROM
    customers_mst;
```

**別解: SPLIT_PART を使う**
```sql
SELECT
    customer_name,
    email,
    SPLIT_PART(email, '@', 2) AS email_domain
FROM
    customers_mst;
```

### 解説:
`SPLIT_PART(文字列, 区切り文字, 何番目)` は、「文字列を区切り文字で分割し、N番目の部分を取得する」という非常に便利な関数です。

## 問題 9: 商品名の文字長を取得する
- **目的**: `LENGTH()` または `CHAR_LENGTH()` 関数を使用して、文字列の長さを取得する方法を理解する。

### 問題:
`products_mst` テーブルから、商品名とその **文字数** を両方表示してください。

### 解答:
```sql
SELECT
    product_name,
    CHAR_LENGTH(product_name) AS product_name_length
    -- PostgreSQLでは LENGTH(product_name) でも文字数が返ります
FROM
    products_mst;
```

### 解説:
PostgreSQLの `LENGTH()` は文字数を返しますが、他のDB（MySQL等）ではバイト数を返すことがあるため、SQL標準である `CHAR_LENGTH()` を使うとより移植性が高くなります。

## 問題 10: NULL のメモを「メモなし」と表示する
- **目的**: `COALESCE()` 関数を使用して、NULL 値を別の値に置き換えて表示する方法を理解する。

### 問題:
`products_mst` テーブルから、商品名とメモを表示してください。
ただし、メモ(`memo`)が NULL の場合は、NULLの代わりに **'メモなし'** という文字列を表示してください。

### 解答:
```sql
SELECT
    product_name,
    COALESCE(memo, 'メモなし') AS display_memo
FROM
    products_mst;
```

### 解説:
`COALESCE(値1, 値2, ...)` は、引数を左から順に評価し、最初に見つかった「NULLではない値」を返します。レポート出力や画面表示用にNULLを空文字や特定のメッセージに変換する際によく利用されます。

## 問題 11: `||` と `CONCAT` は NULL の扱いが違う
- **目的**: 文字列連結における `||`（NULL が混ざると全体が NULL）と `CONCAT`（NULL を空文字として無視）の挙動差を実データで確認し、`COALESCE` で正しく制御できるようにする。

### 問題:
商品一覧の画面に「商品名（商品説明）」という形式の表示用文字列を出したいと考えています。

(1) `products_mst` テーブルから、`product_name` と `memo` に加えて、次の2つの列を **1つのSQL** で表示してください（`product_id` の昇順）。

- **label_pipe**: `||` 演算子で `商品名（説明）` の形に組み立てたもの
- **label_concat**: `CONCAT()` 関数で同じ形に組み立てたもの

(2) (1) の結果のうち `product_id = 2` の行で、`label_pipe` と `label_concat` がそれぞれどうなるかを確認し、なぜそうなるのかを説明してください。

(3) `memo` が未入力の商品では `商品名（説明未登録）` と表示されるように、`label_pipe` を修正してください。

> **ヒント**: 「（」「）」も連結する部品のひとつとして、文字列リテラルで挟み込みます。(3) は問題10で使った `COALESCE(列名, 代替値)` を連結の前に挟みます。

### 解答:
```sql
-- (1) || と CONCAT を並べて比較する
SELECT
    product_id,
    product_name,
    memo,
    product_name || '（' || memo || '）' AS label_pipe,
    CONCAT(product_name, '（', memo, '）') AS label_concat
FROM
    products_mst
ORDER BY
    product_id;

-- (3) COALESCE で既定値を与えてから連結する
SELECT
    product_id,
    product_name || '（' || COALESCE(memo, '説明未登録') || '）' AS label_pipe
FROM
    products_mst
ORDER BY
    product_id;
```

### 期待結果:
(1)（23件・抜粋）

| product_id | memo | label_pipe | label_concat |
| ---: | :--- | :--- | :--- |
| 1 | 高音質でノイズキャンセリング機能付き | ワイヤレスイヤホン（高音質でノイズキャンセリング機能付き） | ワイヤレスイヤホン（高音質でノイズキャンセリング機能付き） |
| 2 | **(NULL)** | **(NULL)** | SQL 入門（） |
| 6 | **(NULL)** | **(NULL)** | オーガニックコーヒー豆（） |

(3)（23件・抜粋）

| product_id | label_pipe |
| ---: | :--- |
| 1 | ワイヤレスイヤホン（高音質でノイズキャンセリング機能付き） |
| 2 | SQL 入門（説明未登録） |
| 6 | オーガニックコーヒー豆（説明未登録） |

### 解説:
`||` は連結する値に1つでも NULL が混ざると結果全体が NULL になるため、`label_pipe` では商品名まで消えてしまいます（`memo` が NULL なのは product_id = 2, 6, 11, 18, 20, 21, 22 の7件）。`CONCAT()` は NULL を空文字として扱うので、中身が空のカッコだけが残ります。どちらもそのまま画面に出せる値ではないので、表示用の文字列は (3) のように `COALESCE()` で既定値を与えてから連結します。

## 問題 12: 目に見えない空白を可視化する
- **目的**: 画面上は同じに見える文字列でも DB 上は別の値になりうることを、`CHAR_LENGTH` と `TRIM` と区切り記号による可視化で証明できるようにする。

### 問題:
`products_mst` には `国産はちみつ` という商品が2件（`product_id = 15` と `20`）あるように見えますが、`WHERE product_name = '国産はちみつ'` で検索すると1件しかヒットしません。

(1) この2件について、次の4つの列を表示して原因を突き止めてください。

- **raw**: 商品名を `[` と `]` で挟んだもの
- **raw_len**: 商品名の文字数
- **trimmed**: 商品名の前後の空白を除去し、`[` と `]` で挟んだもの
- **trimmed_len**: 空白を除去した後の文字数

(2) 全商品のうち、商品名の前後に余分な空白が入っている商品を抽出してください（`TRIM` した結果が元の値と異なる行）。

> **ヒント**: (1) で2件とも取り出すには、`WHERE` の条件側にも `TRIM()` を適用します。

### 解答:
```sql
-- (1) 2件の商品名を可視化して比較する
SELECT
    product_id,
    '[' || product_name || ']' AS raw,
    CHAR_LENGTH(product_name) AS raw_len,
    '[' || TRIM(product_name) || ']' AS trimmed,
    CHAR_LENGTH(TRIM(product_name)) AS trimmed_len
FROM
    products_mst
WHERE
    TRIM(product_name) = '国産はちみつ'
ORDER BY
    product_id;

-- (2) 前後に余分な空白が入っている商品を洗い出す
SELECT
    product_id,
    '[' || product_name || ']' AS raw,
    CHAR_LENGTH(product_name) AS raw_len
FROM
    products_mst
WHERE
    product_name <> TRIM(product_name)
ORDER BY
    product_id;
```

### 期待結果:
(1)

| product_id | raw | raw_len | trimmed | trimmed_len |
| ---: | :--- | ---: | :--- | ---: |
| 15 | `[国産はちみつ]` | 6 | `[国産はちみつ]` | 6 |
| 20 | `[ 国産はちみつ ]` | 8 | `[国産はちみつ]` | 6 |

(2)

| product_id | raw | raw_len |
| ---: | :--- | ---: |
| 20 | `[ 国産はちみつ ]` | 8 |

### 解説:
`product_id = 20` は商品名の前後に半角スペースが1つずつ入っているため文字数が8になり、`=` の完全一致では別の値として扱われます（該当は1件のみ）。文字列の異常は画面を見ても分からないので、「`[` `]` などで囲んで端を見えるようにする」「`CHAR_LENGTH` で長さを比べる」が定番の調査手順です。(2) の `列 <> TRIM(列)` という書き方は、データ移行の直後やCSV取込後の表記ゆれ検出にそのまま使えます。

## 問題 13: 経過期間を「期間」と「日数」の2通りで出す
- **目的**: `AGE()` で2つの日付の差を年月日の期間として求め、日付同士の引き算（整数の日数）との違いを理解する。あわせて基準日を固定して結果が再現可能なクエリにする作法を学ぶ。

### 問題:
(1) `customers_mst` テーブルから、全顧客について **2024年12月31日時点** での登録日からの経過期間を、次の3つの列で表示してください。並び順は登録日(`created_date`)の古い順とします。

- **elapsed**: `AGE()` で求めた「◯年◯か月◯日」という期間
- **elapsed_days**: 日付同士の引き算で求めた通算日数
- **elapsed_years**: `elapsed` から「年」の部分だけを取り出した数値

(2) このSQLで `NOW()` を使わず `2024-12-31` を直接書いているのはなぜか説明してください。

(3) 退会済みの顧客（`deleted_at` に値が入っている顧客）について、登録日から退会日までの在籍期間を求めてください。

> **ヒント**: `AGE(終了日, 開始日)` で2つの日付の差が期間として求まります。(3) の `deleted_at` は日付ではなく日時なので、`deleted_at::date` のように日付へ変換してから渡します。

### 解答:
```sql
-- (1) 2024-12-31 を基準にした経過期間
SELECT
    customer_id,
    customer_name,
    created_date,
    AGE(DATE '2024-12-31', created_date) AS elapsed,
    DATE '2024-12-31' - created_date AS elapsed_days,
    EXTRACT(YEAR FROM AGE(DATE '2024-12-31', created_date)) AS elapsed_years
FROM
    customers_mst
ORDER BY
    created_date;

-- (3) 退会済み顧客の在籍期間
SELECT
    customer_id,
    customer_name,
    created_date,
    deleted_at::date AS left_date,
    AGE(deleted_at::date, created_date) AS membership_period
FROM
    customers_mst
WHERE
    deleted_at IS NOT NULL
ORDER BY
    customer_id;
```

### 期待結果:
(1)

| customer_id | customer_name | created_date | elapsed | elapsed_days | elapsed_years |
| ---: | :--- | :--- | :--- | ---: | ---: |
| 1 | 佐藤 太郎 | 2023-01-15 | 1 year 11 mons 16 days | 716 | 1 |
| 2 | 鈴木 花子 | 2023-02-20 | 1 year 10 mons 11 days | 680 | 1 |
| 3 | 田中 健太 | 2023-03-01 | 1 year 9 mons 30 days | 671 | 1 |
| 4 | 山田 恵美 | 2023-04-10 | 1 year 8 mons 21 days | 631 | 1 |
| 5 | 渡辺 剛 | 2023-05-05 | 1 year 7 mons 26 days | 606 | 1 |
| 6 | 高橋 明 | 2023-06-12 | 1 year 6 mons 19 days | 568 | 1 |
| 7 | 中村 友子 | 2023-07-25 | 1 year 5 mons 6 days | 525 | 1 |
| 8 | 小林 大輔 | 2023-08-01 | 1 year 4 mons 30 days | 518 | 1 |
| 9 | 伊藤 さやか | 2023-09-18 | 1 year 3 mons 13 days | 470 | 1 |

(3)

| customer_id | customer_name | created_date | left_date | membership_period |
| ---: | :--- | :--- | :--- | :--- |
| 4 | 山田 恵美 | 2023-04-10 | 2023-09-15 | 5 mons 5 days |

### 解説:
`AGE(終了日, 開始日)` が返すのは interval（人間が読みやすい年月日の期間）、日付同士の引き算が返すのは integer（通算日数）で、月の長さが違うため互いに変換することはできません。`deleted_at::date` は `CAST(deleted_at AS DATE)` の短縮記法で、キャストせずに使うと時刻やタイムゾーンの分だけ値がずれます。(2) は `NOW()` を使うと実行するたびに結果が変わり、答え合わせや再実行で同じ結果を再現できなくなるためです。

## 問題 14: 集計キーとしての「年月」の作り方
- **目的**: `TO_CHAR` で `YYYY-MM` という年月キーを作る方法を学び、`EXTRACT(MONTH …)` が「年をまたぐと同じ値になる」ため集計キーには使えないことを理解する。

### 問題:
(1) `orders_trn` テーブルから、全注文について `order_id` と `order_date` に加えて、次の3つの列を注文日の古い順に表示してください。

- **month_only**: `EXTRACT()` で取り出した「月」の数値
- **year_month**: `TO_CHAR()` で `2023-08` の形式にしたもの
- **ja_label**: `TO_CHAR()` で `2023年08月` の形式にしたもの

(2) `month_only` が `8` になる注文だけを抽出してください。それらは何件あり、全て同じ月の売上と言えますか。

(3) 月次売上レポートの集計キーには `month_only` と `year_month` のどちらを使うべきか、理由とあわせて説明してください。

> **ヒント**: 書式文字列の中に「年」「月」のようなリテラル文字を含めたいときは、`'YYYY"年"MM"月"'` のようにダブルクォートで囲みます。

### 解答:
```sql
-- (1) 3通りの「月」の表現を並べる
SELECT
    order_id,
    order_date,
    EXTRACT(MONTH FROM order_date) AS month_only,
    TO_CHAR(order_date, 'YYYY-MM') AS year_month,
    TO_CHAR(order_date, 'YYYY"年"MM"月"') AS ja_label
FROM
    orders_trn
ORDER BY
    order_date;

-- (2) 「月」が8の注文を列挙する
SELECT
    order_id,
    order_date,
    TO_CHAR(order_date, 'YYYY-MM') AS year_month
FROM
    orders_trn
WHERE
    EXTRACT(MONTH FROM order_date) = 8
ORDER BY
    order_date;
```

### 期待結果:
(1)（18件・抜粋）

| order_id | order_date | month_only | year_month | ja_label |

### 解説:
`EXTRACT` は日付の一部を数値で取り出す関数、`TO_CHAR` は書式を指定して文字列に変換する関数で、そもそも目的が違います。(2) の10件は 2023-08 の8件と 2024-08 の2件が混ざっており「同じ月の売上」ではないため、月次集計のキーには必ず年を含んだ `TO_CHAR(日付, 'YYYY-MM')` を使います（`YYYY-MM` は文字列のまま並べ替えても時系列順になる利点があります）。この落とし穴は 07章 問題17 で `GROUP BY` と組み合わせて再登場します。

> **⚠️ 講師向けの注意**: `EXTRACT(MONTH FROM order_date)` 別の件数は 2月=2、3月=1、8月=10、9月=5 です。8月の突出はサンプルデータの偏りではなく、異なる年が合算された結果であることを板書で示すと (3) の結論が伝わりやすくなります。
