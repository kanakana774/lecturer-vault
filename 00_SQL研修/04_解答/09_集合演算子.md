## 問題 1: UNION と UNION ALL の違い
- **目的**: `UNION` が重複行を1つにまとめること、`UNION ALL` はまとめないことを、件数の差で確かめる。

### 問題:
`customers` テーブルから、次の2つを1つの一覧にまとめてください。

1. **東京在住の顧客**（`city` が `'Tokyo'`）のメールアドレス
2. **Bronze会員の顧客**（`membership_id` が `1`）のメールアドレス

**【問1】** **重複を排除して** 一覧を取得してください。
**【問2】** `UNION` を `UNION ALL` に変えて実行し、**件数がいくつからいくつに変わるか** を答えてください。また、**増えた1行が誰のものか** も答えてください。
**【問3】** `UNION` と `UNION ALL`、実務ではどちらを既定に選ぶべきですか。理由も書いてください。

### 解答:

**【問1】** 重複を排除する（`UNION`）

```sql
SELECT
	email
FROM
	customers
WHERE
	city = 'Tokyo'
UNION
SELECT
	email
FROM
	customers
WHERE
	membership_id = 1
ORDER BY
	email;
```

**【問2】** `UNION ALL` に変える

```sql
SELECT
	email
FROM
	customers
WHERE
	city = 'Tokyo'
UNION ALL
SELECT
	email
FROM
	customers
WHERE
	membership_id = 1
ORDER BY
	email;
```

**7件 → 8件** になります。増えるのは **`hank@example.com`**（Hank は東京在住 **かつ** Bronze会員なので、両方のSELECTに登場する）。

**【問3】** **重複が起きないと分かっているなら `UNION ALL`。** `UNION` は重複を消すために並べ替え（または集約）が必要で、そのぶん遅くなります。「重複していても構わない／そもそも重複しない」場面でわざわざ `UNION` を使う理由はありません。

### 期待結果:

`UNION`（7件）

```
       email
-------------------
 alice@example.com
 bob@example.com
 diana@example.com
 ellen@example.com
 grace@example.com
 hank@example.com
 ivy@example.com
```

`UNION ALL`（8件・`hank@example.com` が2回）

```
       email
-------------------
 alice@example.com
 bob@example.com
 diana@example.com
 ellen@example.com
 grace@example.com
 hank@example.com
 hank@example.com
 ivy@example.com
```

### 解説:
東京在住は Alice / Diana / Ellen / Hank の4人、Bronze会員は Bob / Grace / Hank / Ivy の4人で、**Hank だけが両方に属します**。だから 4+4=8行を `UNION` すると7行になります。
`UNION` は「2つの結果を縦につないでから重複を1つにまとめる」演算です。**列の数と型が両側で揃っている必要があり**、列名は左側のSELECTのものが使われます。`ORDER BY` は全体に対して1つだけ、いちばん最後に書きます。

## 問題 2: すべての活動日の一覧
- **目的**: 別々のテーブルの同じ意味の列を `UNION` で1本の列にまとめ、`ORDER BY` を全体に効かせる。

### 問題:
「商品レビューが投稿された日付」と「支払いが行われた日付」をまとめ、
**すべての活動日一覧** を昇順で取得してください。

### 解答:
```sql
SELECT
	review_date AS active_day
FROM
	reviews
UNION
SELECT
	payment_date AS active_day
FROM
	payments
ORDER BY
	active_day;
```

### 期待結果:
15件。

```
 active_day
------------
 2022-01-06
 2022-01-07
 2022-01-08
 2022-01-16
 2022-01-26
 2022-02-01
 2022-02-05
 2022-02-15
 2022-02-16
 2022-02-20
 2022-02-26
 2022-03-10
 2022-03-11
 2022-03-21
 2022-03-25
```

### 解説:
`ORDER BY` は**最後のSELECTの後ろに1回だけ**書きます。個々のSELECTに付けても全体の並びは保証されません。並べ替えの基準名には、左側のSELECTで付けた別名（`active_day`）が使えます。
なお、このデータではレビュー日と支払日がたまたま1日も重なっていないため、**`UNION ALL` に変えても15件のまま**です。結果を見ただけでは「重複排除が効いたのか、そもそも重複が無かったのか」は区別できません（問題1と対照的）。

## 問題 3: 在庫数と注文数を1つの表にまとめる
- **目的**: `UNION ALL` で異なる集計を縦に積み、固定文字列の列で「どちらの行か」を識別できるようにする。

### 問題:
商品名と、商品ごとの在庫数と注文数を同じ形式で結合したものを数(`quantity`)として取得してください。
またその際、それぞれの商品が在庫数か、注文数か、区別つけるため、`source` として
在庫数の場合「Stock」、注文数の場合「Order」と表示するようにしましょう。
ただし、商品名ごとに表示されるように順番を指定してください。

### 解答:
```sql
SELECT
	p.product_name,
	'Stock' AS source,
	SUM(i.stock_quantity) AS quantity
FROM
	inventory i
	INNER JOIN products p ON i.product_id = p.product_id
GROUP BY
	p.product_name
UNION ALL
SELECT
	p.product_name,
	'Order' AS source,
	SUM(oi.quantity) AS quantity
FROM
	orderitems oi
	INNER JOIN products p ON oi.product_id = p.product_id
GROUP BY
	p.product_name
ORDER BY
	product_name,
	source;
```

### 期待結果:
24件。

```
  product_name  | source | quantity
----------------+--------+----------
 Cap            | Order  |        2
 Cap            | Stock  |       50
 Dining Chair   | Order  |        4
 Dining Chair   | Stock  |       10
 Headphones     | Order  |        1
 Headphones     | Stock  |       20
 Jacket         | Order  |        1
 Jacket         | Stock  |        0
 Laptop         | Order  |        4
 Laptop         | Stock  |       60
 Luxury Sofa    | Stock  |        2
 Monitor        | Stock  |       40
 Novel          | Order  |        2
 Novel          | Stock  |      100
 Office Chair   | Order  |        2
 Office Chair   | Stock  |        5
 Smartphone     | Order  |        2
 Smartphone     | Stock  |       30
 Socks          | Order  |        6
 Socks          | Stock  |      100
 T-shirt        | Order  |        5
 T-shirt        | Stock  |       80
 Technical Book | Order  |        1
 Technical Book | Stock  |       20
```

### 解説:
ここは `UNION` ではなく **`UNION ALL` を使うのが正解**です。「在庫」と「注文」は別の意味の行なので、たまたま商品名・数量が一致しても1行にまとめてはいけません。
`'Stock'` / `'Order'` のような**固定値の列**を足して行の出自を持たせるのは、`UNION ALL` の定石です。
`Luxury Sofa` と `Monitor` に `Order` 行が無いのは、一度も注文されていないためです。逆に `Jacket` の `Stock` が0なのは、在庫レコードはあるが数量が0という意味で、**「行が無い」のとは違います**。

## 問題 4: 注文もレビューもした顧客（INTERSECT）
- **目的**: `INTERSECT` で2つの集合の共通部分だけを取り出す。

### 問題:
「一度でも注文をした顧客」と「一度でもレビューを書いた顧客」の
**両方に当てはまる**顧客名を取得してください。

### 解答:
```sql
SELECT
	c.name
FROM
	customers c
	INNER JOIN orders o ON c.customer_id = o.customer_id
INTERSECT
SELECT
	c.name
FROM
	customers c
	INNER JOIN reviews r ON c.customer_id = r.customer_id
ORDER BY
	name;
```

### 期待結果:
3件。

```
 name
-------
 Alice
 Diana
 Ellen
```

### 解説:
`INTERSECT` は**両側に現れる行だけ**を残します。`UNION` と同じく重複は自動的に排除されるので、同じ顧客が何度注文していても名前は1回しか出ません。
左側の「注文した顧客」は7人、右側の「レビューを書いた顧客」は3人で、結果が3人になります。**この章のデータではレビュー投稿者が全員注文経験者**なので、右側がそのまま答えになっています。

## 問題 5: 会員ランクを持ち、かつ注文経験もある顧客（INTERSECT）
- **目的**: `WHERE` で絞った集合と結合で作った集合という、**作り方の違う2つの集合**にも `INTERSECT` が使えることを確認する。

### 問題:
「会員ランクを持つ顧客」と「一度でも注文をした顧客」の
**両方に当てはまる**顧客名を取得してください。

### 解答:
```sql
SELECT
	c.name
FROM
	customers c
WHERE
	c.membership_id IS NOT NULL
INTERSECT
SELECT
	c.name
FROM
	customers c
	INNER JOIN orders o ON c.customer_id = o.customer_id
ORDER BY
	name;
```

### 期待結果:
7件。

```
 name
-------
 Alice
 Bob
 Diana
 Ellen
 Hank
 Ivy
 Jack
```

### 解説:
集合演算子がつなぐのは「テーブル」ではなく「SELECTの結果」です。片方は `WHERE` で絞っただけ、もう片方は `INNER JOIN` した結果、というように**作り方が違っていても、列の数と型さえ合っていればつなげます**。
会員ランクを持つ顧客は8人（Charlie だけが未設定）、注文経験者は7人。共通部分が7人になるのは、**注文経験者が全員ランク持ちだった**ためです。ここから漏れる1人（Grace）が、次の問題6の答えになります。

## 問題 6: 会員なのに一度も注文していない顧客（EXCEPT）
- **目的**: `EXCEPT` で「左にあって右にない行」を取り出す。`INTERSECT` との違いを、同じ2つの集合で見比べる。

### 問題:
**【問1】** 「会員ランクを持つ顧客」から「一度でも注文をした顧客」を**除いた**顧客名を取得してください。
**【問2】** 問題4と**まったく同じ2つのSELECT**（注文した顧客／レビューを書いた顧客）を `INTERSECT` ではなく `EXCEPT` でつなぐと、何が取れますか。実行して結果を答えてください。
**【問3】** 問題4の結果（3件）と【問2】の結果を足すと何件になりますか。それはなぜですか。

### 解答:

**【問1】** 会員ランク持ち − 注文経験者

```sql
SELECT
	c.name
FROM
	customers c
WHERE
	c.membership_id IS NOT NULL
EXCEPT
SELECT
	c.name
FROM
	customers c
	INNER JOIN orders o ON c.customer_id = o.customer_id
ORDER BY
	name;
```

**Grace** の1件。

**【問2】** 注文経験者 − レビュー投稿者 ＝ **注文はしたが、レビューを書いていない顧客**

```sql
SELECT
	c.name
FROM
	customers c
	INNER JOIN orders o ON c.customer_id = o.customer_id
EXCEPT
SELECT
	c.name
FROM
	customers c
	INNER JOIN reviews r ON c.customer_id = r.customer_id
ORDER BY
	name;
```

Bob / Hank / Ivy / Jack の4件。

**【問3】** **3件 + 4件 = 7件** で、左側の「注文をした顧客」7人とちょうど一致します。
`INTERSECT`（両方にある）と `EXCEPT`（左にしかない）は、**左側の集合を重なりで2つに切り分ける**演算だからです。切り分けたものを足せば元に戻ります。

### 期待結果:

【問1】

```
 name
-------
 Grace
```

【問2】

```
 name
-------
 Bob
 Hank
 Ivy
 Jack
```

### 解説:
**`EXCEPT` は左右を入れ替えると結果が変わります**（`UNION` や `INTERSECT` は入れ替えても同じ）。「AからBを引く」であって「AとBの違い」ではない点に注意してください。
【問2】を逆向き（レビュー投稿者 − 注文経験者）にすると0件になります。レビューを書いた3人が全員注文経験者だからです。
なお `EXCEPT` も重複を排除します。重複を残したい場合は `EXCEPT ALL` を使いますが、実務で使う場面はほとんどありません。
