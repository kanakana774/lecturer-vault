## 問題 1: UNION と UNION ALL の違い
- **目的**: `UNION` が重複行を1つにまとめること、`UNION ALL` はまとめないことを、件数の差で確かめる。

### 問題:
`customers` テーブルから、次の2つを1つの一覧にまとめてください。

1. **東京在住の顧客**（`city` が `'Tokyo'`）のメールアドレス
2. **Bronze会員の顧客**（`membership_id` が `1`）のメールアドレス

**【問1】** **重複を排除して** 一覧を取得してください。
**【問2】** `UNION` を `UNION ALL` に変えて実行し、**件数がいくつからいくつに変わるか** を答えてください。また、**増えた1行が誰のものか** も答えてください。
**【問3】** `UNION` と `UNION ALL`、実務ではどちらを既定に選ぶべきですか。理由も書いてください。

### 解答:

**【問1】** 重複を排除する（`UNION`）

```sql
SELECT
	email
FROM
	customers
WHERE
	city = 'Tokyo'
UNION
SELECT
	email
FROM
	customers
WHERE
	membership_id = 1
ORDER BY
	email;
```

**【問2】** `UNION` を `UNION ALL` に変える

```sql
SELECT
	email
FROM
	customers
WHERE
	city = 'Tokyo'
UNION ALL
SELECT
	email
FROM
	customers
WHERE
	membership_id = 1
ORDER BY
	email;
```

**8件 → 9件** になります。増えた1行は **Hank**（`hank@example.com`）です。Hank は東京在住かつ Bronze会員で、両方の `SELECT` に登場します。

**【問3】** **重複が起きないと分かっているなら `UNION ALL` を既定にします。** `UNION` は重複を消すために結果全体を並べ替える（または集約する）ので、そのぶん遅くなります。「重複しても構わない」「そもそも重複しない」場面で `UNION` を選ぶ理由はありません。

### 期待結果:

**【問1】** `UNION` — 8件

```
       email
-------------------
 alice@example.com
 bob@example.com
 diana@example.com
 ellen@example.com
 grace@example.com
 hank@example.com
 ivy@example.com
 kevin@example.com
(8 rows)
```

**【問2】** `UNION ALL` — 9件（`hank@example.com` が2回）

```
       email
-------------------
 alice@example.com
 bob@example.com
 diana@example.com
 ellen@example.com
 grace@example.com
 hank@example.com
 hank@example.com
 ivy@example.com
 kevin@example.com
(9 rows)
```

### 解説:

**件数は2つの集合の内訳から計算できます。**

| 集合 | 件数 | 顧客 |
| :--- | ---: | :--- |
| 東京在住（左の `SELECT`） | 5 | Alice / Diana / Ellen / Hank / Kevin |
| Bronze会員（右の `SELECT`） | 4 | Bob / Grace / Hank / Ivy |
| **両方に属する（重なり）** | **1** | **Hank** |

`UNION ALL` は縦につなぐだけなので 5 + 4 = **9件**。`UNION` はそこから重なりの1件を消して **8件** です。

`UNION` は「2つの結果を縦につないでから、重複を1つにまとめる」演算です。つなぐには**両側で列の数と型が揃っている必要があり**、結果の列名は左側の `SELECT` のものが使われます。`ORDER BY` は結果全体に1つだけ、いちばん最後に書きます。

## 問題 2: すべての活動日の一覧
- **目的**: 別々のテーブルの同じ意味の列を `UNION` で1本の列にまとめ、`ORDER BY` を全体に効かせる。

### 問題:
「商品レビューが投稿された日付」と「支払いが行われた日付」をまとめ、
**すべての活動日一覧** を昇順で取得してください。**同じ日付は1行にまとめてください。**

### 解答:
```sql
SELECT
	review_date AS active_day
FROM
	reviews
UNION
SELECT
	payment_date AS active_day
FROM
	payments
ORDER BY
	active_day;
```

### 期待結果:
19件。

```
 active_day
------------
 2022-01-06
 2022-01-08
 2022-01-09
 2022-01-16
 2022-01-26
 2022-02-05
 2022-02-10
 2022-02-15
 2022-02-20
 2022-02-26
 2022-03-01
 2022-03-05
 2022-03-11
 2022-03-21
 2022-03-25
 2022-04-10
 2022-04-12
 2022-04-19
 2022-04-20
(19 rows)
```

### 解説:

**並べ替えの基準名には、左側の `SELECT` で付けた別名（`active_day`）が使えます。** 結果の列名は左側から取られるためです（問題1の解説）。

**`ORDER BY` は最後に1回だけ書きます。** 個々の `SELECT` に直接書くと構文エラーになります。

```
ERROR:  syntax error at or near "UNION"
```

**そして `ORDER BY` を書かないと、日付順には並びません。** 実測では `2022-03-11` から始まる、意味のない順序で返りました。集合演算子の結果に順序の保証は無いので、並べたいなら必ず書きます。

`UNION ALL` に変えると **20件**になります。増える1行は **`2022-02-15`** で、これは**レビュー日どうしの重複**です（同じ日に2件のレビューが投稿されている）。レビュー日と支払日は1日も重なっていません。

## 問題 3: 在庫数と注文数を1つの表にまとめる
- **目的**: `UNION ALL` で異なる集計を縦に積み、固定文字列の列で「どちらの行か」を識別できるようにする。

### 問題:
商品ごとの**在庫数**と**注文数**を、`product_name` / `source` / `quantity` の3列で1つの表にまとめてください。

- `quantity` … 在庫数または注文数
- `source` … その行がどちらかを示す固定の文字列。在庫数の行は `'Stock'`、注文数の行は `'Order'`

並び順は **`product_name` の昇順、同じ商品の中では `source` の昇順**としてください。

### 解答:
```sql
SELECT
	p.product_name,
	'Stock' AS source,
	SUM(i.stock_quantity) AS quantity
FROM
	inventory i
	INNER JOIN products p ON i.product_id = p.product_id
GROUP BY
	p.product_name
UNION ALL
SELECT
	p.product_name,
	'Order' AS source,
	SUM(oi.quantity) AS quantity
FROM
	orderitems oi
	INNER JOIN products p ON oi.product_id = p.product_id
GROUP BY
	p.product_name
ORDER BY
	product_name,
	source;
```

### 期待結果:
24件。

```
  product_name  | source | quantity
----------------+--------+----------
 Cap            | Order  |        2
 Cap            | Stock  |       50
 Dining Chair   | Order  |        4
 Dining Chair   | Stock  |       10
 Headphones     | Order  |        1
 Headphones     | Stock  |       20
 Jacket         | Order  |        1
 Jacket         | Stock  |        0
 Laptop         | Order  |        5
 Laptop         | Stock  |       60
 Luxury Sofa    | Stock  |        2
 Monitor        | Stock  |       40
 Novel          | Order  |        6
 Novel          | Stock  |      100
 Office Chair   | Order  |        2
 Office Chair   | Stock  |        5
 Smartphone     | Order  |        3
 Smartphone     | Stock  |       30
 Socks          | Order  |        6
 Socks          | Stock  |      100
 T-shirt        | Order  |        5
 T-shirt        | Stock  |       80
 Technical Book | Order  |        3
 Technical Book | Stock  |       20
(24 rows)
```

### 解説:

**ここは `UNION` ではなく `UNION ALL` を使います。** 「在庫」と「注文」は別の意味の行なので、商品名と数量がたまたま一致しても1行にまとめてはいけません。`'Stock'` / `'Order'` のような**固定値の列**を足して行の出自を持たせるのは、`UNION ALL` の定石です。

**`Order` 行が無い商品と、`Stock` が0の商品は別物です。**

| 商品 | 見え方 | 意味 |
| :--- | :--- | :--- |
| Luxury Sofa / Monitor | `Order` の行そのものが無い | 一度も注文されていない（`orderitems` に行が無い） |
| Jacket | `Stock` の行があり `0` | 在庫レコードはあるが、数量が0 |

「行が無い」のか「行はあって値が0」なのかは、縦に積んだ表では**行の有無**として現れます。

`source` の昇順は `Order` → `Stock` の順です（アルファベット順）。指定しないと同じ商品の中の並びが決まらないので、`ORDER BY` の第2キーに入れています。

## 問題 4: 注文もレビューもした顧客（INTERSECT）
- **目的**: `INTERSECT` で2つの集合の共通部分だけを取り出す。

### 問題:
「一度でも注文をした顧客」と「一度でもレビューを書いた顧客」の
**両方に当てはまる**顧客名を取得してください。

### 解答:
```sql
SELECT
	c.name
FROM
	customers c
	INNER JOIN orders o ON c.customer_id = o.customer_id
INTERSECT
SELECT
	c.name
FROM
	customers c
	INNER JOIN reviews r ON c.customer_id = r.customer_id
ORDER BY
	name;
```

### 期待結果:
2件。

```
 name
-------
 Alice
 Leo
(2 rows)
```

### 解説:

`INTERSECT` は**両側に現れる行だけ**を残します。

| 集合 | 件数 | 顧客 |
| :--- | ---: | :--- |
| 注文をした顧客（左の `SELECT`） | 9 | Alice / Bob / Diana / Ellen / Hank / Ivy / Jack / Kevin / Leo |
| レビューを書いた顧客（右の `SELECT`） | 2 | Alice / Leo |
| **両方（`INTERSECT` の結果）** | **2** | **Alice / Leo** |

**`UNION` と同じく重複は自動的に排除されます。** Alice は注文もレビューも複数持ちますが、名前は1回しか出ません。

このデータではレビューを書いた2人が**どちらも注文経験者**なので、右側の集合がそのまま答えになっています。

## 問題 5: 会員ランクを持ち、かつ注文経験もある顧客（INTERSECT）
- **目的**: `WHERE` で絞った集合と結合で作った集合という、**作り方の違う2つの集合**にも `INTERSECT` が使えることを確認する。

### 問題:
「会員ランクを持つ顧客」と「一度でも注文をした顧客」の
**両方に当てはまる**顧客名を取得してください。

### 解答:
```sql
SELECT
	c.name
FROM
	customers c
WHERE
	c.membership_id IS NOT NULL
INTERSECT
SELECT
	c.name
FROM
	customers c
	INNER JOIN orders o ON c.customer_id = o.customer_id
ORDER BY
	name;
```

### 期待結果:
9件。

```
 name
-------
 Alice
 Bob
 Diana
 Ellen
 Hank
 Ivy
 Jack
 Kevin
 Leo
(9 rows)
```

### 解説:

**集合演算子がつなぐのは「テーブル」ではなく「`SELECT` の結果」です。** 片方は `WHERE` で絞っただけ、もう片方は `INNER JOIN` した結果でも、**列の数と型が合っていればつなげます**。

| 集合 | 作り方 | 件数 | 顧客 |
| :--- | :--- | ---: | :--- |
| 会員ランクを持つ顧客（左） | `WHERE` で絞る | 10 | Charlie 以外の全員 |
| 注文をした顧客（右） | `INNER JOIN` する | 9 | Grace 以外の会員 |
| **両方（`INTERSECT` の結果）** | | **9** | 左から Grace が落ちたもの |

**左の10人から落ちる1人が Grace** です。Grace は会員ランクを持っていますが、`orders` に一度も登場しません。この Grace が、次の問題6【問1】の答えになります。

## 問題 6: 会員なのに一度も注文していない顧客（EXCEPT）
- **目的**: `EXCEPT` で「左にあって右にない行」を取り出す。`INTERSECT` との違いを、同じ2つの集合で見比べる。

### 問題:
**【問1】** 「会員ランクを持つ顧客」から「一度でも注文をした顧客」を**除いた**顧客名を取得してください。
**【問2】** 問題4と**まったく同じ2つのSELECT**（注文した顧客／レビューを書いた顧客）を `INTERSECT` ではなく `EXCEPT` でつなぐと、何が取れますか。実行して結果を答えてください。
**【問3】** 問題4の結果と【問2】の結果を足すと何件になりますか。それはなぜですか。

### 解答:

**【問1】** 会員ランク持ち − 注文経験者

```sql
SELECT
	c.name
FROM
	customers c
WHERE
	c.membership_id IS NOT NULL
EXCEPT
SELECT
	c.name
FROM
	customers c
	INNER JOIN orders o ON c.customer_id = o.customer_id
ORDER BY
	name;
```

**Grace** の1件。会員ランクを持ちながら、一度も注文していない顧客です。

**【問2】** 注文経験者 − レビュー投稿者 ＝ **注文はしたが、レビューを書いていない顧客**

```sql
SELECT
	c.name
FROM
	customers c
	INNER JOIN orders o ON c.customer_id = o.customer_id
EXCEPT
SELECT
	c.name
FROM
	customers c
	INNER JOIN reviews r ON c.customer_id = r.customer_id
ORDER BY
	name;
```

**7件**（Bob / Diana / Ellen / Hank / Ivy / Jack / Kevin）。

**【問3】** 問題4の **2件** と【問2】の **7件** を足して **9件**。左側の「注文をした顧客」9人とちょうど一致します。

`INTERSECT`（両方にある）と `EXCEPT`（左にしかない）は、**同じ2つの集合に対して、左側を重なりで2つに切り分ける**演算です。切り分けたものを足せば元に戻ります。

### 期待結果:

**【問1】** 1件

```
 name
-------
 Grace
(1 row)
```

**【問2】** 7件

```
 name
-------
 Bob
 Diana
 Ellen
 Hank
 Ivy
 Jack
 Kevin
(7 rows)
```

### 解説:

**【問3】の「切り分け」を表にすると、こうなります。** 左右の `SELECT` は問題4とまったく同じで、演算子だけが違います。

| 演算子 | 取れるもの | 件数 | 顧客 |
| :--- | :--- | ---: | :--- |
| `INTERSECT`（問題4） | 両方にある | 2 | Alice / Leo |
| `EXCEPT`（【問2】） | 左にしかない | 7 | Bob / Diana / Ellen / Hank / Ivy / Jack / Kevin |
| **合計** | **＝左の集合そのもの** | **9** | 注文をした顧客9人 |

**`EXCEPT` は左右を入れ替えると結果が変わります**（`UNION` と `INTERSECT` は入れ替えても同じ）。「AからBを引く」であって「AとBの違い」ではない点に注意してください。【問2】を逆向き（レビュー投稿者 − 注文経験者）にすると **0件**になります。レビューを書いた2人が、どちらも注文経験者だからです。

`EXCEPT` も `UNION` `INTERSECT` と同じく重複を排除します。残したい場合は `EXCEPT ALL` を使いますが、実務で使う場面はほとんどありません。
