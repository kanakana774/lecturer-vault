## 問題 1: 非相関サブクエリ
- **目的**: `IN` を使った非相関サブクエリと、同じことを `INNER JOIN` で書いた形を見比べる。

### 問題:
「東京都に住んでいる顧客が行ったすべての注文ID」を取得してください。

### 解答:
最も直感的で、要件をそのまま SQL にした形です。
```sql
-- 案1: IN 句
SELECT
    order_id
FROM
    orders
WHERE
    customer_id IN (
        SELECT
            customer_id
        FROM
            customers
        WHERE
            city = 'Tokyo'
    );
```

実務ではパフォーマンスや拡張性（顧客名も出したい等）の観点から JOIN が好まれることが多いです。
```sql
-- 案2: INNER JOIN
SELECT
    o.order_id
FROM
    orders o
    INNER JOIN customers c ON o.customer_id = c.customer_id
WHERE
    c.city = 'Tokyo';
```

## 問題 2: スカラサブクエリ
- **目的**: スカラサブクエリで「最大値」を条件に使う。`ORDER BY` + `LIMIT` との違い（同率1位の扱い）を理解する。

### 問題:
「最も価格が高い商品名と価格」を取得してください。

### 解答:
同価格で最高値の商品が複数あってもすべて取得できる、安全な書き方です。
```sql
-- 案1: サブクエリ
SELECT
    product_name,
    price
FROM
    products
WHERE
    price = (
        SELECT
            MAX(price)
        FROM
            products
    );
```

**注意:** 同率1位が複数ある場合、どれか1つしか出ません。仕様で「1件だけでよい」と決まっている場合のみ使用します。
```sql
-- 案2: ORDER BY + LIMIT
SELECT
    product_name,
    price
FROM
    products
ORDER BY
    price DESC
LIMIT 1;
```

## 問題 3: 相関サブクエリ
- **目的**: `EXISTS` による存在チェックを書けるようになり、`JOIN` + `DISTINCT` との読みやすさの差を知る。

### 問題:
「一度でもレビューを書いたことがある顧客のIDと名前」を取得してください。

### 解答:
相関サブクエリの最も代表的な使い方です。レビューテーブルが巨大でも、1件見つかればスキャンを止めるため高速です。
existsを使っているため、存在チェックという意図が読みやすいため、可読性の点でも高いかなと思います。
```sql
-- 案1: EXISTS
SELECT
    c.customer_id,
    c.name
FROM
    customers c
WHERE
    EXISTS (
        SELECT
            1
        FROM
            reviews r
        WHERE
            r.customer_id = c.customer_id
    );
```

```sql
-- 案2: JOIN + DISTINCT
SELECT DISTINCT
    c.customer_id,
    c.name
FROM
    customers c
    INNER JOIN reviews r ON c.customer_id = r.customer_id;
```

## 問題 4: 相関サブクエリ
- **目的**: 外側の行の値をサブクエリの中で参照する相関サブクエリを、グループごとの平均との比較で使う。

### 問題:
それぞれの倉庫において、その倉庫の「平均在庫数」よりも多く在庫されている商品を取得してください。
表示項目：倉庫名、商品名、在庫数

### 解答:
```sql
-- 案1: 相関サブクエリ
SELECT
	w.warehouse_name,
	p.product_name,
	i.stock_quantity
FROM
	inventory i
	JOIN warehouses w ON i.warehouse_id = w.warehouse_id
	JOIN products p ON i.product_id = p.product_id
WHERE
	i.stock_quantity > (
		-- その倉庫(i.warehouse_id)の平均在庫
		SELECT
			AVG(stock_quantity)
		FROM
			inventory i2
		WHERE
			i2.warehouse_id = i.warehouse_id
	);
```

### 解説:
例えば、「東京倉庫の平均と東京倉庫の商品」を比べるので、比較対象が直感的で、相関サブクエリのオーソドックスな練習問題。

## 問題 5: 順位付け (Window関数)
- **目的**: 「上位N件（同率含む）」を、ウィンドウ関数・`LIMIT`・自己結合の3通りで表現できるようにする。

### 問題:
**「1回の注文（`order_id`）ごとの支払い合計額が、全体のトップ 3 に入る注文 ID と金額」を取得してください。**
※分割払いの注文は、1回の注文としてまとめて集計します。
※同率1位などがある場合も考慮してください。

### 解答:
1回の注文で複数回支払い（分割払い）がある可能性を考慮し、まず `SUM` してからランク付けします。
```sql
-- 案1: CTE + DENSE_RANK
WITH OrderPaymentTotals AS (
    SELECT
        order_id,
        SUM(amount) AS total_amount
    FROM
        payments
    GROUP BY
        order_id
),
RankedOrders AS (
    SELECT
        order_id,
        total_amount,
        -- 同率を詰めてランク付け (1, 1, 2, 3, 3...)
        DENSE_RANK() OVER (ORDER BY total_amount DESC) AS rnk
    FROM
        OrderPaymentTotals
)
SELECT
    order_id,
    total_amount
FROM
    RankedOrders
WHERE
    rnk <= 3;
```

```sql
-- 案2: order by + limit
SELECT
	o.order_id,
	SUM(p.amount) AS sum_amount
FROM
	orders AS o
	INNER JOIN payments AS p ON o.order_id = p.order_id
GROUP BY
	o.order_id
HAVING
	SUM(amount) IN (
		SELECT DISTINCT
			SUM(amount) AS high_price
		FROM
			payments
		GROUP BY
			order_id
		ORDER BY
			SUM(amount) DESC
		LIMIT
			3
	)
ORDER BY
	sum_amount DESC,
	o.order_id;
```

再帰的に集合の要素数を増やし、その要素数でランキングを付ける方策です。
もちろんwith句を使えばより見やすくなります。
```sql
-- 案3: 自己結合、再帰的集合
-- 順位付を、自分より多い支払金額の集合の要素数という見方
SELECT
	p1.order_id,
	p1.total_amount,
	COUNT(DISTINCT p2.total_amount) AS ranking -- 同率を圧縮する
FROM
	(
		SELECT
			order_id,
			SUM(amount) AS total_amount
		FROM
			payments
		GROUP BY
			order_id
	) AS p1
	INNER JOIN (
		SELECT
			order_id,
			SUM(amount) AS total_amount
		FROM
			payments
		GROUP BY
			order_id
	) AS p2 ON p1.total_amount <= p2.total_amount -- 自分より低い支払金額のレコードの集合を作る
GROUP BY
	p1.order_id,
	p1.total_amount
HAVING
	COUNT(DISTINCT p2.total_amount) <= 3
ORDER BY
	ranking,
	p1.order_id;
```
もちろんwith句を使えばより見やすくなります。
```sql
-- 案4: 相関スカラサブクエリ、再帰的集合
-- 順位付を、自分より多い支払金額の集合の要素数という見方
SELECT
	order_id,
	total_amount,
	ranking
FROM
	(
		SELECT
			order_id,
			total_amount,
			(
				SELECT
					COUNT(DISTINCT total_amount)
				FROM
					(
						SELECT
							order_id,
							SUM(amount) AS total_amount
						FROM
							payments
						GROUP BY
							order_id
					) AS p2
				WHERE
					p2.total_amount >= p1.total_amount
			) AS ranking
		FROM
			(
				SELECT
					order_id,
					SUM(amount) AS total_amount
				FROM
					payments
				GROUP BY
					order_id
			) AS p1
	)
WHERE
	ranking <= 3
ORDER BY
	ranking,
	order_id;
```
```sql
-- 案5: 相関スカラサブクエリを WHERE 句に置く書き方
SELECT
	t1.order_id,
	t1.total_amount
FROM
	(
		SELECT
			order_id,
			SUM(amount) AS total_amount
		FROM
			payments
		GROUP BY
			order_id
	) AS t1
WHERE
	(
		SELECT
			COUNT(DISTINCT t2.total_amount)
		FROM
			(
				SELECT
					order_id,
					SUM(amount) AS total_amount
				FROM
					payments
				GROUP BY
					order_id
			) AS t2
		WHERE
			t2.total_amount >= t1.total_amount
	) <= 3
ORDER BY
	t1.total_amount DESC;
```

### 解説:
現代の SQL では **Window 関数（`DENSE_RANK`）** を使うのが定石です（案1）。ただし「ウィンドウ関数が使えない環境」「あえて集合の考え方で解く」ときのために、案2〜案5も並べています。案3〜案5は「自分以上の金額がいくつあるか」を数えて順位にする、という同じ発想の書き換えです。

## 問題 6: 集計と最大値
- **目的**: 「最大値を取る行」を、同率1位も落とさずに取り出す。ウィンドウ関数を使わない書き方も身につける。

### 問題:
「最も多く売れた商品（数量ベース）の商品名と販売数量合計」を取得してください。

### 解答:
```sql
-- 案1: CTE + RANK
WITH ProductSales AS (
    SELECT
        p.product_id,
        p.product_name,
        SUM(oi.quantity) AS total_qty
    FROM
        products p
        INNER JOIN orderitems oi ON p.product_id = oi.product_id
        INNER JOIN orders o ON oi.order_id = o.order_id
    WHERE
        o.status != 'Cancelled' -- キャンセル注文を除外
    GROUP BY
        p.product_id,
        p.product_name
),
RankedSales AS (
    SELECT
        product_id,
        product_name,
        total_qty,
        RANK() OVER (ORDER BY total_qty DESC) AS rnk
    FROM
        ProductSales
)
SELECT
    product_name,
    total_qty
FROM
    RankedSales
WHERE
    rnk = 1;
```

```sql
-- 案2: with句もwindow関数も使わないver
SELECT
	p.product_id,
	p.product_name,
	SUM(oi.quantity) AS total_qty
FROM
	products p
	JOIN orderitems oi ON p.product_id = oi.product_id
GROUP BY
	p.product_id,
	p.product_name
HAVING
	SUM(oi.quantity) = ( -- 商品ごとの売上個数合計と比較することで同率を考慮
		SELECT
			MAX(total_quantity_by_product.total_quantity) -- 最も多く売れた商品
		FROM
			(
				SELECT
					SUM(quantity) AS total_quantity -- 商品ごとの売上個数合計
				FROM
					orderitems
				GROUP BY
					product_id
			) total_quantity_by_product
	);
```

### 解説:
ここでのポイントは2つです。
1.  **同率1位への対応:** `MAX` サブクエリまたは `RANK()` を使う。
2.  **キャンセル注文の除外:** データの整合性を保つため、`orders.status != 'Cancelled'` を考慮する。

## 問題 7: 複雑な集計 (相関サブクエリ or JOIN)
- **目的**: 「注文ごとに集計 → 顧客ごとに最大」の二段階集計を、CTE・派生テーブル・相関サブクエリで書き分ける。

### 問題:
各顧客が「最も高額な注文」で支払った金額を取得してください。

### 解答:
CTEで一度「注文ごとの支払総額」を作ってしまうのが、最も可読性が高くミスが少ない方法です。
```sql
-- 案1: CTE（共通テーブル式）を使う ← 推奨
WITH OrderTotals AS (
    -- 1. 注文ごとの支払合計額を算出
    SELECT
        o.customer_id,
        o.order_id,
        SUM(p.amount) AS total_amount
    FROM
        orders o
        INNER JOIN payments p ON o.order_id = p.order_id
    GROUP BY
        o.order_id,
        o.customer_id
)
-- 2. 顧客ごとに最大の注文金額を抽出
SELECT
    c.customer_id,
    c.name,
    MAX(ot.total_amount) AS max_order_total
FROM
    customers c
    INNER JOIN OrderTotals ot ON c.customer_id = ot.customer_id
GROUP BY
    c.customer_id,
    c.name;
```

```sql
-- 案2: FROM句でのサブクエリ（派生テーブル）
SELECT
    c.customer_id,
    c.name,
    MAX(sub_order_totals.total_paid) AS max_order_total
FROM
    customers c
    JOIN (
        -- ここで注文ごとの集計テーブルを一時的に作る
        SELECT
            o.customer_id,
            SUM(p.amount) AS total_paid
        FROM
            orders o
            JOIN payments p ON o.order_id = p.order_id
        GROUP BY
            o.customer_id, -- 結合用にcustomer_idも残す
            o.order_id
    ) AS sub_order_totals 
    ON c.customer_id = sub_order_totals.customer_id
GROUP BY
    c.customer_id,
    c.name;
```

```sql
-- 案3: SELECT句の相関サブクエリ ← 発展
SELECT
    c.customer_id,
    c.name,
    (
        -- その顧客の「注文ごとの合計」の中で最大のものを取り出す
        SELECT
            MAX(per_order.total_paid)
        FROM (
            -- 特定の注文ごとの合計を計算
            SELECT
                SUM(p.amount) AS total_paid
            FROM
                orders o
                JOIN payments p ON o.order_id = p.order_id
            WHERE
                o.customer_id = c.customer_id -- 【相関】外側の顧客IDと紐付け
            GROUP BY
                o.order_id
        ) AS per_order
    ) AS max_payment
FROM
    customers c
-- 支払実績がない顧客を除外したければここで制御、今回は全顧客表示ならLEFT JOIN的な挙動になる
ORDER BY
    c.customer_id;
```

### 解説:
これも「分割払い」を考慮すると、「まず注文ごとに合計」→「その中で顧客ごとの最大」という2段階が必要です。

## 問題 8: 存在否定 (NOT EXISTS)
- **目的**: 「〜だけを買った」を「〜以外を買っていない」と言い換え、`NOT EXISTS` で表現する。

### 問題:
平均より高い価格の商品だけを購入したことがある顧客の名前を取得してください。

### 解答:
最もスマートな解法です。
*   `MIN(price) > Average` なら、一番安い買い物ですら平均超えなので、すべて平均超えです。
*   一度も買っていない人は `MIN` が `NULL` になり、比較条件で落ちる（まぁ、内部結合してるので、購入履歴がない客はhaving動く前に落ちますが、、、）ので「未購入者」も自然に除外できます。

```sql
-- 案1: MIN を使った集計アプローチ
SELECT
    c.customer_id,
    c.name
FROM
    customers c
    INNER JOIN orders o ON c.customer_id = o.customer_id
    INNER JOIN orderitems oi ON o.order_id = oi.order_id
    INNER JOIN products p ON oi.product_id = p.product_id
GROUP BY
    c.customer_id,
    c.name
HAVING
    MIN(p.price) > (
        SELECT
            AVG(price)
        FROM
            products
    );
```

相関サブクエリの練習としてはこちらが正解。「購入履歴がある(EXISTS)」かつ「平均以下の購入がない(NOT EXISTS)」と明示します。

```sql
-- 案2: EXISTS + NOT EXISTS
SELECT
    c.customer_id,
    c.name
FROM
    customers c
WHERE
    -- 1. 少なくとも1回は購入している
    EXISTS (
        SELECT
            1
        FROM
            orders o
        WHERE
            o.customer_id = c.customer_id
    )
    AND
    -- 2. 平均価格以下の商品を買った履歴が存在しない
    NOT EXISTS (
        SELECT
            1
        FROM
            orders o
            INNER JOIN orderitems oi ON o.order_id = oi.order_id
            INNER JOIN products p ON oi.product_id = p.product_id
        WHERE
            o.customer_id = c.customer_id
            AND p.price <= (
                SELECT
                    AVG(price)
                FROM
                    products
            )
    );
```

### 解説:
この問題は論理的思考力が試されます。
「平均より高い商品**だけ**を買った」
＝「平均以下の商品を買ったことが**ない**」かつ「**何かは買ったことがある**（未購入者除外）」
となります。
