#### 【ORDERS】（注文全体：販売管理システムが更新）
1.  **Pending（保留）**: 顧客が「注文ボタン」を押した直後。入金確認待ち。
2.  **Processing（処理中）**: 入金が確認され、倉庫に「出荷指示」が出た状態。
3.  **Shipped（出荷済み）**: 倉庫から全ての荷物が出荷された状態。
4.  **Partially Shipped（一部出荷済み）**: 複数の荷物のうち、一部だけが出荷された状態。
5.  **Completed（完了）**: 全ての荷物が「配達完了」になった状態。
6.  **Cancelled（キャンセル）**: 欠品や顧客都合で取引が終了した状態。

#### 【SHIPMENTS】（配送：倉庫作業員・配送業者が更新）
1.  (レコードなし): 出荷準備前。
2.  **In Transit（輸送中）**: 倉庫からトラックに乗った状態。`shipped_date` が入る。
3.  **Delivered（配達完了）**: 顧客に荷物が届いた状態。`delivery_date` が入る。

## この表の使い方

**テストデータを1行でも変えたら／問題文を直したら、まずこの表を引く。**

| やること | 見る場所 |
| :--- | :--- |
| **データを変える前** | §2「行ごとの依存」で、その行が支えている問を確認する。§1 の採番・件数依存も必ず見る |
| **データを変えた後** | 影響した章の解答を再実行して、期待結果・実測値を差し替える |
| **問題文を直したとき** | §3「章 → 依存テーブル」で、同じテーブルを使う他章に矛盾が出ないか確認する |

**⚠️ この表に載っている行は「たまたま在るデータ」ではなく、問題の狙いを成立させている構造物。** 消す・値を変えると、その問は**エラーにならずに黙って学習効果を失う**（＝誤答でも正解と同じ結果が出るようになる）。

## §4. データを変えるときの手順

1. **§2 で、触る行が支えている問を洗う。** 「⚠️」と太字が付いている行は**変更前に必ず [[_既知の問題不備]] を読む**
2. **§1 の採番・件数依存を確認する。** `orders` / `orderitems` / `reviews` / `shipments` に1行足すと、13章・15章の資料の数値が全部ズレる
3. 影響する章の解答SQLを**実際に流して**期待結果を差し替える。検証は使い捨てDB（`tmp_` 接頭辞）で行い、終わったら `DROP DATABASE`
4. **`02_問題` 側にも数値がハードコードされていないか grep する。**（例: 09章 問6 の問題文に「問題4の結果（3件）」が埋まっている）
5. [[_既知の問題不備]] の該当行の「状態」を更新する
