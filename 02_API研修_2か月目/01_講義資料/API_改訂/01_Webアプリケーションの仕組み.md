## 1. Web は「見せる側」と「用意する側」に分かれている

普段見ているウェブページは、役割の違う 2 つの部分が連携して表示されています。

| | フロントエンド | バックエンド |
| :--- | :--- | :--- |
| 何をするか | ユーザーが見て操作する部分を作る | データの処理や保存をする |
| どこで動くか | **Web ブラウザの中** | **サーバーの中** |
| 目に見えるか | 見える | 見えない |
| 主な技術 | HTML / CSS / JavaScript | Java、PHP、Python、Ruby など |
| 担当者 | フロントエンドエンジニア | バックエンドエンジニア |

## 2. サーバーとクライアント

- **サーバー** … サービスを**提供する**コンピューター
- **クライアント** … サービスを**受ける**コンピューター

Web の世界では、ブラウザがクライアント、ページのデータを持っている側がサーバーです。

> [!hint]- 飲食店に例えると
> フロントエンドは注文を取って料理を運ぶ「ホール係」、バックエンドは料理を作る「厨房」。
> お客さんは厨房の中を見ませんが、頼めば料理が出てきます。

---

## 3. ブラウザが読める 3 つの言語

サーバーがどんな言語で書かれていても、**ブラウザが解釈できるのはこの 3 つだけ**です。

| 言語 | 担当 | 例 |
| :--- | :--- | :--- |
| **HTML** | ページの**骨組み**。何があるか | `<h1>` は見出し、`<p>` は段落、`<img>` は画像 |
| **CSS** | **見た目**。どう見えるか | 文字を青くする、角を丸くする |
| **JavaScript** | **動き**。操作にどう反応するか | ボタンを押すと表示が変わる、入力内容をチェックする |

> [!example]- 講義中にやること
> 開発者ツールを開いて、HTML を書き換えたり CSS を消したりして、
> 表示がどう変わるかをその場で見てみます。

## 4. URL を入れてから表示されるまで

![[Pasted image 20251118180533.png]]

1. **ブラウザがリクエストを送る** — 「このページの HTML・CSS・JavaScript をください」
2. **サーバーが探す** — 要求されたデータを用意する
3. **サーバーがレスポンスを返す** — 見つけたデータを返す
4. **ブラウザが組み立てる** — 受け取った HTML・CSS・JavaScript を解釈して画面に描く

**この「リクエストを送る／レスポンスが返る」のやり取りのルールが HTTP です。**
HTTP の中身は `03_HTTPプロトコル` で詳しく見ます。

## 5. 静的なサイトと動的なサイト

同じように見えるページでも、**中身がいつ作られるか**が違います。

| | 静的なサイト | 動的なサイト |
| :--- | :--- | :--- |
| 中身がいつ作られるか | **あらかじめ作ってある** | **リクエストを受けてから作る** |
| サーバーがすること | 置いてあるファイルをそのまま返す | DB から情報を取り、組み立てて返す |
| 誰が見ても同じか | 同じ | 人や状況によって変わる |
| 向いているもの | 会社概要、イベント告知 | EC サイト、SNS、ニュース |

## 6. 動的なサイトの作り方は 1 つではない

ここが 2 か月目の課題に直結します。動的なサイトには**作り方が 2 通り**あります。

| | サーバーが HTML を組み立てる | ブラウザが HTML を組み立てる |
| :--- | :--- | :--- |
| サーバーが返すもの | **完成した HTML** | **データだけ**（JSON） |
| 誰が画面を組み立てるか | サーバー | ブラウザの JavaScript |
| ページ切り替え | ページ全体を読み込み直す | 必要な部分だけ書き換わる |
| 代表例 | 昔ながらの Web サイト | **SPA**（Google マップ、Gmail、Web版 Slack） |

### SPA（Single Page Application）

![[Pasted image 20251118170246.png|750]]

1. サーバーは最初、**最小限の HTML（骨組み）だけ**を返す
2. ブラウザの JavaScript が、**必要なデータだけ**をサーバーに要求する
3. サーバーは **JSON でデータだけ**を返す
4. JavaScript がそのデータを使って画面を組み立てる

ページを切り替えるたびに全部を読み込み直さないので、動きが速くなります。

> [!important] 2か月目に作るのは、この「データだけを返す側」です
> 画面は作りません。**ブラウザから「このデータをください」と言われて、JSON を返すプログラム**を作ります。
> この「データを返す窓口」のことを **Web API** と呼びます。
>
> 次の章で、その Web API が何なのかを見ていきます。

> [!note]- データだけ返す形にすると、何が嬉しいのか
> 返すのが HTML ではなくデータなので、**受け取る側がブラウザでなくても構いません。**
> 同じ窓口を、スマホアプリからも、別の会社のシステムからも使えます。
> 画面を作り直しても、データを返す側はそのまま使えます。
