DBに`batch`DBを作成してください。

DBを作成したら、クローンしたbatchプロジェクトで、`mvn spring-boot:run`をしてみてください。
もし動けば自動でテーブルが`batch`DB配下に作成されるはずです。

- `T_SCORE` のテストデータ（6,000件）は**初回起動時に1回だけ**作られます。起動した日の前後30日分のプレイ履歴です。2回目以降の起動ではデータは変わりません
- 作成から1か月ほど経つと「前日」のデータが無くなります。そのときや、データを作り直したいときは、`batch` DBを削除して作り直してください
- `T_GAME_HISTORY` の処理日が本日の行は、起動のたびに消えます。同じ日に何度流しても、前回の結果に足し込まれることはありません
その中でも下記テーブルのデータ構造を確認しておいてください。
- T_SCOREテーブル：今までのゲームのプレイ履歴
- T_GAME_HISTORYテーブル：プレイ履歴のサマリー（日ごとに更新）

### 課題で作成するプログラムの内容
下記のプログラムが上記テーブルをどのように操作すれば作れそうか考えてみてください。

前日のゲームのプレイ数と、前日までの累計のプレイ数を記録するjobの作成

- **プレイ数**は `T_SCORE` の件数（1回遊ぶと1件）です。同じユーザーが2回遊べば2と数えます（ユーザーの重複は除きません）。
- 集計の対象は**バッチを起動した日の前日**です。0時を過ぎてから起動し、前日分を集計する想定です（講義資料 2-6 落とし穴1）。
- 結果は `T_GAME_HISTORY` の、`PROCESSED_DAY`（処理日）が**起動した日**の行に書きます。

- step1（chunk）
	- **Reader**で、`T_SCOREテーブル`（ゲームのプレイ履歴）を読み込む。←作成済み
	- **Processor**で、論理削除されておらず、かつ前日にプレイされた履歴だけに絞り込む。←**要編集**
		- 絞り込みの条件は Reader のSQLに書くほうが効率的ですが、この課題では Processor の練習のため、全件を読んで Processor で絞ります（対象外の件は `null` を返すと捨てられます）。
	- **Writer**で、`T_GAME_HISTORYテーブル`（日ごとの集計）に、前日のプレイ数を `TODAY_PLAY_NUMBERS` として書き込む。←**要編集**
		- Writer はチャンク（100件）ごとに呼ばれます。1回の呼び出しで全件が来るわけではありません（講義資料 4章）。
		- SQLを呼ぶ必要があるので、`mapperインタフェース`と`mapper.xml`の記述が必要。←**要編集**
- step2（tasklet）←作成済み
	- 前日までの累計のプレイ数を `TOTAL_PLAY_NUMBERS` として `T_GAME_HISTORYテーブル`に書き込む。

動かしたら、`BATCH_STEP_EXECUTION` テーブルで読んだ件数・捨てた件数・書いた件数を確認してください（講義資料 4章）。
